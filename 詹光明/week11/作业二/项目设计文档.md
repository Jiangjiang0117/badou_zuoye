*面向企业内部经营分析的自然语言数据分析系统*

版本：0.1（设计基线草案） \| 状态：待业务试点与技术验证后基线化

# 1. 文档目的与状态

本文定义项目目标、用户、产品定位、范围、阶段规划、风险与验收原则，为功能设计和技术设计提供共同基线。当前业务域、指标口径和最终技术栈尚未确定，因此本文区分已确认需求与暂定设计假设。

# 2. 项目背景与问题

-   业务人员依赖数据分析师或 BI
    工程师完成查询，简单问题响应慢，复杂问题需要多轮沟通。

-   传统 BI
    通常要求用户预先理解指标、维度和报表结构，不利于临时探索式分析。

-   单纯的自然语言转 SQL
    容易受表结构、指标口径、关联关系和权限约束影响，生成结果未必可信。

-   经营异常分析往往需要多轮查询、维度拆解、贡献度计算与证据汇总，单轮
    SQL 不足以完成任务。

# 3. 产品定位与目标

产品定位：面向企业内部员工、业务人员和管理层的 ChatBI + Data
Agent。用户以自然语言提出数据问题，系统在授权范围内执行只读查询；简单问题通过确定性流程完成，复杂问题由
Agent 规划多步骤分析，最终输出表格、图表和可追溯结论。

## 3.1 目标

-   降低业务人员获取数据和进行初步分析的门槛。

-   支持同比/环比、多维度下钻、贡献度分析等常见经营分析任务。

-   让关键结论能够追溯到指标定义、筛选条件、SQL、查询结果和分析步骤。

-   通过轻量语义层逐步沉淀企业指标口径与业务知识。

-   在私有化环境下兼顾模型效果、推理成本与数据安全。

## 3.2 非目标（MVP 阶段）

-   不执行 INSERT、UPDATE、DELETE、DDL 或其他写操作。

-   不承诺自动证明业务因果关系；贡献度和维度拆解属于统计归因，结论需谨慎表述。

-   不在第一版建设完整企业数据治理平台、统一指标中台或多数据源联邦查询。

-   不默认支持自动修改业务系统、发送通知或触发外部业务动作。

-   不将模型内部隐式推理过程作为审计内容；只记录可解释的计划、工具调用和执行证据。

# 4. 目标用户与核心场景

  ---------------------------------------------------------------------------------------------------------------
  用户角色                主要目标                               典型操作
  ----------------------- -------------------------------------- ------------------------------------------------
  业务人员                快速获取经营数据并探索原因             自然语言提问、筛选时间范围、继续追问、查看图表

  管理层                  理解经营表现和异常影响                 查看摘要、同比环比、主要贡献维度和结论依据

  数据分析师 / BI 工程师  验证结果、维护语义配置、排查查询问题   检查 SQL、指标口径、元数据和审计记录

  系统管理员              维护数据源、用户授权和系统运行         配置 MySQL、授权表、管理用户与查看运行状态
  ---------------------------------------------------------------------------------------------------------------

# 5. 产品范围

## 5.1 MVP 范围

-   管理员配置一个或多个 MySQL 数据源连接，并测试连通性。

-   同步或读取数据库元数据，管理员选择可供分析的库、表和字段。

-   配置轻量语义层：指标、维度、字段描述、同义词、表关联、默认时间字段与口径说明。

-   支持会话式自然语言问数、同比/环比、多维度下钻和贡献度分析。

-   简单任务走确定性流程，复杂任务通过受控 Agent 规划和执行多步分析。

-   后端强制执行用户身份、表/字段授权与行级数据过滤。

-   提供表格、基础图表、分析摘要、分析步骤及可展开的 SQL 和查询结果。

-   对业务歧义、权限拒绝、SQL 错误、空结果和证据不足给出明确反馈。

-   记录任务状态、执行步骤、查询参数、耗时、模型调用元信息与审计事件。

## 5.2 暂不纳入 MVP

-   多种异构数据库的统一查询；优先保证 MySQL 端到端闭环。

-   预测模型、因果推断、自动机器学习等高级分析。

-   复杂报表设计器、定时推送、协作批注和自动生成演示文稿。

-   完整多租户 SaaS 计费、跨企业隔离和复杂组织治理。

-   自动执行任何会改变数据或业务状态的操作。

# 6. 产品原则

1.  安全优先：权限和 SQL
    安全由后端执行链路强制保证，不把安全责任交给提示词。

2.  证据优先：结论必须与可复现的数据结果关联；证据不足时明确说明。

3.  渐进式透明：默认展示业务可读结果，按需展开分析步骤、SQL、参数和指标口径。

4.  有限自主：Agent
    可以规划分析，但只能调用白名单工具并受预算、轮数、超时和结果量约束。

5.  语义先行：优先使用已审核的指标、维度和关系，不允许模型随意猜测业务口径。

6.  可替换：模型供应商、模型路由和部分分析策略通过接口隔离，避免绑定单一厂商。

# 7. 成功指标与验收方向

  ----------------------------------------------------------------------------------------------
  指标类别                            建议验收方式（阈值待试点校准）
  ----------------------------------- ----------------------------------------------------------
  任务完成率                          建立代表性问题集，统计可正确返回结果的问题比例

  结果正确性                          与人工 SQL 或已审核基准结果对比，覆盖指标口径、筛选和聚合

  权限安全                            越权查询测试全部阻断；不得仅靠提示词或前端过滤

  可追溯性                            成功任务均可关联到语义定义、SQL/参数、结果摘要与步骤记录

  响应性能                            区分简单问数和多步骤分析，测量 P50/P95
                                      延迟并在试点后设定目标

  成本                                记录每任务模型调用量、Token、数据库耗时与重试次数

  可用性                              SQL 错误、超时、空结果和歧义均有可理解的反馈与恢复建议
  ----------------------------------------------------------------------------------------------

# 8. 阶段规划

7.  阶段 0：试点准备。选定首个业务域、样例问题、指标口径和基准
    SQL；确认内网部署和模型数据边界。

8.  阶段 1：数据与语义底座。实现 MySQL
    配置、元数据读取、语义层管理、身份和行级权限。

9.  阶段 2：ChatBI 闭环。实现问题解析、语义检索、SQL
    生成与校验、查询执行、表格/图表和会话追问。

10. 阶段 3：Data
    Agent。实现任务计划、受控工具调用、多步分析、同比环比、维度下钻和贡献度分析。

11. 阶段
    4：可试点加固。补齐审计、监控、错误恢复、性能测试、安全测试、安装部署与运维文档。

# 9. 风险与待确认事项

  ---------------------------------------------------------------------------------------------------------------
  事项                    当前处理方式                                           后续动作
  ----------------------- ------------------------------------------------------ --------------------------------
  首个业务域未知          使用可替换的示例业务模型，不固化行业规则               试点前选定真实业务域和核心指标

  指标定义不完整          语义层对未审核指标标记状态，不默认作为权威口径         由业务负责人/数据分析师审核

  外部模型数据边界        默认不发送原始明细和敏感字段；模型路由前做数据最小化   根据模型服务协议和内网政策确认

  行级权限实现            后端可信策略注入，数据库只读账号与查询校验双重控制     安全评审并执行越权测试

  复杂分析耗时和成本      限制 Agent 轮数、SQL 次数、超时、结果行数与 Token 预算 以代表性任务进行压测和成本评估

  技术栈尚未最终确认      暂定 React/TypeScript + Python/FastAPI                 在团队能力、部署约束和 PoC
                                                                                 后冻结
  ---------------------------------------------------------------------------------------------------------------

# 10. 需求基线变更规则

首个业务域、权限规则、模型数据出境边界和核心分析口径属于高影响决策；变更时需同步更新项目、功能和技术设计文档。具体模型名称、图表样式和非核心
UI 细节可在实现阶段通过配置或迭代调整。
