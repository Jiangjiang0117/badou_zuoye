*私有化部署、受控 Agent、语义层与安全 SQL 执行*

版本：0.1（设计基线草案） \| 状态：待业务试点与技术验证后基线化

# 1. 技术设计目标

-   构建可试点、可观测、可扩展的部门级服务，优先保证数据正确性和权限安全。

-   将 LLM
    从数据库执行权限中隔离：模型提出候选计划/SQL，可信后端校验并执行。

-   以语义层约束 Text-to-SQL，并将分析计算尽量放在确定性代码中完成。

-   通过统一模型网关实现本地模型与外部模型 API 的可替换路由。

-   所有分析步骤具有任务 ID、步骤 ID、语义版本、查询记录和审计关联。

# 3. 总体架构

逻辑链路：Web UI → API/Auth → Conversation & Task Service → Intent
Router → (Deterministic Query Flow 或 Agent Planner) → Semantic Service
→ SQL Generator → SQL Policy & Permission Enforcement → Read-only Query
Executor → Result Analyzer → Chart/Answer Composer → Audit & Trace
Store。

模型网关只提供文本/结构化输出能力，不直接持有数据库凭据。数据库执行器不接受未经校验的自由文本
SQL；只接受通过策略校验的查询对象。

# 4. 核心服务边界

  -----------------------------------------------------------------------------------------------------------------
  服务                    职责                                             关键约束
  ----------------------- ------------------------------------------------ ----------------------------------------
  API/Auth                身份验证、角色检查、会话和任务 API               每个请求绑定可信 user_id 与权限上下文

  Data Source Service     连接配置、连通性测试、元数据刷新                 凭据加密存储；连接信息不暴露给模型

  Semantic Service        检索指标、维度、同义词、表关系和口径             优先使用已发布定义；记录语义版本

  Intent Router           区分简单问数与复杂分析                           路由结果可解释、可测试，失败时安全降级

  Planner/Agent           创建分析计划、选择受控工具、读取步骤结果并调整   限制工具集合、循环次数、时间和查询预算

  SQL Generator           基于语义上下文生成候选 SQL                       输出 SQL 与结构化参数；不能自行执行

  Policy & Permission     验证表/字段、操作类型、行级策略和成本限制        服务端强制执行；校验失败即拒绝

  Query Executor          通过只读连接执行 SQL                             超时、行数、并发、扫描量和结果大小限制

  Analysis Engine         计算同比/环比、下钻、贡献度和一致性校验          尽可能用确定性代码完成计算

  Answer Composer         将结果转成业务可读结论和图表规格                 结论引用具体步骤和结果，不编造数字

  Audit/Trace             保存任务步骤、执行元信息、权限事件和错误         敏感字段脱敏，访问审计日志本身也需授权
  -----------------------------------------------------------------------------------------------------------------

# 5. 关键执行流程

## 5.1 简单问数

1.  API 接收问题并建立 task_id，附带已认证用户身份。

2.  Intent Router 判定为简单查询；抽取指标、维度、时间和过滤条件。

3.  Semantic Service 返回可用指标定义、关联路径、字段和语义版本。

4.  缺少必要条件或指标存在歧义时，返回
    clarification_required，不执行查询。

5.  SQL Generator 生成候选 SQL 和参数化绑定值。

6.  SQL AST
    校验器限制为单条只读查询，检查表/列白名单、危险语法、关联与查询预算。

7.  权限服务从可信身份上下文计算行级策略；由服务端生成或约束查询条件，不能接受模型自行决定授权范围。

8.  Query Executor
    在事务只读模式（若驱动/数据库支持）下执行，实施超时和结果上限。

9.  结果校验器检查列类型、空值、分母和聚合一致性；生成表格/图表规格。

10. 持久化任务步骤与审计信息，返回答案和详情入口。

## 5.2 复杂 Agent 分析

11. Planner
    将目标转换为结构化计划：目标、步骤、输入依赖、工具、预期输出和停止条件。

12. Plan Validator
    校验每一步是否属于允许的分析操作，并检查步骤数量、查询预算与数据范围。

13. Agent Runtime 通过工具契约调用
    semantic_lookup、query_readonly、compare_periods、drill_down、calculate_contribution、validate_result
    等工具。

14. 每个查询工具均独立执行身份/权限校验，不信任上游 Agent 已经做过检查。

15. 中间结果以结构化摘要返回；默认不把超大明细结果直接塞入模型上下文。

16. 若出现歧义、无效口径或权限错误，按对应异常策略停止或向用户澄清。

17. 若结果可支持分析，Analysis Engine
    计算差异和贡献度，验证各分项与总量关系。

18. Answer Composer
    生成结论、图表和证据引用；将步骤链与语义版本一并保存。

SQL。

# 7. 行级权限与 SQL 安全

## 7.1 权限模型

-   功能权限（RBAC）：控制用户能否管理数据源、维护语义、查看 SQL
    或查看审计。

-   资源权限：限制用户可访问的数据源、表、字段和指标。

-   行级权限：由可信用户身份映射到部门、区域、租户或业务实体，并由服务端强制过滤。

-   每个工具调用和每条查询都重新执行权限检查；会话记忆、模型输出和前端状态不能充当授权依据。

-   对敏感字段实施列级屏蔽或聚合限制；对导出、明细查看和 SQL
    详情采用独立权限。

## 7.2 SQL 安全防线

19. 数据库层：专用只读账号，仅授予必要 schema/table 的 SELECT
    权限；限制网络访问。

20. 解析层：使用 MySQL 方言 AST
    解析，拒绝多语句、写操作、DDL、存储过程调用和不允许的系统表访问。

21. 白名单层：只允许语义层授权的表、列、关联路径与函数集合。

22. 权限层：将行级策略应用于可信查询计划，检查子查询、CTE、JOIN、别名等场景是否可能绕过策略。

23. 资源层：设置 statement
    timeout、最大返回行数、并发上限、查询成本或扫描规模限制（数据库支持时）。

24. 执行层：参数化绑定值；不将用户输入直接拼接到 SQL；记录 SQL
    hash、参数类型与脱敏后的参数。

25. 验证层：测试
    UNION、嵌套查询、别名、注释、CTE、JOIN、函数、无权限字段和提示注入等攻击场景。

关键设计要求：仅通过正则表达式删除危险关键词不足以形成可靠安全边界。行级过滤应由后端可信策略生成，并在数据库权限或受控查询执行层形成纵深防御。

# 8. 模型路由与数据安全

-   定义统一 Model Provider
    接口：模型选择、结构化输出、超时、重试、Token 统计和错误归一化。

-   本地模型优先处理含敏感业务上下文的任务；外部模型调用前进行数据最小化和脱敏。

-   默认不向模型发送数据库凭据、原始敏感字段、整表数据或不必要的个人信息。

-   模型只生成计划、候选 SQL、解释和图表规格；所有 SQL
    由后端校验并执行。

-   设置每任务模型调用预算、最大上下文长度和降级策略；模型不可用时简单查询可返回明确错误或走受控降级路径。

-   保存供应商、模型版本、请求耗时、Token
    和策略版本等元信息；避免在日志中保存完整敏感提示词。

# 11. 部署与运行

-   组件建议：Web 前端、API/Agent 服务、应用元数据库、业务
    MySQL、模型网关/本地推理服务、日志与指标采集。

-   所有服务部署于企业内网；外部模型连接由网络策略显式控制，不允许数据库服务直接暴露公网。

-   密钥通过环境注入或密钥管理系统提供，不写入代码仓库、镜像或普通日志。

-   配置数据库连接池、请求超时、Agent 任务并发限制、任务超时和优雅取消。

-   定义应用库和语义配置的备份恢复流程；审计数据保留期由企业合规要求决定。

-   若使用 Kubernetes，需配置 NetworkPolicy、Secret 管理、资源
    requests/limits、健康检查与滚动升级；否则先以 Docker Compose 验证
    MVP。

# 13. 关键风险与技术验证

26. 先用真实代表性数据验证 Text-to-SQL 准确率，不应仅依赖公开数据集或
    Demo。

27. 对行级权限实现做独立安全评审，重点测试
    JOIN、子查询、CTE、聚合与维度下钻。

28. 比较本地模型与外部 API 在 SQL
    正确率、中文业务理解、延迟、成本和隐私边界上的表现。

29. 对 SQL AST 校验器进行 MySQL 方言兼容性验证，明确不支持的语法和函数。

30. 验证贡献度算法在负值、零值、缺失维度和总体变化接近零时的定义。

31. 明确业务数据、模型请求、会话和审计记录的保留、脱敏与删除策略。
