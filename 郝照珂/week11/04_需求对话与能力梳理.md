# 需求对话与能力梳理

日期：2026-10-24。来源：本次用户与 Codex AI 助手的真实交流及助手据此进行的需求分析。本记录不是与 DeepSeek、Qwen、豆包分别对话的截图或日志，也不宣称已经调用这些服务。

## 1. 实际交流

用户要求：参考 sql-agent.ipynb 和 chinook.db 实现完整 SQL Agent workflow，并通过与 AI 交流梳理 ChatBI / Data Agent 能力，产出项目、功能、技术设计文档。

助手提问：“ChatBI 项目先按 Chinook 音乐商店的销售分析场景设计，你更希望面向哪类用户？”

用户回答：“数据分析师：SQL 审核、复杂分析、结果导出”。

助手回应：按数据分析师定位调整设计，重点放在 SQL 可审查、多表分析、指标口径和结果导出，并记录每个阶段的输入输出。

## 2. 基于回答的能力分析

分析师需要的不只是自然语言问答入口。首先需要理解数据资产，包括字段、主外键、数据粒度和指标口径。其次需要让生成 SQL 可被检查和修改，并在修改后重新校验，避免旧审核对应新 SQL。再次，多表和时间分析必须有基准答案验证，尤其是 JOIN 后重复累加发票金额的问题。最后，导出应保留 SQL、筛选条件、结果截断状态及执行来源，让其他人能够复核。

七阶段工作流是底座。面向分析师的完整产品还需要：歧义澄清、多轮筛选继承、SQL 版本管理、人工审核、指标字典、权限隔离、审计、可视化、导出与评测。项目设计文档将这些能力分为已实现原型、MVP 和后续扩展，避免将规划误报为完成。
