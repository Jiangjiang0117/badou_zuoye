# ChatBI / Data Agent 项目设计文档

版本：1.0｜日期：2026-10-24｜场景：Chinook 音乐商店｜主要用户：数据分析师

## 1. 项目背景与目标

数据分析师需要反复查找表结构、确认关联关系、编写 SQL 并向业务人员解释结果。自然语言直接生成 SQL 能节约输入时间，但错误字段、错误连接和指标口径不一致会让“可执行的查询”产生错误结论。本项目将问数拆成可观察的工作流，让分析师检查 SQL、结果和修复过程。

目标是交付一个辅助分析工具：分析师以自然语言表达问题，系统选择表、生成并校验 SQL、有限修复错误、执行只读查询、汇总证据并导出结果。分析师保留最终业务判断权。

## 2. 用户及典型任务

|角色|核心任务|交付价值|
|---|---|---|
|数据分析师（主用户）|多表销售分析、SQL 审核、修订与导出|减少重复查询准备工作，保留可复核依据|
|业务负责人|确认销售额、时间范围和排名口径|避免同名指标不同解释|
|数据管理员|维护表关系、可访问字段和指标字典|控制数据访问范围|

核心故事：分析师询问“销售额最高的五种音乐曲风是什么”，系统选中 invoice_items、tracks、genres，展示连接路径及销售额计算方式，给出 SQL 和结果。分析师能够确认没有将发票总额在明细连接后重复求和。

## 3. 范围与阶段

课程原型已实现：SQLite 元数据解析、固定案例离线工作流、可配置模型接口的选表/生成/改写、数据库编译校验、只读执行、确定性结果汇总、JSON 轨迹及 CSV 导出。

产品 MVP 规划：增加 SQL 编辑审核界面、指标字典、会话追问、图表、登录及服务端数据权限。自然语言存在歧义时先澄清，再执行；课程 CLI 尚不实现这套交互。

后续扩展：多数据库连接、查询任务队列、可复用分析报告、数据质量检查、团队共享与定时分析。数据库写入、自动更改业务数据、无人审核的经营决策不在本期范围。

## 4. 成功指标与验收

以下是产品目标，并非已测量成绩：

|维度|MVP 验收方法与目标|
|---|---|
|结果正确性|人工确认的 30 道查询集，结果等价率至少 90%；排序和金额精度按案例定义比较|
|修复能力|10 道可修复 SQL 错误，最多两轮内修复至少 8 道；不得改变问题语义|
|安全性|写入、越权字段、多语句及附件数据库测试全部阻断|
|可解释性|每次成功任务能回溯问题、选表、SQL、校验、执行和汇总|
|体验|Chinook 小数据集本地查询通常应在 3 秒预算内终止；模型端耗时独立统计|
|导出|导出行与展示行一致，明确截断状态，文本公式风险处理通过测试|

当前验证范围：五个固定离线问题和自动化边界测试，不能据此推断真实模型的泛化正确率。

## 5. 里程碑与交付物

1. 第一阶段：完成七阶段工作流、错误修复演示和 notebook（本次交付）。
2. 第二阶段：使用用户配置的模型运行 30 道基准题，整理失效类别和调用成本。
3. 第三阶段：实现 SQL 审核页面、指标管理、导出权限及多轮上下文。
4. 第四阶段：测试权限隔离、负载和异常恢复，开展分析师试用。

交付物包括源代码、可执行 notebook、复现说明、运行轨迹、测试记录，以及项目、功能、技术三份文档。阶段二至四是计划，不表述为已实现。

## 6. 风险与取舍

SQL 编译成功不代表业务含义正确，因此产品需要指标字典和人工审核。客户地址、邮箱等字段不必作为模型样本发送；当前解析仅返回结构和行数。现有原型仅有表级白名单，并无生产级列权限。离线样例降低复现门槛，但自由问答必须配置真实模型。真实接口尚未调用，不给出准确率和费用结论。

## 7. 设计依据

本地课程 `../Week11/04_SQL-Code-Agent-Demo/sql-agent.ipynb` 提供数据库解析、选表思路及尚待补充的生成、汇总阶段；`../Week11/note.txt` 涉及分步工作流、输出格式兼容性和工具失败后重试。本项目按这些思路完成独立实现，并使用同目录课程 chinook.db 验证。用户在本次对话中明确选择“数据分析师：SQL 审核、复杂分析、结果导出”。
