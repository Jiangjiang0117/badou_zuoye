# ChatBI / Data Agent 功能设计文档

版本：1.0｜主要用户：数据分析师

## 1. 分析师工作流程

输入问题 → 确认指标和时间范围 → 查看选表和连接路径 → 生成 SQL → 自动校验 → 分析师审查或修改 → 执行 → 查看数据与结论 → 导出。

课程版本自动执行校验通过的只读 SQL；人工审核节点和图形界面属于产品 MVP 计划。错误修复只修改 SQL，不应擅自放宽过滤条件以获得结果。

## 3. 指标和口径

|指标|定义|注意事项|
|---|---|---|
|营业额|SUM(invoices.Total)|国家维度使用 BillingCountry；不连接明细后直接累加 Total|
|曲风销售额|SUM(invoice_items.UnitPrice * Quantity)|按 TrackId 连接 tracks，再按 GenreId 连接 genres|
|销量|SUM(invoice_items.Quantity)|不是 COUNT(invoice_items.*)|
|客户数|COUNT(*) FROM customers|注册客户数与有购买记录客户数不同|
|客单价|SUM(Total) / COUNT(DISTINCT InvoiceId)|不是人均消费额；无订单时不除以零|
|月度销售额|按 InvoiceDate 的年月汇总|当前示例只返回有记录的月份；补零需要日期维表或明确的日历逻辑|

数据库未在本作业中验证货币元数据，界面应标为“数据库金额单位”，不自行声称人民币或美元。发票总额示例不包含退款建模。日期边界统一采用 `[起始日, 下一周期起始日)`。

## 4. 交互设计（规划）

分析工作台分为问题区、SQL 区、结果区。问题区显示数据源、当前筛选和口径；SQL 区展示选表理由、查询计划、修复前后 SQL，并提供“保存修改并校验”和“执行已审核版本”；结果区同时呈现数据表、汇总、行数、截断提示和导出入口。修复失败显示具体错误，不将失败包装成业务答案。

问题“销售怎么样”缺少时间、指标和比较基准，应追问；“2013 年每月营业额”口径明确，可直接规划。“再按国家分组”需保留 2013 年的过滤范围，并在执行前显示。

## 5. 异常场景

|场景|处理|
|---|---|
|数据库不存在|初始化失败；不能创建空数据库冒充数据源|
|模型返回非 JSON 或未知表|任务失败并记录原因，不回退为虚构结果|
|错误字段|进入修复，超过上限返回失败|
|空结果|正常成功，说明条件下没有记录|
|超时|中断查询，有限修复后仍失败则终止|
|超过返回上限|仅返回前 200 行并标记截断；导出同样是这批行|
|外部 API 失败|记录失败；当前版本不自动重试网络调用|
|恶意指令要求写库|查询执行器阻断；模型不能决定数据库权限|

## 6. 验收用例

国家销售额 Top5 应以 USA、523.06 开始；曲风销售额 Top5 应以 Rock、826.65 开始；2013 年月度汇总返回 12 行；客户总数为 59；2099 年发票查询为空。错误字段 TotalAmount 应被识别并改写为 Total。删除表、越权查 employees、加载扩展、多语句请求均应阻断。

这些结果来自实际本地执行的固定案例。上线前还需增加至少 30 道人工审核的自然语言题，包括歧义、复杂 JOIN、时间对比及重复计数陷阱。
