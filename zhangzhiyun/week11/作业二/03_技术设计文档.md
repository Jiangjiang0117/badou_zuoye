## 1. 总体架构

```
┌─────────────────────────────────────────────────────────────┐
│ 接入层        Web / IM(飞书·钉钉·企业微信) / OpenAPI / SDK     │
├─────────────────────────────────────────────────────────────┤
│ 对话编排层    会话状态 · 意图路由 · 任务规划 · 澄清 · 工具调用   │
├─────────────────────────────────────────────────────────────┤
│ 理解与检索层  意图分类 · 业务域路由 · Schema召回 · Linking     │
│              Few-shot RAG · 值识别                            │
├─────────────────────────────────────────────────────────────┤
│ 语义层        指标/维度/实体/同义词 · 语义查询DSL · 权限绑定    │
├─────────────────────────────────────────────────────────────┤
│ 生成层        LLM(结构化输出) · 模型路由 · 自修复 · 多候选      │
├─────────────────────────────────────────────────────────────┤
│ 校验执行层    安全校验 · AST校验 · DryRun · 查询网关 · 连接器   │
├─────────────────────────────────────────────────────────────┤
│ 可视化解释层  图表推荐 · 编码映射 · 洞察摘要 · 引用溯源         │
├─────────────────────────────────────────────────────────────┤
│ 数据层        元数据 · 知识库 · 向量库 · 轨迹日志 · 评测集 · 缓存│
└─────────────────────────────────────────────────────────────┘
横切：安全权限 · 可观测与评测 · 成本配额 · 配置与知识运营
```

**架构核心原则**：
1. 生产主链路 `NL → 语义查询 → SQL 编译`，LLM 不做全库自由写 SQL 的默认路径；自由 SQL 仅对分析师开放且置于只读沙箱；
2. 权限与口径在**语义层、执行层双重校验**（Prompt 不是权限边界）；
3. 契约先行：先定语义查询 DSL、工具接口、结构化输出 Schema，再选框架。

## 2. 核心请求链路（与作业一 workflow 的对应关系）

```
用户问题
  → [检索层] 业务域路由 + 表召回（对应作业一 Table 选择）
  → [语义层] 指标/维度/时间/过滤解析，生成语义查询
  → [生成层] LLM 生成 SQL（对应 SQL 生成）
  → [校验层] 安全校验(仅SELECT) + sqlglot AST + EXPLAIN Dry Run（对应 SQL 校验）
       └ 失败 → [生成层] 携带报错自修复 ≤3 轮（对应 SQL 改写，保留 diff）
  → [执行层] 权限注入 → 只读连接执行 + 行数上限（对应 SQL 执行）
  → [解释层] 结果 Sanity Check + LLM 摘要 + 图表推荐（对应 结果汇总）
```

作业一实现的"校验→改写"自修复循环即该链路的 MVP 形态：正则安全校验 + SQLite EXPLAIN + 报错回喂，实测 3 个测试问题一次通过（改写环节作为兜底未触发）。

## 3. 分层技术选型

| 层 | MVP（0–3 月，模块化单体） | 成熟（12 月+，K8s 微服务） |
|---|---|---|
| 接入 | React + AntD + ECharts，单 Web + 企业 SSO | 多端 + IM 消息卡片 + 门户/BI 嵌入 |
| 编排 | FastAPI + 确定性流水线（意图→召回→生成→校验→输出）+ Redis 会话 | 自研图编排（LangGraph 思路自研状态机）+ Temporal 异步长任务 |
| 检索 | pgvector + 关键词 + 业务标签规则；同义词配置表 | Milvus/Qdrant + ES 混合检索 + bge-reranker 精排 |
| 语义 | YAML/DB 配置指标 + 模板编译 SQL；Join 路径配置化 | 独立语义服务：自研 DSL + AST + 版本血缘；或 Cube.js / dbt MetricFlow 改造 |
| 生成 | 单模型（DeepSeek/Qwen-Max/GPT 系）+ JSON Schema 结构化输出 + LiteLLM 网关 | 模型路由（简单问题小模型）+ 多候选执行一致性投票 + 私有化 vLLM 部署 |
| 校验执行 | sqlglot AST 校验 + 直连只读从库 + 语句超时 + 行数上限 | 统一查询网关（成本预估/资源组/队列/缓存/熔断）+ Trino 联邦多源 |
| 可视化 | 规则驱动图表推荐 + LLM 引用式摘要 | 意图驱动推荐 + 归因算法库 + 交互下钻 |
| 数据 | PG + pgvector + MinIO + 日志简表；评测集 CSV + pytest | DataHub 元数据平台 + OpenLineage 血缘 + Langfuse 轨迹 + 评测平台 |
| 横切 | SSO + 行级过滤 + 只读账号 | OPA/Casbin 策略中心 + 字段脱敏 + 导出管控 + 全链路审计 + Prompt 注入防护 |

关键组件说明：
- **SQL 校验**：sqlglot（解析/方言转换/AST 检查），不自研 Parser；
- **结构化输出**：Instructor / Outlines / JSON Schema 强约束，保证输出可解析；
- **模型**：商用 DeepSeek-V3/R1、Qwen-Max、GPT/Claude/GLM 按需路由；开源兜底 Qwen2.5-Coder / SQLCoder；
- **嵌入/重排**：bge-m3 / Qwen-Embedding + bge-reranker。

## 4. 关键设计点

### 4.1 自修复（Self-correction）机制
- 触发：校验失败 / 执行报错 / 结果 Sanity Check 异常（空结果、量级异常、重复计数）；
- 约束：**限 1–3 次**、报错信息原文回喂、每轮保留 SQL diff 供审计与评测；
- 风险控制：可能"把对的改错"，重试前先判定失败类型，语法类才自动重试，口径类走澄清。

### 4.2 权限注入
- 行级权限编译为 WHERE 谓词、列级权限在 Schema 暴露阶段即屏蔽（无权限字段不进 Prompt）；
- 执行层二次校验：SQL 中的表/列必须与该用户语义层白名单一致，否则拒绝。

### 4.3 数据安全
- 连接全部只读账号；外部模型调用前 Schema 与数据脱敏（`138****0000` 式）；
- 提示词注入防护：用户输入与 Schema/知识上下文分段隔离，工具调用白名单。

### 4.4 可观测与评测
- 全链路记录：问题、召回结果、Prompt、语义查询、SQL、执行结果、耗时、权限决策、用户反馈；
- 离线回归门禁：黄金评测集（300–1000 条，分域分难度，带期望结果）作为 CI 门槛；
- 在线：Recall@K、SQL 可执行率、结果准确率、澄清率、P95 时延、LLM 成本。

## 5. MVP 与成熟阶段的演进取舍

| 维度 | MVP 取舍 | 演进触发条件 |
|---|---|---|
| 部署 | 模块化单体（FastAPI + PG + Redis + pgvector） | 团队 > 10 人或单服务发布阻塞 → 微服务 |
| 语义层 | 配置驱动 + 模板，覆盖核心 3–5 域 | 指标数 > 200 或接入第二个产品 → 独立语义服务 |
| 查询执行 | 直连只读库 + 连接池 | 数据源 > 3 个或出现拖库事故 → 查询网关 + Trino |
| 检索 | 单向量库，召回率优先 | Recall@5 < 85% → 混合检索 + 精排 |
| 模型 | 单模型 + 重试 1 次 | 月度 LLM 成本超阈值 → 路由 + 缓存 |
| 元数据 | 脚本定时采集 | 表数 > 500 或口径频繁变更 → DataHub 平台化 |

**三条硬原则**：
1. 契约先行，避免被 LangChain/Dify 等框架版本绑架（框架仅用于原型验证）；
2. 先护栏后智能：AST 校验、权限注入、Dry Run、结果上限必须在扩场景之前上线；
3. 模块化单体优先，出现真实的独立扩缩容需求再拆微服务。

**四个反模式**（讨论中明确的避坑清单）：
- 让 LLM 对全库自由写 SQL 作为默认路径；
- 核心链路深度绑定某一编排框架；
- 没有评测集和轨迹日志就扩业务域；
- 过早引入 Trino、DataHub、微服务。
