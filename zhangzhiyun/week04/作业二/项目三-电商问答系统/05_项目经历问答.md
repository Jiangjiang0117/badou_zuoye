# 项目经历问答 —— 电商智能问答系统

> 本文件把项目1思维导图(`项目1-大模型意图识别图片内容.md`)中针对**电商智能问答系统案例**提出的问题,
> 结合本项目3的实际实现**逐条作答**,可直接作为面试/简历的"项目经历"素材。
> 实现细节见 `01~04` 文档与 README。

---

## 1. 项目背景是什么?

电商平台每天面临海量用户咨询(商品参数、订单状态、退换货政策等),传统人工客服响应慢、成本高;
通用问答大模型因缺乏领域知识容易产生"幻觉"——编造不存在的政策或物流信息。

**解决思路**:基于**检索增强生成(RAG)**,先从一个可信的电商知识库检索到相关证据,
再让大模型"照证据回答"。证据兜底,幻觉可控,答案可追溯。

## 2. 项目内容 / 具体要做什么?

做一个电商智能问答系统:**输入一句买家咨询 → 从知识库检索最相关问答证据 → 大模型结合证据生成客服语气回答**。

落地形态(本目录交付):

| 能力 | 说明 |
|---|---|
| 知识库构建 | 16,205 条公开客服问答对 → 清洗 → 8,000 条知识条目 |
| 语义检索 | BM25 + jieba 中文分词,召回 Top-K 证据(带分数) |
| 大模型生成 | Deepseek(云端)+ 本地 Qwen(Ollama)双模型,自动降级 |
| 交互 | 命令行 / HTTP API / **Flask 浏览器聊天页** |
| 评测 | 链路自检 + 换说法召回,可复现 |

## 3. 技术路线(方法 1/2/3/4)与适用场景?

三套方案,差异度明显:

| 方法 | 一句话 | 适用场景 |
|---|---|---|
| **方案 A:完整知识图谱版** | BiLSTM+CRF 实体识别 → R-BERT 关系抽取 → Neo4j 图谱 → BM25 → Deepseek | 生产级客服、需跨实体推理、大规模商品库 |
| **方案 B:简化可运行 RAG(本项目采用)** | 问答对知识库 + BM25+jieba 检索 + 双模型生成 + Web 页面 | 课程项目 / 快速验证 RAG / 低成本 FAQ 机器人 |
| **方案 C:纯检索直答** | 只检索不生成,直接返回最佳匹配答案 | 极简 FAQ、纯离线展示;作为 B 的降级兜底 |

**为什么最终选 B**:A 能力强但要标注数据 + Neo4j 运维 + GPU,超出单机课程项目; C 太浅答不出知识库没有的问法。
B 三要素(知识库/检索/生成)一个不缺,离线可跑,且沿 B 的接口可以逐步补入 A 的能力(见 04 演进路径)。

**本项目技术栈**:RAG、BM25、jieba、Deepseek、Ollama/Qwen、Flask。

## 4. 项目做的过程中有什么难点?步骤?

**步骤**(对应执行顺序):
```
① 数据清洗 → ② 建 BM25 索引 → ③ 检索自检 → ④ 接大模型(DS) → ⑤ 加本地 Qwen(Ollama)
→ ⑥ 双模型路由 + 降级 → ⑦ Flask 网页 → ⑧ 评测指标 → ⑨ 文档沉淀
```

**关键难点与解法**(全部如实记录在 `04_开发文档.md` 第九节):

| 难点 | 解法 |
|---|---|
| 中文分词 / 纯词级退化 | jieba + char 2-gram 混合分词,4 种策略实测选定 |
| BM25 与 TF-IDF 分数量纲不同 | 独立阈值 + 索引带 method 标记 |
| 客服语料大量寒暄对污染召回 | 长度/去重/种子采样三级清洗 |
| 双模型怎么选、怎么降级 | 路由策略 auto:DS → Qwen → 检索直答,主链路永不中断 |
| Ollama 安装/拉模型踩坑 | 断点续传下载、stdout 重定向避开 GBK/管道死锁 |
| 评测口径 | 先定义"链路自检 + 换说法召回"双口径,避免 Recall=0 假象 |

## 5. 项目经历应该如何写?(一段话素材)

> 我独立完成了一个**电商智能问答系统**,基于 RAG 架构:使用 16,205 条公开客服问答对,
> 设计清洗规则产出 8,000 条知识库;检索层采用 **BM25 + jieba 混合分词**(对比 4 种分词策略选型),
> 换说法召回 R@1 较旧版字符 n-gram TF-IDF 提升 12%→13.6%;生成层接入 **Deepseek 云端 + 本地 Qwen(Ollama)双模型**,
> 实现自动路由与三层降级链(DS→Qwen→检索直答),主链路离线可用;并开发了 Flask 聊天页面支持模式切换与证据追溯。
> 用固定种子双口径评测,链路自检 Top-1 命中 0.96,结果可复现。该经历覆盖了 RAG 全链路、
> 双模型路由、检索评测方法论,并沉淀为 5 份开发文档。

## 6. 项目成果(量化)

| 指标 | 数值 |
|---|---|
| 知识库 | 16,205 → 8,000 条(清洗) |
| 链路自检 Top-1 | 0.96 |
| 换说法召回 R@1 / R@5 | 0.136 / 0.296 |
| 双模型降级链 | DS → Qwen → 检索直答,主链路不中断 |
| 索引构建 | ~1.1s |
| 交互 | Web 页面 / 命令行 / HTTP 三入口 |

> 注:思维导图案例写的是"人工评测满意度 95%(1000 条测试)"——那是完整知识图谱版(方案 A)的目标口径。
> 本项目以**可复现的客观指标**(链路自检 + 召回率)替代主观满意度,口径更硬、可随时复跑。
