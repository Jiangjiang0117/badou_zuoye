## 1. 技术选型总览

| 层 | 选型 | 说明 |
|---|---|---|
| LLM 编排 | `openai-agents`（Python SDK） | 与课程一致；支持 Agent、Runner、串行编排、工具调用 |
| 大模型 | `qwen-max`（DashScope）为主，路由到更小模型/规则兜底 | 国内可访问，兼容 OpenAI 协议 |
| 数据库接入 | SQLAlchemy（`inspect`/`text`）+ 各库驱动 | 统一元数据内省与执行抽象 |
| 元数据/语义层 | 关系库（MySQL/PG）存储指标/维度/同义词/血缘 | 需要权限、版本、审核 |
| 向量检索 | 向量库（如 Milvus / PGVector） | 历史问答检索、Few-shot 召回 |
| 服务框架 | FastAPI（异步） | 与 Agent 异步模型契合，便于流式 |
| 前端 | 对话式 UI（React/Web Components）+ 图表库 | 表格、图表、报告 |
| 缓存 | Redis | 相同/相似问题结果缓存 |
| 可观测 | 日志 + Tracing（Langfuse/自研）+ 指标 | 延迟、成本、成功率 |
| 部署 | 容器化（K8s）+ 私有化可选 | 数据不出域方案 |

## 2. 总体架构

```
┌──────────────────────────────────────────────────────────────┐
│                         接入层                                │
│   Web UI / API / 企业IM(企微/钉钉) / 语音(二期)                 │
└───────────────────────────┬──────────────────────────────────┘
                            ▼
┌──────────────────────────────────────────────────────────────┐
│                      ChatBI 服务层（FastAPI）                  │
│                                                              │
│  ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────────┐     │
│  │ 对话管理 │ │ 意图路由  │ │ 问数引擎  │ │ 洞察/归因    │     │
│  │ Context  │ │ Router   │ │ NL2SQL   │ │ Insight      │     │
│  └──────────┘ └──────────┘ └──────────┘ └──────────────┘     │
│        │            │           │               │            │
│  ┌─────┴────────────┴───────────┴───────────────┴──────┐     │
│  │        能力中台（可被 Agent 以工具方式调用）            │     │
│  │  语义层引擎 · 元数据服务 · SQL执行器 · 权限服务 · 检索  │     │
│  └───────────────────────────┬──────────────────────────┘     │
└──────────────────────────────┼───────────────────────────────┘
                               ▼
        ┌──────────┬───────────┼───────────┬──────────────┐
        ▼          ▼           ▼           ▼              ▼
      MySQL     PostgreSQL  数仓(Hive/  Doris/    Redis/向量库
   (SQLite)                 Doris)   ClickHouse  /对象存储
```

**设计原则**
1. **能力中台化**：语义层、元数据、权限、执行器都是「可被 LLM 调用的工具」，而非埋在 Agent 内部，便于复用、测试、治理。
2. **Agent 只做调度与理解**：确定性、高风险的活（内省、执行、权限）交给中台服务。
3. **可信优先**：所有 SQL 必须经过语义层/权限/只读校验才可执行。

## 3. 核心链路：问数引擎（NL2SQL）

### 3.1 流水线（在课程 7 阶段基础上产品化）

```
用户问题
  │
  ├─(1) 意图识别[LLM] ── 问数 / 元数据 / 闲聊 / 操作
  ├─(2) 指标路由[语义层] ── 命中官方指标? ──是──► 直接用指标定义(口径)生成
  │                                          │否
  ├─(3) 实体链接[检索+语义层] ── 表/字段/维度/过滤值/同义词
  ├─(4) 表选择[LLM]  （课程 Stage2，升级为「实体链接结果」驱动）
  ├─(5) SQL生成[LLM] （课程 Stage3，注入 Few-shot + 口径）
  ├─(6) SQL校验[硬校验+语义校验]（课程 Stage4）
  ├─(7) SQL改写[LLM]（课程 Stage5，最多 N 次）
  ├─(8) 权限注入 + 只读执行[执行器]（课程 Stage6 增强）
  └─(9) 结果解读 + 选图[LLM]（课程 Stage7 增强）
```

### 3.2 与课程 Demo 的差异点

| 环节 | 课程 Demo | 产品化 |
|---|---|---|
| 表选择 | 直接让 LLM 从表清单里挑 | 先做实体链接（指标/字段/同义词召回），缩小候选，再让 LLM 确认 |
| SQL 生成 | 只看 schema 样例 | 注入指标口径、Few-shot（相似历史正确 SQL）、数据字典 |
| 校验 | 语法 + LLM 语义 | 增加执行计划校验、结果行数/形态校验、口径一致性校验 |
| 执行 | 直接跑 | 权限注入、超时、降采样、缓存 |

### 3.3 Few-shot 检索增强（RAG）

- 把「历史正确问答对（问题 → SQL）」向量化存入向量库。
- 新问题进来先召回 Top-K 相似样例，作为 SQL 生成的 in-context 示例。
- 兜底：召回不充分时走纯 schema 生成。

## 4. 指标语义层（关键技术）

### 4.1 数据模型

```
Metric(指标)     1──n  Synonym(同义词)
   │ 1
   │ n
Dimension(维度)  1──n  Synonym
   │
MetricDefinition(口径/计算逻辑) 1──1 MetricVersion(版本)
   │
   └─► 表达式 AST：metric = SUM(order.amount) WHERE status='paid'
                            [关联表/字段] [过滤] [聚合方式]
```

### 4.2 指标路由策略
1. 意图为问数 → 从问题中抽取「指标词」。
2. 用同义词/向量匹配 `Metric` 表，命中即取官方 `MetricDefinition`。
3. 命中官方指标 → 按定义生成 SQL（口径一致）；未命中 → 走通用 NL2SQL。

### 4.3 口径一致性保障
- 同一指标只有一份官方定义；任何改写都基于该定义，不允许自由重写计算逻辑。
- 口径变更走版本 + 审批，历史问答可追溯当时口径。

## 5. Agent 编排方案

### 5.1 编排模式选择

| 模式 | 适用 | 本项目 |
|---|---|---|
| 串行流水线（课程 `30_串行编排.py`） | 阶段有严格先后依赖 | 问数主链路采用 |
| 工具化 Orchestrator（`as_tool`） | 多能力路由 | 意图路由层采用：把「问数/元数据/洞察」包装成工具，由 router agent 分发 |
| Handoffs（转交） | 会话中切换专家 | 多轮追问时可选 |

### 5.2 Agent 清单

| Agent | 职责 | 类型 |
|---|---|---|
| router_agent | 意图识别与分发 | LLM + tools |
| entity_link_agent | 实体/指标/字段链接 | LLM + 检索工具 |
| table_select_agent | 表选择 | LLM（课程已有） |
| sql_gen_agent | SQL 生成 | LLM（课程已有） |
| sql_validate_agent | 语义校验 | LLM（课程已有） |
| sql_rewrite_agent | 改写自愈 | LLM（课程已有） |
| result_summary_agent | 结果解读 + 选图 | LLM（课程已有） |
| insight_agent | 异动归因（二期） | LLM + 分析工具 |

### 5.3 工具清单（能力中台暴露给 Agent）

| 工具 | 说明 | 确定性 |
|---|---|---|
| `get_metadata` | 查表/字段/血缘/样例 | 是 |
| `lookup_metric` | 查指标口径/同义词 | 是 |
| `execute_sql` | 只读执行（含权限注入） | 是 |
| `check_sql` | SQL 硬校验 | 是 |
| `search_fewshot` | 相似历史问答检索 | 是 |
| `get_chart_spec` | 结果→图表推荐 | 是（规则） |
| `detect_anomaly` | 异常检测（二期） | 是（算法） |

## 6. 安全与权限

### 6.1 只读 SQL 白名单
- 只放行 `SELECT / WITH / PRAGMA / EXPLAIN`。
- 关键字黑名单：`INSERT/UPDATE/DELETE/DROP/ALTER/ATTACH/TRUNCATE/GRANT/REVOKE`。
- 解析为 AST 再做二次校验（防关键字绕过），拒绝子查询里的写操作。

### 6.2 权限注入
- 从用户身份 → 权限服务 → 得到该用户可访问的表/行/列规则。
- 执行前把行级/列级过滤注入 SQL（或由执行器包裹），敏感列直接剔除/脱敏。
- 数据源原生权限优先对齐，避免两套权限体系不一致。

### 6.3 敏感数据
- 字段分级（普通/敏感/机密）；敏感字段识别（正则 + 规则 + LLM 辅助）。
- 输出前脱敏；机密字段默认拒绝问答。

## 7. 评测体系（技术实现）

### 7.1 评测集结构
```
{ question, gold_sql, gold_answer, metrics_hit?, difficulty, domain }
```

### 7.2 评测流程
```
CI/定时 → 跑评测集 → 对比(gold_sql 执行结果 vs 生成 SQL 执行结果)
        → 语义准确率(结果集合一致) / 口径命中率 / 端到端正确率
        → 产出报告与回归告警
```
- 结果集对比（而非字符串对比）是语义准确的可靠度量：`set(gold_rows) == set(pred_rows)`。

### 7.3 持续改进闭环
点踩/纠错 → 人工复核 → 更新 Few-shot / 同义词 / 口径 / 提示词 → 回归评测。

## 9. 性能与成本

| 手段 | 说明 |
|---|---|
| 结果缓存 | 相同/相似问题命中缓存（Redis），秒回 |
| 模型路由 | 简单问题走小模型/规则，复杂问题走大模型 |
| 超时控制 | SQL 执行超时、LLM 重试退避、整体 P95 预算 |
| 降采样 | 大结果集降采样/分页，限制返回行数 |
| 成本计量 | 按 token/请求记账，聚合到可观测看板 |

## 10. 可观测与运维

- **日志**：全链路 `request_id` 贯穿；记录 问题/SQL/口径/结果/耗时/成本/反馈。
- **Tracing**：Agent 多步调用链可视化（Langfuse 或自研）。
- **指标**：端到端延迟、各阶段耗时、成功率、准确率、token 成本、缓存命中率。
- **告警**：准确率骤降、延迟超阈值、失败率升高、成本异常。

## 12. 关键风险与缓解（技术）

| 风险 | 缓解 |
|---|---|
| LLM SQL 幻觉 | 语义层约束 + 硬校验 + 自愈 + 结果附 SQL 可审计 |
| 口径漂移 | 统一指标定义 + 版本 + 审批 |
| 越权/泄露 | 权限注入 + 只读白名单 + 脱敏 + 审计 |
| 慢查询拖垮库 | 超时 + 并发限流 + 只读 + 降采样 |
| 评测失真 | 结果集对比 + 人工抽检 + 评测集持续更新 |
