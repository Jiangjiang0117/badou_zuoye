# 技术设计文档（Technical Design Document）

## 1. 技术概述

| 项 | 选型 | 说明 |
|---|---|---|
| 语言 | Python 3.14 | 项目实际运行环境 |
| 前端 | Streamlit | 对话界面 + 表格/图表，低代码快速搭建 |
| 数据存储 | SQLite | 单文件、零部署，适合 MVP |
| 结构化输出 | Pydantic v2 | 约束 SQL 结果模型 |
| 模型调用 | OpenAI SDK | 兼容 Ollama（本地）与 DeepSeek/Qwen（远程） |
| 数据处理 | pandas | 结果转 DataFrame、类型判断、可视化 |

**依赖**：pandas、pydantic、openai、streamlit（见 `requirements.txt`）。

## 2. 系统架构

```
┌────────────────────────────────────────────────────────────┐
│  前端层  app.py (Streamlit)                                 │
│  对话输入 │ 结果渲染(表格+柱状图) │ SQL查看 │ 侧边栏示例    │
└───────────────────────┬────────────────────────────────────┘
                        │ ask(question, history)
┌───────────────────────▼────────────────────────────────────┐
│  Agent 层  src/agent.py                                    │
│  generate_sql → _rule_check(规则校验) → execute_sql → 自纠  │
│  Pydantic: SQLResponse / AgentResult                       │
└───────────────────────┬────────────────────────────────────┘
                        │ 系统提示词(语义层)
┌───────────────────────▼────────────────────────────────────┐
│  LLM 层  src/llm.py (OpenAI SDK)                           │
│  后端1: 本地 Ollama (base_url=localhost:11434/v1)          │
│  后端2: 远程 API (DeepSeek/Qwen)                           │
└───────────────────────┬────────────────────────────────────┘
                        │ SQL
┌───────────────────────▼────────────────────────────────────┐
│  数据层  SQLite (data/rentals.db)                           │
│  表 rentals(16字段,1585行) │ 由 generate_data → init_db 建   │
└─────────────────────────────────────────────────────────────┘
```

## 3. 模块设计

### 3.1 `src/metadata.py`（语义层）

职责：定义字段字典、指标库、业务规则、板块映射，并生成系统提示词。

- `COLUMNS`：16 个字段的名称/类型/中文含义/取值示例。
- `METRICS`：指标库，统一口径（房源总数、平均/最高/最低租金、租金中位数、平均面积、每平米租金、近地铁占比）。
- `RULES`：业务规则列表（租金用 rent、近地铁=near_metro=1、区/板块区分、占比需浮点、只读限制）。
- `BLOCK_TO_DISTRICT`：30 个板块 → 所在区映射（解决"下沙是钱塘区的板块，不是区"）。
- `build_system_prompt()`：拼接成大模型系统提示词。
- `get_schema_sql()`：返回建表 SQL。

### 3.2 `src/llm.py`（模型抽象层）

职责：屏蔽后端差异，统一 `chat(messages) -> str`。

- 后端选择：设置了 `CHATBI_API_KEY` + `CHATBI_BASE_URL` → 远程 API；否则本地 Ollama。
- 环境变量：`CHATBI_API_KEY`、`CHATBI_BASE_URL`、`CHATBI_MODEL`。
- 默认：本地 `http://localhost:11434/v1` + `qwen3:0.6b`。
- 统一异常封装：调用失败抛 `RuntimeError` 并带上下文。

### 3.3 `src/agent.py`（NL→SQL 核心）

职责：编排生成、校验、执行、自纠全流程。

| 组件 | 作用 |
|---|---|
| `SQLResponse`（Pydantic） | 结构化输出约束，仅允许 `sql`/`error` 字段 |
| `AgentResult`（Pydantic） | 返回结果模型：question/sql/columns/rows/error/corrected |
| `generate_sql()` | 首次生成 SQL（注入语义层提示词 + 历史） |
| `correct_sql()` | 错误自纠：问题+出错SQL+错误信息回喂 |
| `_parse_sql_response()` | 输出解析：JSON → 代码块 → 裸 SQL 三级兜底 |
| `_is_read_only()` | 只读校验（仅 SELECT/CTE） |
| `_rule_check()` | 规则校验（字段混淆、整数除法、非只读） |
| `execute_sql()` | 执行 SQLite，返回列名+行 |
| `ask()` | 主流程编排 |

### 3.4 `app.py`（前端）

职责：Streamlit 对话界面。
- `st.session_state.history`：最近 4 轮上下文。
- `st.chat_message` 渲染对话气泡。
- 结果渲染：`st.dataframe` + 自动 `st.bar_chart`（检测"文本列+数值列"）+ `st.expander` 展示 SQL。
- 侧边栏：模型后端信息 + 7 个示例问题按钮。

## 4. 数据结构设计

### 4.1 表结构 `rentals`

| 字段 | 类型 | 含义 | 取值示例 |
|---|---|---|---|
| id | INTEGER | 主键 | 1 |
| title | TEXT | 房源标题 | 钱江新城 市民中心公寓 3室2厅 整租 |
| district | TEXT | 城区 | 上城区/拱墅区/.../富阳区 |
| block | TEXT | 板块 | 钱江新城/申花/下沙 |
| community | TEXT | 小区 | 市民中心公寓 |
| layout | TEXT | 户型文本 | 2室1厅 |
| rooms | INTEGER | 室数 | 1/2/3/4 |
| halls | INTEGER | 厅数 | 0/1/2 |
| area | REAL | 面积(㎡) | 60.5 |
| orientation | TEXT | 朝向 | 朝南/南北通透 |
| floor | TEXT | 楼层 | 低/中/高楼层 |
| decoration | TEXT | 装修 | 精装/简装/豪装/毛坯 |
| rent | INTEGER | 月租金(元) | 4000 |
| near_metro | INTEGER | 是否近地铁 | 1/0 |
| rent_type | TEXT | 出租方式 | 整租/合租 |
| publish_date | TEXT | 发布日期 | 2026-10-15 |

### 4.2 数据生成

- `data/generate_data.py`：随机种子 42，按城区→板块→租金区间、户型/面积分布、朝向/楼层/装修权重生成 1585 条，输出 UTF-8-SIG CSV。
- `data/init_db.py`：CSV → SQLite（`INSERT` 全量重建，先 `DELETE` 再插入，保证幂等）。

## 5. 核心流程（NL→SQL）

```
ask(question, history)
  │ 1. generate_sql：系统提示词(语义层) + 历史 + 问题 → LLM → SQL
  │    - 解析失败 → 追加提示重试一次
  ├─ 2. _is_read_only：非只读 → 拒绝并返回错误
  ├─ 3. _rule_check：识别字段混淆/整数除法等 → 先 correct_sql 一次
  ├─ 4. 循环(≤MAX_CORRECT_ATTEMPTS+1)：
  │     execute_sql → 成功则返回结果
  │     抛错 → correct_sql → 重新校验只读 → 重试
  └─ 5. 返回 AgentResult(columns, rows) 或 error
```

### 5.1 错误自纠策略

- 自纠输入 = 原始问题 + 出错 SQL + `sqlite3.Error` 消息。
- 上限：`MAX_CORRECT_ATTEMPTS = 2`。
- 自纠后仍校验只读，杜绝被诱导为非 SELECT。

### 5.2 结果合法性校验（`_rule_check`）

| 识别项 | 判定 | 修正提示 |
|---|---|---|
| 装修字段用错 | SQL 含 `rent_type` 且值含精装/简装/毛坯 | 提示用 `decoration` |
| 占比整数除法 | 含 `SUM(` 与 `/` 且无 `100.0` 与 `COUNT(*)` | 提示加 `*100.0` 浮点 |
| 近地铁占比误用 COUNT | 含 near_metro 且用 COUNT 而非 SUM | 提示 `SUM(near_metro)*100.0/COUNT(*)` |

## 6. 模型抽象与配置

### 6.1 环境变量

| 变量 | 默认 | 说明 |
|---|---|---|
| `CHATBI_API_KEY` | 空 | 设置后走远程 API；空则走本地 Ollama |
| `CHATBI_BASE_URL` | `http://localhost:11434/v1` | 模型服务地址 |
| `CHATBI_MODEL` | 本地 `qwen3:0.6b` | 模型名 |

### 6.2 后端选择逻辑

```python
if CHATBI_API_KEY and CHATBI_BASE_URL:
    → OpenAI(api_key, base_url)  # 远程 DeepSeek/Qwen
else:
    → OpenAI(api_key="ollama", base_url=localhost:11434/v1)  # 本地
```

## 7. 安全设计

| 威胁 | 防护 |
|---|---|
| SQL 注入 / 非查询语句 | `_is_read_only` 仅放行 `SELECT`/CTE；拒绝 DML/DDL |
| 模型输出异常 | Pydantic 约束 + 三级解析兜底（JSON→代码块→裸 SQL） |
| 数据篡改 | SQLite 只读连接执行，结果不写库 |
| 自纠被诱导写操作 | 自纠后再次只读校验 |
| 敏感字段 | 仅白名单字段（语义层定义），无 PII |

### 8.2 已知缺口

- 本地 0.6b 模型对复杂语义（板块归属、比例口径）稳定性不足，已靠规则校验部分兜底，**建议升级 qwen3:8b 或 API**。
- 未覆盖自动化单测（可用 `pytest` 扩展）。

## 9. 部署与运行

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python data/generate_data.py   # 生成仿真数据
python data/init_db.py         # 初始化数据库
streamlit run app.py           # 启动，默认 http://localhost:8501
```

## 10. 演进方向

1. 模型升级：本地 qwen3:8b/14b 或 DeepSeek API，提升准确率。
2. 真实数据接入 + 增量更新。
3. 自然语言出图指令、报表导出。
4. 自动化测试（pytest + 用例集）。
5. 语义缓存（历史同义问题复用 SQL）。
