# 项目设计文档（Project Design Document）

## 1. 项目概述

| 项 | 内容 |
|---|---|
| 项目名称 | 杭州租房 ChatBI（Hangzhou Rent ChatBI） |
| 项目类型 | 对话式数据分析系统（NL→SQL→可视化） |
| 一句话定位 | 用自然语言查询杭州租房数据，自动生成 SQL 并可视化，降低数据分析门槛 |
| 技术底座 | Python + Streamlit + 大模型（本地 Ollama / OpenAI 兼容 API） |
| 数据域 | 杭州 9 城区、30 板块、1585 条仿真房源 |

## 2. 项目背景

- 传统 BI 工具门槛高：需要懂 SQL、会操作报表工具，非技术人员无法自助取数。
- 租房决策高度依赖数据（租金、户型、区位、地铁），但普通用户只会"逛平台"，难以横向对比、统计。
- 大模型已具备将自然语言转 SQL 的能力，但直接裸用准确率低、口径不稳定，需要语义层与校验兜底。

## 3. 项目目标

### 3.1 业务目标
1. 用户能用中文问句直接获取房源统计与筛选结果（"杭州各区平均租金是多少？"）。
2. 支持条件组合查询（区/板块、预算、户型、近地铁、装修、朝向）。
3. 结果以表格 + 图表直观呈现，可追溯生成的 SQL。

### 3.2 技术目标
1. 端到端打通「自然语言 → SQL → 执行 → 可视化」链路。
2. 通过语义层（字段字典 + 指标库 + 业务规则 + 板块映射）稳定 SQL 口径。
3. 具备错误自纠与只读安全校验，避免非查询语句与恶意注入。
4. 模型可插拔：本地 Ollama 与远程 API 无缝切换。

## 4. 项目范围

### 4.1 范围内（MVP）
- 杭州房源仿真数据建模与入库（SQLite）。
- 自然语言查询 → SQL 生成 → 执行 → 表格/图表展示。
- 多轮上下文、错误自纠（≤2 次）、结果合法性校验。
- Streamlit 对话界面（含示例问题、SQL 查看、自动可视化）。

### 4.2 范围外（非本次目标）
- 真实房源数据爬取与实时更新。
- 多数据源接入、复杂权限体系、账号系统。
- 通勤计算（已按用户要求排除）、地图联动、预测模型。

## 5. 干系人与角色

| 角色 | 职责 |
|---|---|
| 项目发起人 | 提供业务诉求、验收演示 |
| 开发（本项目 Agent） | 数据建模、语义层、NL→SQL 核心、前端、测试交付 |
| 使用者 | 有租房需求、无 SQL 技能的用户 |

## 6. 总体方案

```
┌────────────┐   中文问句    ┌──────────────┐   语义层注入   ┌───────────┐
│ Streamlit   │ ────────────▶ │  NL→SQL Agent │ ─────────────▶ │ 大模型     │
│ 对话界面     │              │  (agent.py)   │               │  (llm.py)  │
└────────────┘ ◀──────────── └──────────────┘ ◀────────────── └───────────┘
   ▲  表格/图表/SQL      │  执行结果/自纠
   │                     ▼
   │            ┌──────────────┐
   └────────────│  SQLite 数据库 │
                └──────────────┘
```

- 语义层（`metadata.py`）：表结构、字段字典、指标库、业务规则、板块归属 → 生成系统提示词。
- 模型层（`llm.py`）：抽象 Ollama / API 两种后端。
- Agent 层（`agent.py`）：生成 → 校验 → 执行 → 自纠。
- 数据层：`generate_data.py` 生成仿真 CSV → `init_db.py` 入库 SQLite。

## 7. 数据方案

> ⚠️ **关键说明**：本数据为**仿真演示数据**，基于杭州真实城区/板块分布与常见租金区间生成（固定随机种子 42，可复现），**非真实挂牌房源**。用于项目演示、测试与功能验证。

- 数据规模：1585 条 / 9 城区 / 30 板块。
- 生成方式：`data/generate_data.py`（随机种子固定，结果确定）。
- 存储：SQLite（`data/rentals.db`），单表 `rentals`。
- 字段（16 列）：id、title、district、block、community、layout、rooms、halls、area、orientation、floor、decoration、rent、near_metro、rent_type、publish_date。

**演进方向**：接入真实挂牌数据（贝壳/链家公开数据或官方住房租赁平台），增加更新时间字段与增量更新机制。

## 9. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 本地模型能力不足（qwen3:0.6b） | SQL 生成准确率低、易用错字段/口径混淆 | 语义层 + 规则校验兜底；模型可插拔，升级 qwen3:8b 或 API |
| 仿真数据非真实 | 结论不代表市场真实行情 | 文档/界面明确标注；支持替换真实数据源 |
| SQL 注入 / 非查询语句 | 数据安全 | 只读校验（仅允许 SELECT/CTE）+ 白名单表名 |
| 大模型调用失败/超时 | 服务不可用 | llm 层统一异常封装；本地 Ollama 回退 |

## 10. 验收标准

1. 前端可启动，健康检查通过（`/_stcore/health` 返回 ok）。
2. 简单条件查询（区 + 预算 + 户型）可正确生成 SQL 并返回结果。
3. 分组聚合（各区平均租金、近地铁占比）返回正确指标。
4. 无匹配时如实返回空结果，不编造数据。
5. 生成的 SQL 可在界面中查看；非只读语句被拒绝执行。
6. 多轮对话上下文可延续。
