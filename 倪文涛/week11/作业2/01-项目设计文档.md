## 1. 背景与定位

业务人员查询销售数据，通常需要了解表结构、编写 SQL，再整理成表格或图表。本项目面向课程演示，以电商销售为固定业务领域，让使用者打开本机浏览器后直接输入中文问题，获得可核对的数据结果。

项目采用 ChatBI 交互和多 Agent 编排：IntentAgent 理解问题与澄清，QueryAgent 调用受控查询工具并完成有限修正，AnswerAgent 整理有数据依据的结论。编排器按固定流程调度，业务规则、权限和执行次数由后端服务统一控制。系统不承担开放式自主研究、预测、因果归因或业务操作。

验收同时面向老师和开发团队：老师能够通过完整场景演示评估效果，开发人员能够依据功能规则、数据字典及接口契约实现系统。

## 2. 目标与成功标准

| 目标 | 可检查的表现 | 验收依据 |
| --- | --- | --- |
| 演示完整 | 从启动、提问、澄清、查询、追问到图表、导出、历史恢复形成闭环 | 功能文档中的流程和 AC-01～AC-20 |
| 查询正确 | 销售额、订单量、客单价和比较值符合统一口径 | 独立基准 SQL 对比，金额按分校验 |
| 分析可信 | 可查看 SQL、参数、指标定义、筛选范围；结论不添加无依据原因 | 回答审查和故障注入 |
| 能指导实现 | 表结构、状态、接口、配置、错误及测试有明确约定 | 技术文档与需求追踪表 |

计划建立 20 个验收案例，作为演示题集和开发测试清单。正常查询的核心数值必须全部与基准结果一致；金额聚合使用整数分，派生比率按文档规则舍入。澄清和拒绝场景不得误执行 SQL，失败场景不得伪造结果。上述是验收目标，当前尚未运行项目或测得通过率。

## 3. 用户、场景与边界

### 3.1 使用角色

产品只有一种使用角色：查询演示数据的访问者，无登录、注册或角色权限。典型使用者可视为销售运营、课程老师或演示人员。开发者通过后端环境变量配置模型服务，通过离线脚本准备数据；不在页面内配置密钥。

### 3.2 代表场景

1. 输入“2025 年销售额、订单量和客单价是多少”，查看指标及口径。
2. 输入“2025 年每月销售额趋势”，查看折线图和月度数据。
3. 继续输入“只看华东”，保留年度、指标和粒度，增加地区条件。
4. 输入“哪个地区表现最好”，在没有既有指标时先选择销售额、订单量或客单价。
5. 输入“2025 年销售额最高的 10 个商品”，通过订单、明细和商品关联获得排行。
6. 查询明细、查看 SQL、导出已返回数据，刷新后恢复历史。

### 3.3 首版范围

| 需求编号 | 能力 | 范围说明 |
| --- | --- | --- |
| R-01 | 本机免登录访问 | 前后端仅绑定回环地址，联网调用模型 |
| R-02 | 自然语言查询 | 统计、分组排行、趋势、同比环比、关联、明细 |
| R-03 | 对话与澄清 | 当前会话继承条件，歧义先澄清，新会话重置 |
| R-04 | 结果可追溯 | 结论、表格、适用图表、SQL、参数、口径和条件 |
| R-05 | 结果操作 | 每页 50 行、最多返回 1,000 行、复制 SQL、CSV 导出 |
| R-06 | 本地历史 | 多会话、刷新恢复、删除、同浏览器共享 |
| R-07 | 受控执行 | 只读、有限 SQL 修正、运行上限、60 秒请求期限 |
| R-08 | 异常可解释 | 空结果、数据范围外、故障、截断及总结降级 |
| R-09 | 可重复数据 | 固定种子、四张核心表、金额和关联一致性 |
| R-10 | 模型与日志配置 | 兼容接口接入验证、后端保管密钥、关闭云端 tracing |

首版不包括用户管理、任意数据库连接、文件上传、数据写入、退款流程、库存管理、营销活动、预测、自动归因、定时任务、自定义仪表盘、跨浏览器同步或公网部署。跨表关联仅限本项目四张业务表。

## 4. 数据与业务基线

| 项目 | 固定约定 |
| --- | --- |
| 数据类型 | 虚构演示数据，非真实经营业绩 |
| 时间范围 | 2024-01-01 至 2025-12-31，按订单发生日期统计 |
| 数据规模 | 1,000 位客户、100 个商品、5,000 笔订单；每单 1～5 条明细 |
| 数据实体 | 客户、商品、订单、订单明细 |
| 订单状态 | 待付款、已付款、已完成、已取消 |
| 有效订单 | 已付款、已完成 |
| 销售额 | 有效订单实付金额；商品范围下使用对应明细实付金额 |
| 订单量 | 对应范围内有效订单的去重数量 |
| 客单价 | 对应范围销售额÷对应范围有效订单量，分母为零返回空值 |
| 商品金额 | 明细保存数量、成交单价和实付金额；折扣已分摊，汇总等于订单实付 |
| 地区 | 订单收货大区，如华东、华南；不采集真实地址 |
| 时间基准 | “今天”锚定 2025-12-31；不使用运行电脑的真实日期推导演示范围 |

数据生成使用固定种子和固定算法，保留每月基础订单、促销月份差异、地区分布差异以及多明细订单，支持趋势展示和重复计数检测。差异是人为设计的分布，不应被解释为真实促销因果。技术文档规定生成约束和校验方法。

## 5. 总体方案

| 层次 | 选型 | 职责 |
| --- | --- | --- |
| 浏览器 | Vue 3、TypeScript、ECharts | 聊天、澄清、结果、分页、图表、CSV、本地会话 |
| 服务端 | Python、FastAPI | 请求管理、阶段事件、结构校验、业务规则和统一响应 |
| Agent | OpenAI Agents SDK，三个专职 Agent | 意图澄清、查询与修正、答案整理，由代码串行编排 |
| 查询层 | 结构化 QuerySpec、指标定义、SQLite SQL 编译与校验 | 确保金额口径和关联粒度，受控只读执行 |
| 存储 | 本地 SQLite 文件 | 保存四张业务表，不保存用户身份和聊天历史 |
| 外部服务 | 配置的兼容模型 API | 处理允许发送的问题、结构及有限数据 |

主链路为：问题与会话上下文 → IntentAgent 产生结构化查询意图或澄清 → QueryAgent 调用后端生成、校验并只读执行 SQL → AnswerAgent 选择结果支持的事实 → 后端生成结论 → 前端展示。采用受约束的 Text-to-SQL：模型决定业务查询条件，后端负责可信 SQL 生成，不开放自由 SQL 控制台。

后端目录以 `backend/` 为根，包含 `main.py`（FastAPI 应用与启动入口）、`chatbi.db`（SQLite 文件）、`requirements.txt`、`api/`（接口层）、`services/`（服务层）和 `agent/`（业务智能体层）。本地包采用单数 `agent`，避免与 SDK 的 `agents` 导入名冲突；初始化与模型预检也由 main.py 的命令入口统一调用。

后端维护单次请求的临时任务状态供前端读取真实处理阶段；该状态不构成聊天历史或用户账号，进程重启即可丢失。数据导出和会话恢复由浏览器完成。

## 6. 核心流程

### 6.1 成功查询

访问首页 → 查看数据范围与示例 → 输入问题 → 显示实际处理阶段 → 校验业务条件 → 执行查询 → 展示结论、数据及适用图表 → 展开依据或导出 → 保存到当前浏览器会话。

### 6.2 澄清与追问

没有可继承指标或存在关键歧义时，系统返回具体问题及可选项，本轮不执行 SQL。用户回复后结合待澄清问题继续解析。后续追问只覆盖明确改变的条件，其余继承；新建会话不继承其他会话条件。

### 6.3 失败与降级

结构或查询可修正错误 → QueryAgent 根据错误修正，首次加最多 2 次修正共 3 个候选尝试；安全拒绝、超时和外部 API 故障不进行 SQL 修正。最终无结果则解释失败，不生成数据结论。SQL 已成功而 AnswerAgent 总结失败，则保留数据、图表和 SQL。所有 Agent、模型和工具活动受同一总请求期限约束，切换 Agent 不重置期限或修正预算。

## 7. 质量、运行及信息边界

| 主题 | 约束 |
| --- | --- |
| 响应 | 请求默认总期限 60 秒，展示真实阶段；尚未测得平均耗时 |
| 查询量 | 表格每页 50 行，后端最多返回 1,000 行，另取一行判断截断 |
| 统计正确性 | 先全量筛选、聚合、排序，再限制返回行数 |
| 分析边界 | 截断只能总结已返回部分，全量结论需数据库聚合依据 |
| 运行范围 | 本机演示，单进程、小规模并发，不承诺多租户吞吐 |
| 数据权限 | SQLite 只读连接、只读授权与 SQL 校验；离线初始化与在线查询分离 |
| 数据外发 | 允许必要问题、上下文、结构、指标、有限结果；不发送整个数据库 |
| 敏感信息 | 客户只用虚构编号和非敏感属性；API 密钥仅存后端环境 |
| 可观测性 | 默认关闭云端 tracing，日志记录请求号、阶段、耗时、次数和错误类别 |
| 可用性 | 总结失败可降级；模型不可用时不伪装实时智能查询 |

## 8. 实施阶段与产出

当前没有约定交付日期和人员数量，按依赖安排阶段，不编造工期承诺。

| 阶段 | 工作 | 完成条件 |
| --- | --- | --- |
| M0 设计基线 | 确认业务、功能、技术及接口 | 三份文档一致、关键问题闭合 |
| M1 数据与查询核心 | 初始化四表、生成固定数据、指标编译、只读执行、独立基准 | 金额、关联、范围和只读测试通过 |
| M2 Agent 接入 | 三 Agent 预检、结构输出、编排交接、工具、澄清、修正、共享期限 | 固定问题获得正确结果或明确澄清，跨 Agent 不绕过限制 |
| M3 前端闭环 | 页面、阶段、结果、图表、CSV、本地历史 | 主流程和刷新恢复可用 |
| M4 联调验收 | 20 案例、故障注入、演示彩排 | 记录模型、依赖、数据版本及实际测试结果 |

人员可由同一开发者兼任产品、前后端和测试；基准 SQL 应先独立编写，再与系统结果对比，不用同一查询编译器同时生成“答案”和“标准答案”。

## 9. 风险与应对

| 风险 | 应对 | 剩余限制 |
| --- | --- | --- |
| 兼容 API 不支持工具或结构返回 | 上线演示前执行模型接入预检并锁定版本 | 没有指定供应商，当前尚未实际联调 |
| 多表关联重复计算金额 | 统一 QuerySpec 与指标编译规则，覆盖多明细订单案例 | 首版只支持规定维度和运算 |
| 模型将相关性写成原因 | 结论采用数据事实引用及受限文字，审查不支持的断言 | 自由文本不能仅靠提示词保证正确 |
| 演示当天网络不稳定 | 提前检查联网、配置及固定题集；故障时明确提示 | 不承诺离线自然语言查询 |
| 本地历史占满或被清除 | 存储前校验、容量提示、可删除；不静默丢数据 | 不跨浏览器同步，不构成备份 |
| 当前时间与演示时间冲突 | 持续展示锚点，答案列出实际日期区间 | 不反映 2026 年实际销售情况 |

## 10. 演示与验收组织

建议演示顺序：启动及数据说明 → 三项核心指标 → 月趋势 → 地区追问 → 商品排行及 SQL → 新会话歧义澄清 → 明细与 CSV → 刷新恢复 → 超范围和只读拒绝。异常重试、超时和外部服务故障可在可控测试中展示，不通过破坏业务数据库制造故障。

验收记录应包含数据版本、种子、模型标识、API 类型、依赖锁文件、案例输入、预期结果、实际结果、SQL 与必要截图。报告中的数字必须来自实际运行，文档示例不当作测试证据。
