## 2. 页面与信息架构

### 2.1 单页布局

| 区域 | 内容与交互 |
| --- | --- |
| 左侧会话栏 | 新建会话、会话列表、当前项、删除入口；标题默认取首条问题前 20 个字符 |
| 顶部信息栏 | 项目名、演示数据日期范围、相对时间基准、服务可用状态 |
| 空会话欢迎区 | 能力说明、示例问题、只读与虚构数据说明 |
| 中间消息区 | 用户问题、澄清卡、阶段状态、回答卡、错误提示；历史结果可展开 |
| 底部输入区 | 多行输入、发送按钮；运行时当前会话禁止重复发送 |
| 回答依据区 | 展开查看 SQL、绑定参数、指标口径、实际条件、修正次数 |

页面主文案：“演示数据：2024-01-01—2025-12-31；相对时间以 2025-12-31 为基准。”模型状态只展示是否配置、预检是否通过及简短原因，不展示密钥、完整 API URL 或异常堆栈。

首版优先支持桌面浏览器；窄窗口将会话栏折叠，表格允许横向滚动。按钮、标签和错误不能只通过颜色区分，输入框可键盘操作。

### 2.2 示例问题

- 2025 年销售额、订单量和客单价是多少？
- 2025 年每月销售额趋势如何？
- 2025 年各地区销售额排行。
- 2025 年销售额最高的 10 个商品。
- 2025 年 12 月销售额同比和环比是多少？
- 查看 2025 年 12 月华东地区的有效订单明细。

点击示例只填入输入框，由用户发送。页面不提供登录、数据连接管理或模型密钥输入框。

## 3. 使用前置与输入规则

1. 后端可访问本地数据文件，数据版本校验通过，模型服务配置有效。
2. 前端启动时读取系统元信息；模型未配置时允许浏览历史，但禁用新查询并提示由开发者检查后端配置。
3. 输入去除首尾空白后为 1～2,000 个字符，空白不能发送；Enter 发送、Shift+Enter 换行，中文输入法组字时不触发发送。
4. 每次发送立即显示用户消息并持久化；服务端接受后，记录请求编号并显示真实阶段。
5. 同一会话一次只运行一个请求；可切换其他会话查看历史，切换不取消正在执行的请求。
6. 网络重试必须由用户主动点击，产生新的请求编号，界面在原消息下记录新的尝试，不复制一条用户问题。

## 4. 对话、澄清与条件继承

### 4.1 业务条件

每次查询解析为：任务类型、指标、时间范围、分组维度、筛选条件、排序和返回数量。界面用可读标签展示最终生效条件。缺省且不影响业务含义的值可以自动补全，但必须展示：

| 条件 | 首次独立查询的默认值 |
| --- | --- |
| 时间 | 全部演示范围，2024-01-01 至 2025-12-31 |
| 有效销售范围 | 已付款、已完成 |
| 地区、商品、品类、客户分层 | 全部 |
| 排行条数 | 明确“排行/前几名”但未指定条数时，前 10 名 |
| 趋势粒度 | 已明确趋势但未指定粒度时，按月，并显示默认值 |
| 明细类型 | 只说“明细”时询问订单级还是商品明细级 |

“销售额”“订单量”“客单价”可直接映射统一指标。“业绩/表现最好”“增长多少”且无法从上下文确定指标或比较方式时，必须澄清。“平均”未说明对象时也需澄清。

### 4.2 连续追问规则

| 用户输入 | 处理 |
| --- | --- |
| “只看华东” | 继承指标、时间、任务及粒度，地区改为华东 |
| “换成按品类” | 替换分组维度，保留筛选；排序仅在仍兼容时继承 |
| “改成订单量” | 替换指标；若原排序指标已消失，同步替换为新指标 |
| “取消地区限制” | 清除地区条件，保留其余条件 |
| “再加上订单量” | 追加指标，不清除原指标 |
| “重新查 2024 年各地区销售额，不要沿用条件” | 按独立完整问题重置条件 |
| “它怎么样”且指代不清 | 澄清指代，不猜测 |

新会话没有继承条件。执行失败、被拒绝或空问题不更新上一次成功的查询条件；合法但结果为空的查询仍可成为后续追问上下文。文字总结失败不影响成功查询条件的保存。

历史问题包含一个已批准的结构化条件快照及有限消息文本。后端重新校验客户端传入的条件，不把历史 SQL、浏览器缓存或模型自述视为可信执行依据。

### 4.3 澄清交互

示例：用户首次问“哪个地区表现最好？”系统显示：“你希望按哪个指标比较地区？”并提供“销售额”“订单量”“客单价”选项，也支持输入自定义补充。

澄清响应必须列出待补条件，本轮不执行 SQL，不显示空图表或“查询成功”。用户补充后合并原始问题继续处理；一次可询问多个相互独立的缺失项。切换会话后回来仍能恢复待澄清状态；新问题明确放弃原任务时清除待澄清项。

## 5. 查询能力与业务规则

### 5.1 指标与统计粒度

| 指标 | 定义 | 展示 |
| --- | --- | --- |
| 销售额 | 有效订单实付金额；有商品/品类筛选时汇总匹配明细实付 | 人民币元，2 位小数 |
| 订单量 | 当前范围有效订单去重计数 | 整数，单位“单” |
| 客单价 | 当前范围销售额÷当前范围有效订单量 | 元/单，2 位小数；无订单为“—” |
| 销售数量 | 当前范围有效订单对应商品数量之和 | 整数，单位“件” |

商品/品类分组时，一张包含多个商品的订单可能进入多个组，各组订单量不能相加解释为全局订单量。此时客单价标明“该商品/品类成交额÷包含该商品/品类的有效订单数”。系统不得将该值表述为整张订单的平均实付。

不带商品维度时，订单级指标以订单表为统计基础，避免订单明细关联造成销售额重复。客户分层通过客户表关联，地区以订单收货大区为准。默认不支持利润、退款净额、库存和获客成本；询问这些内容应说明缺少数据。

### 5.2 时间规则

日期以中国时区的业务日表达，查询使用左闭右开区间；界面显示含首尾的自然日期。

| 表述 | 实际查询范围 |
| --- | --- |
| 全部数据 | [2024-01-01, 2026-01-01) |
| 今天 | [2025-12-31, 2026-01-01) |
| 今年 | [2025-01-01, 2026-01-01) |
| 最近一个月 / 本月 | [2025-12-01, 2026-01-01) |
| 上个月 | [2025-11-01, 2025-12-01) |
| 最近 7 天 | [2025-12-25, 2026-01-01) |

“近 30 天”按含锚点的 30 个自然日解释，与“最近一个月”区分；界面始终列出最终日期。完整落在数据集外的明确日期，直接告知无覆盖；部分相交时只查询交集并显示范围调整，不静默将 2026 年问题改成 2025 年。

首版同比/环比支持自然月、自然年及月/年序列；单独询问“同比”未给周期且上下文也无周期时先澄清。月同比比较去年同月，月环比比较上一个自然月，年同比比较上一自然年；“年环比”按上一自然年并说明。任意不完整日期段的同比/环比先要求改成完整自然月/年，避免不同天数的隐含口径。

增长率＝（本期值－对比期值）÷对比期值×100%，保留 2 位小数。对比范围无覆盖或部分缺失时不可计算；有完整覆盖但无成交时指标为零，零分母不可计算。无成交的月份在趋势中补齐为 0，客单价补为空值。

### 5.3 支持的查询形态

| 类型 | 规则 |
| --- | --- |
| 汇总 | 可同时查询多个预置指标，默认单个指标卡或多指标卡 |
| 分组 | 支持地区、品类、商品、客户分层及日/月/年；首版最多两个分组维度 |
| 排行 | 按一个已选择指标排序；并列时用分组标识稳定排序，不自动扩展并列名次 |
| 趋势 | 按时间升序；默认月；仅支持有明确定义的日/月/年粒度 |
| 比较 | 返回本期、对比期、差额、增长率和无法计算原因 |
| 订单明细 | 一行一订单，含订单编号、日期、客户编号、地区、状态、实付金额 |
| 商品明细 | 一行一订单明细，含订单及商品编号、品类、数量、单价、分摊折扣、明细实付 |

明细默认查询有效订单；明确要求“已取消订单明细”等状态时可返回对应记录，但不能将其统计为有效销售业绩。用户明确要求把取消订单计入销售额时，应说明统一指标不包含它们，并建议查看状态明细。

## 6. 回答卡与结果操作

### 6.1 回答组成

按顺序展示：简短结论 → 生效条件 → 指标卡或适用图表 → 数据表 → 行数与截断提示 → 可展开依据 → 复制和导出操作。数据表始终可访问，图表不替代原始数字。

结论仅描述本次返回数据支持的事实，例如“华东在返回的地区排行中销售额最高”。不生成“因为促销有效”“客户更喜欢该商品”等因果解释；不展示模型内部思考过程。若截断，结论必须明确范围限制。

### 6.2 图表规则

| 数据形态 | 默认展示 | 允许切换 |
| --- | --- | --- |
| 无维度、单行指标 | 指标卡及表格 | 表格 |
| 时间序列 | 折线图及表格 | 柱状图、表格 |
| 单分类维度排行/分组 | 柱状图及表格 | 表格 |
| 两维或明细、无合适数值列 | 表格 | 首版不强制生成复杂图表 |

图表只引用本次已返回数据列，前端使用固定 ECharts 配置，不执行模型提供的 JavaScript、HTML 或配置函数。分类超过 20 项时图表只显示前 20 项并标注“图表展示 20 项，完整已返回数据见表格”；这与后端 1,000 行截断分开提示。

金额和数量使用独立坐标或分开选择，不把不同单位直接混在同一个轴上。比较结果对不可计算的增长率显示“—”及原因。

### 6.3 依据与复制

可展开区展示实际执行成功的受控 SQL、绑定参数、指标定义、生效日期及其他筛选、数据版本、修正次数。SQL 和参数分开展示，复制时生成一个包含 SQL 与参数 JSON 注释的文本块，不将参数简单拼接为可执行 SQL。

若尚未成功执行，则按状态展示“未执行查询”或最后一份安全候选 SQL 与失败原因，不能标成成功执行依据；被安全校验拒绝的文本不作为可复制执行结果。所有字段以纯文本渲染。

### 6.4 分页、截断与导出

- 浏览器对已返回行做每页 50 行分页；翻页不调用模型，也不重新查数据库。
- 后端最多返回 1,000 行，查询阶段取至多 1,001 行判断是否截断，第 1,001 行不展示、不导出、不送模型。
- 截断时显示“仅返回前 1,000 行，结果已截断；请缩小范围或使用汇总查询”。不展示未经计算的总行数。
- CSV 导出当前回答的全部已返回行，最多 1,000 行，包含列头且顺序与表格一致；不是仅导出当前 50 行，也不承诺导出数据库全部匹配行。
- 文件名包含请求编号及数据集标识；UTF-8 BOM 编码，规范转义逗号、引号和换行。对字符串公式前缀做防护；数值保持数值语义。
- 空结果禁用导出；复制和下载失败显示原因，可重试，不改变查询结果。

## 7. 会话与本地持久化

每个会话保存编号、标题、创建和更新时间、消息、上次合法查询条件、待澄清内容和数据版本。最终回答保存返回数据及必要依据，以便刷新后恢复图表、表格和导出能力。

默认采用浏览器 IndexedDB，以事务方式保存，避免 localStorage 对多条结果数据的容量限制。另一个同源标签页可读取同一份会话；写入后通知其他标签页重新加载，避免旧快照覆盖新消息。跨浏览器、跨端口、隐私模式和清除站点数据均可能导致历史不可见。

| 操作 | 规则 |
| --- | --- |
| 新建 | 建立空会话并切换；不复制旧会话筛选 |
| 切换 | 恢复消息、结果和澄清；不取消其他会话请求 |
| 刷新 | 恢复历史，未完成请求尝试重新查询临时任务状态 |
| 后端重启或任务过期 | 未完成消息标记“处理中断”，用户可重试 |
| 删除 | 用户确认后删除本机会话；有运行任务时禁止删除，提示等待结束 |
| 存储失败 | 明确提示“本次记录未能保存”，保留当前内存结果，允许删除旧会话后重试保存 |
| 数据版本变化 | 历史结果继续标记旧版本；不将旧查询快照自动带入新查询，提示新建会话 |

浏览器同源标签页中同一会话通过 Web Locks 防止重复提交；不支持该能力的目标浏览器不作为首版验收环境。浏览器存储不是后端账号或备份系统。

## 8. 阶段、错误与降级

### 8.1 处理状态

| 状态 | 用户展示 | 可否发送当前会话下一问 |
| --- | --- | --- |
| idle | 可输入问题 | 是 |
| understanding | 正在理解问题 | 否 |
| querying | 正在校验并查询数据 | 否 |
| repairing | 正在修正查询（第 1/2 次） | 否 |
| summarizing | 正在整理结果 | 否 |
| clarification | 请补充条件 | 是，按澄清上下文处理 |
| success / partial | 查询完成 / 数据成功、总结不可用 | 是 |
| empty / out_of_scope | 无匹配结果 / 超出支持范围 | 是 |
| rejected / failed / timeout | 已拒绝 / 失败 / 超时 | 是 |

阶段只展示当前实际状态，修正时允许回到 querying；不以定时器制造进度百分比。后台由 IntentAgent 对应理解/澄清阶段、QueryAgent 对应查询/修正阶段、AnswerAgent 对应整理结果阶段，用户仍在同一会话中操作，不需要选择 Agent。

首次执行后最多修正 2 次，共最多 3 个查询候选尝试。三个 Agent 共享同一请求的次数与 60 秒总期限，交接不重置预算。安全拒绝、API 故障、查询期限超时不进入 SQL 自动修正；澄清后不再调用查询或答案 Agent，空结果不调用答案 Agent。

### 8.2 异常行为

| 情况 | 展示与处理 |
| --- | --- |
| 明确日期完全超出数据范围 | 说明数据覆盖，未执行 SQL，不编造对应年度数据 |
| 不支持的业务指标 | 说明缺少字段或口径，给出可查询指标 |
| 明细无记录 / 分组无匹配 | 单独展示空结果，保留筛选和成功 SQL |
| 汇总无成交 | 销售额、订单量为 0，客单价为“—”，不误报系统错误 |
| 请求修改或删除数据 | 明确只读拒绝，不调用写入工具 |
| SQL 连续失败 | 列出简短错误类别与建议、已用修正次数；不生成结论 |
| 模型认证、限流或网络故障 | 显示服务暂不可用及重试建议，不展示密钥或第三方原始响应 |
| 60 秒到期且 SQL 未成功 | 超时结束，不生成结论，不在后台继续修正 |
| SQL 成功、总结失败或超时 | 保留数据、图表、SQL，标注“数据查询成功，文字总结暂不可用” |
| 网络断开 | 保留问题与请求编号；恢复后读取状态，不能确认时提示中断 |
| 后端繁忙 | 明确提示稍后重试，不静默排队超出总期限 |

## 9. 验收案例

以下为必须实现的 20 个案例。案例内的分支是同一功能的边界验证；预期金额需在生成数据后由独立基准 SQL 计算并保存，当前不填写虚构数值。

| 编号 | 场景与输入 | 核心预期 | 关联功能 |
| --- | --- | --- | --- |
| AC-01 | 启动首页 | 无登录；标明范围、虚构数据、时间锚点；仅回环地址访问 | F-01、F-10 |
