> 依据：`README.md`（唯一规格来源）。本文件把 README 的模糊需求补全成六要素 + 可验收子任务。
> 范围：**本期只做后端**；前端后续补充（另开任务，不进本期范围）。

## 一、六要素

### 1. 业务背景
- 谁在用：市场 / 产品同学。
- 解决什么问题：做主题调研（竞品分析、行业趋势、技术选型、政策解读）时，人工搜几十个网页、整理资料、写报告，单主题耗时 2~3 小时，且容易漏信息、来源不可追溯。
- 为什么现在做：需要把「检索 → 阅读 → 迭代 → 综合」这套流程自动化，产出**带来源引用**的研究报告，让过程可追溯、结论可信度可知。

### 2. 功能范围
- **做**：
  - 输入一个研究主题，产出四类产物：结构化研究报告 / 来源列表 / 研究过程记录 / 置信度说明。
  - 核心流程是 **agentic loop**：规划（拆子问题）→ 多轮检索 → 阅读抽取 → 判断是否需要补检（不足则回到检索）→ 综合生成报告。
  - 异步执行：发起后立即返回 `research_id`，前端可轮询进度与中间结果。
  - 中间结果落盘：检索关键词、已读页面、迭代轮数、报告草稿每轮保存一次。
- **不做**（边界）：
  - 前端页面（本期不做，后续补充）。
  - 用户账号 / 权限 / 多租户。
  - 并发批量研究多个主题、定时研究。
  - 数据库持久化（用本地 JSON 文件落盘即可）。
  - 报告导出 PDF / Word、分享链接。
  - 全文抓取（`fetch_page`）：总结只基于搜索结果的摘要（snippet），不逐页抓取。

### 3. 技术栈与约束
- 语言 / 运行时：Python 3（3.11+，用到 `X | None`、`list[dict]` 等新语法）。
- Web 框架：FastAPI + uvicorn。
- 数据校验：Pydantic v2。
- Agent 框架：OpenAI Agents SDK（`openai-agents`）+ `openai`；模型走 **DeepSeek**（OpenAI 兼容接口）。
- 提示词：Jinja2 模板，**提示词与代码分离**（每个 agent 一个模板文件）。
- HTTP 客户端：httpx（调 Bocha 搜索）。
- 配置：python-dotenv，从项目根 `.env` 读密钥与参数。
- 依赖限制：不引数据库 / ORM / 消息队列；单机运行。

### 4. 输入输出
- **入参**：`POST /api/research`
  - body：`{"topic": string}`，必填，长度 1~500。
- **出参**：
  - `POST /api/research` → `202` + `{"research_id": string, "status": "pending"}`。
  - `GET /api/research/{rid}` → 完整 `ResearchRecord`：`status`（pending/running/completed/failed）+ `report`、`report_html`、`sources`、`draft`、`process`、`confidence`。
  - `GET /api/research` → 研究记录列表。
  - `GET /health` → `{"status": "ok"}`。
- **错误**：
  - `topic` 为空 → `400`。
  - `research_id` 不存在 → `404`。
  - 单次检索失败 → 不返回错误，也不中断整体流程（该关键词结果按空处理）。
  - 研究过程整体异常 → 记录 `status=failed` + `error` 字段，已写入的中间结果保留。

### 5. 限制条件
- 检索 / 判断轮数上限 `RESEARCH_MAX_ROUNDS`（默认 3）；`JudgeAgent` 判 `sufficient` 可提前结束。
- 模型输出偶发空响应（DeepSeek 200 但 content 为空）→ 自动重试 `LLM_RETRIES` 次。
- DeepSeek 不支持 SDK 结构化输出（`output_type`）→ 用提示词约束输出 JSON，代码侧解析。
- **无来源支撑的结论必须标注为「模型推断」**（`is_model_inference=true`）。
- 密钥只从 `.env` 读，禁止写死在代码里；`.env` 不提交。
- 提示词禁止内联进代码，必须放 `backend/templates/`。
- 子 agent 无工具，不直接调搜索；搜索只由编排器调用。

### 6. 验收标准（可检查）
1. `GET /health` 返回 `{"status":"ok"}`。
2. `POST /api/research` 传合法 topic → `202` + `research_id`；传空 topic → `400`。
3. 轮询 `GET /api/research/{rid}`：运行中能看到 `status=running` 且 `process`/`draft`/`sources` 有中间结果；完成后 `status=completed`。
4. 完成后 `report` 含 `title` / `summary` / `sections` / `key_conclusions` / `open_questions`。
5. `sources` 每条含 `url` / `title`；报告结论能关联到来源（可追溯）。
6. `process` 含 `plan` / `search_queries` / `reviewed_urls` / `iterations` / `steps`，且 `iterations >= 1`。
7. `confidence` 含 `overall` / `info_cutoff`；无来源结论 `is_model_inference=true`。
8. 人为让某次搜索失败 → 整体任务不 `failed`，其余关键词照常。
9. `report_html` 是一段可直接在浏览器打开的完整自包含 HTML。
10. 端到端：curl 发起 → 轮询 → 拿到完整报告 + 来源 + 过程 + 置信度。
