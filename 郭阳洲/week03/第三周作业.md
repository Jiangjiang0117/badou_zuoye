作业1：
1、 langchain 工具调用 和 llm function call 有什么区别？
LLM Function Call 是 API 层面的能力，LangChain 在它上面做了 schema 自动生成、参数解析、结果包装三层抽象，开发体验从"手写JSON"变成"装饰器+一行绑定"

2、 langchain 工具调用 的 速度是受到什么影响？
1）API请求往返次数
2）调用大模型API的网络延迟还有模型的推理耗时
3）工具函数的执行时间，如果是真实的业务场景调用外部工具会有一定的耗时

作业2：
从fastapi 接受请求到到返回结果的流程：

完整链路：请求打到 FastAPI 的某个接口，FastAPI 自动用 Pydantic校验请求格式，通过后进到对应的处理函数，函数调用对应的模型模块去推理，拿到分类结果，填进响应对象，FastAPI 序列化成 JSON 返回给客户端。

其中有四个模型：
第一个模型 regex_rule.py，最简单的正则方案。启动的时候把配置里的关键词预编译成正则对象，推理的时候用正则去文本里搜，搜到"播放""电视剧"就判为影视播放类，搜到"空调""广播"就判为家电控制类，什么都没搜到就归为其他类。

第二个模型 tfidf_ml.py，传统机器学习方案。启动时从磁盘加载训练好的 TF-IDF 向量化器和分类器。推理时先用 jieba分词，去掉停用词，空格拼成字符串，转成 TF-IDF 向量，最后送进分类器预测出类别。

第三个模型 bert.py，深度学习方案。启动时加载本地的中文 BERT 模型和 tokenizer，移到 GPU 上。推理时把文本用 tokenizer 编码成input_ids，包成 DataLoader 分 batch 送进模型，模型输出 logits，取最大的那个下标，映射到类别名。整个推理过程关掉梯度计算节省资源。

第四个模型 prompt.py，大模型方案，最复杂。启动时加载训练数据集和 TF-IDF 向量化器。推理时先对输入做 TF-IDF向量化，然后算它跟训练集中每条数据的相似度，取出最相似的十条作为参考例子。接着把待分类文本、这十条参考例子、候选类别列表一起拼进一个提示词模板里，告诉大模型"你是意图识别专家，请从候选类别里选一个"。
最后调用通义千问的 API，超参 temperature设成零确保结果稳定，拿到返回的类别名。本质上就是用 TF-IDF 做相似度检索，然后动态拼 Few-shot 提示词，让大模型照着例子投票。
