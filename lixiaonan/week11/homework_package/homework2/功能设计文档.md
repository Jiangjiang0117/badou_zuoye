## 1. 术语定义

| 术语 | 定义 |
|---|---|
| MQL | Metric Query Language，语义查询：`{指标, 维度[], 过滤[], 时间, 排序, Limit}` 的结构化查询描述 |
| 槽位 | 从用户问题中提取的关键要素：指标 / 维度 / 时间 / 过滤值 / 排序 / TopN |
| 澄清 | 系统检测到歧义时向用户反问，并提供可点选候选项 |
| EX | 执行准确率：生成 SQL 的执行结果与标准答案一致 |
| badcase | 回答错误或体验不佳的问答记录，用于迭代改进 |
| 语义命中 | 用户问题成功匹配到语义层中已定义的指标/维度 |

## 3. 核心业务流程设计

### 3.1 主流程（含状态流转）

```
[S0 接收提问]
    │
    ▼
[S1 改写] Rewrite Agent：合并历史上下文 → 独立完整问题
    │
    ▼
[S2 澄清检查] Clarify Agent：歧义检测
    │
    ├─ 检出歧义 ──► [S2a 反问] 输出澄清问题+候选项 ──► 等待用户选择 ─┐
    │                                                                │
    ▼ 否                                                             │
[S3 语义检索] Semantic Agent：问题 → MQL                              │
    │                                                                │
    ├─ 语义未命中 ──► [S3a 兜底] 裸 NL2SQL（标记 low-confidence）       │
    ▼                                                                │
[S4 SQL 生成] MQL → SQL                                              │
    │                                                                │
    ▼                                                                │
[S5 鉴权] 指标白名单校验 ──失败──► [S9 拒绝] 权限提示                  │
    │通过                                                             │
    ▼                                                                │
[S6 校验执行] Validate Agent：语法/试运行/合理性                       │
    │                                                                │
    ├─ 失败 ──► 修正循环（SQL Agent↔Validate，≤2轮）──仍失败──► [S9b]  │
    ▼通过                                                             │
[S7 执行查询] ──► 结果集                                              │
    │                                                                │
    ▼                                                                │
[S8 汇总输出] Report Agent：解读+图表推荐+SQL+口径                     │
    │                                                                │
    ├─ 归因类问题 ──► [S8a 归因] Analyze Agent ──► 合并输出            │
    ▼                                                                │
[S10 反馈收集] ──► badcase 回流 ◄─────────────────────────────────────┘
```

### 3.2 各状态处理规则

| 状态 | 成功出口 | 异常出口 |
|---|---|---|
| S1 改写 | 首轮问题原样通过 | LLM 异常 → 用原始问题继续（降级 F6.2） |
| S2 澄清 | 无歧义 → S3；用户已选 → 合并答案回 S3 | 反问超过 2 次仍无法确定 → 采用默认值并声明假设 |
| S3 语义检索 | 命中 → S4 | 未命中 → S3a 兜底；兜底置信度低 → 转 S2 反问 |
| S5 鉴权 | 通过 → S6 | 拒绝 → S9，输出无权访问话术 |
| S6 校验 | 通过 → S7 | 2 轮修正仍失败 → S9b（见 §10） |
| S7 执行 | 结果集 → S8 | 超时/行数超限 → 截断并声明 |
| S8 汇总 | 输出 → S10 | 归因数据不足 → 仅输出对比结果，注明无法归因 |

## 4. Agent 功能规格

> 统一规格模板：功能描述 / 触发条件 / 输入 / 处理规则 / 输出 / 异常处理。行业依据以【】标注。

### 4.0 Orchestrator（编排器）【腾讯：DFSDT 强流程】

- **功能描述**：按固定顺序调度 S0–S10；管理澄清等待、修正循环、超时与全链路日志。
- **处理规则**：
  1. 主链路固定编排，不允许 LLM 自由决定跳步；
  2. 仅 S6 校验失败允许进入 ReAct 修正循环（SQL Agent ↔ Validate Agent），**上限 2 轮**；
  3. 澄清等待期间保持会话状态，用户答复后从 S3 恢复；
  4. 每个 Agent 的输入输出全量落日志（供评估与排障）。
- **异常处理**：任一 Agent 超时（>60s）→ 终止本次问答，输出降级提示。

### 4.1 Rewrite Agent（问题改写）【去哪儿：改写 Agent】

- **功能描述**：将多轮对话中的口语化、省略、指代性问题改写为**语义独立完整**的问题。
- **输入**：最近 N 轮对话（N=3）+ 当前问题。
- **处理规则**：
  1. 指代消解："它/他们/那个" → 上一轮实体（"加拿大呢？" → "加拿大的销售额是多少？"）；
  2. 省略补全：继承上一轮的时间/维度/指标槽位（"那按流派拆一下呢？" → 继承"上个月、销售额"）；
  3. 术语展开：命中术语库的黑话替换为标准表述（详见 §5.2）；
  4. 无法确定指代对象时 → 移交 Clarify Agent 反问，不猜。
- **输出**：改写后的完整问题 + 槽位继承说明（写入思考链展示）。

### 4.2 Clarify Agent（歧义澄清）【去哪儿"积分第二名"案例；Aloudata 反问澄清】

- **功能描述**：在语义检索前拦截歧义问题，反问并给出**可点选候选项**。
- **澄清策略矩阵**（核心规则）：

| 歧义类型 | 检测规则 | 反问策略 | 候选项来源 | 兜底 |
|---|---|---|---|---|
| 指标口径歧义 | "好/多/高/效果"等模糊形容词且可映射 ≥2 个指标 | "您想看哪个口径？" | 语义层候选指标列表 | 无兜底，必须澄清 |
| 实体歧义 | 问题实体匹配到多个维度值（如同名歌手） | "您指的是哪一个？" | 维度值模糊匹配结果 Top3 | 无兜底 |
| 时间模糊 | "最近/前段时间/今年以来"无法解析为明确区间 | "您指的时间范围是？" | 最近7天/30天/90天/今年 | 用户跳过 → 默认最近30天并声明 |
| 排序歧义 | "第二名/最好的"未说明方向或范围 | "第二名指排名正数第2，还是其他？" | 正数第2/倒数第2/第2-3名 | 用户跳过 → 按正数第2 |
| 槽位缺失 | 指标可确定但缺维度或时间 | 一次性列出缺失槽位选项 | 常用维度/默认时间 | 时间 → 默认最近12个月 |

- **处理规则**：
  1. 反问必须带候选项（按钮式），禁止开放式提问；候选项 ≤ 4 个；
  2. 单次问答最多反问 **2 轮**，第 3 次歧义采用兜底默认值并在回答中声明"已按 XX 假设回答"；
  3. 用户自由文本答复视同选择，回到本 Agent 再校验一次；
  4. 低置信度兜底 NL2SQL（S3a）的问题必须先经本 Agent 反问确认。
- **输出**：澄清问题 JSON（问题文本 + 候选项列表 + 兜底值）。

### 4.3 Semantic Agent（语义检索与 MQL 生成）【Aloudata：语义编译器；数势：Semantic API】

- **功能描述**：把自然语言问题"编译"为 MQL——**选指标、填条件**，而非生成 SQL。
- **输入**：改写后问题 + 语义层（指标模型/维度/术语/默认条件）。
- **处理规则**：
  1. 实体识别：从问题中抽取指标候选、维度候选、时间表达、过滤值；
  2. 指标匹配：问题表述 → 指标（含同义词、派生规则匹配，如"月环比" → 派生指标 `销售额_环比`）；
  3. 时间解析：时间表达 → 明确区间（规则 Parser 优先，复杂表达交 LLM，LLM 结果回规则校验）【数势难点4：Parser + 模型 + 校验】；
  4. 默认条件注入：时间未指定 → 按默认条件配置补齐；
  5. 校验输出：MQL 中指标/维度/过滤值必须**全部存在于语义层**，不存在的值转 Clarify Agent（防幻觉）。
- **输出**：MQL JSON `{metrics:[], dimensions:[], filters:[], time:{}, order_by, limit}` + 命中置信度。

### 4.4 SQL Agent（SQL 生成）【Aloudata：语义层内 SQL 可靠生成；数势：NL2SQL 路径最短】

- **功能描述**：双轨生成——语义轨（MQL → SQL，主）与兜底轨（问题 → SQL，辅）。
- **处理规则**：
  1. **语义轨**：按 MQL 套用查询模板（选列/聚合/过滤/分组/排序/limit 由 MQL 机械映射），禁止自由发挥；仅 Join 关系由语义层的表关联配置提供；
  2. **兜底轨**（语义未命中时）：输入 = 问题 + 相关表结构（经检索瘦身）+ Few-shot 示例；输出 SQL 必须通过 Validate 三级校验，且标记 `low-confidence`；
  3. 只读约束：仅允许 SELECT；禁用词（INSERT/UPDATE/DELETE/DROP/ALTER/PRAGMA 等）硬拦截；
  4. 行数保护：无聚合的明细查询强制附加 LIMIT（默认 1000）。
- **输出**：SQL + 生成轨标记（semantic/fallback）+ 引用的语义层口径说明。

### 4.5 Validate Agent（三级校验）【腾讯：SQL 校验闭环；平安：兜底策略】

- **功能描述**：SQL 放行前的三道闸门，失败时产出**修正建议**驱动 ReAct 循环。

| 级别 | 校验内容 | 通过标准 | 失败动作 |
|---|---|---|---|
| L1 语法 | SQL 可解析、只读、无禁用词 | 解析通过 | 返回语法错误位置 → SQL Agent 修正 |
| L2 试运行 | EXPLAIN 执行计划、实际执行（LIMIT 1） | 无异常 | 返回数据库报错 → 修正循环 |
| L3 合理性 | 结果类型合理（如时间区间非空、指标非全 NULL）、行数 ≤ 上限 | 合理 | 标记警告；连续异常 → 转澄清 |

- **输出**：校验结论 + 错误详情 + 自然语言修正建议（供 SQL Agent 使用，也供思考链展示）。

### 4.6 Report Agent（汇总解读与图表推荐）【平安：数据结论组装；去哪儿：展示思考过程】

- **功能描述**：将结果集翻译为用户可读的回答，并推荐合适图表。
- **输出结构（固定六段）**：
  1. **结论**：1–2 句直接回答（含关键数字）；
  2. **数据表格**：结果集（超 10 行折叠）；
  3. **图表**：按 §4.6.1 规则推荐；
  4. **SQL**：可展开/可复制；
  5. **口径说明**：本次查询使用的指标定义与过滤条件（含兜底假设声明）；
  6. **推荐追问**：≤3 个（如"要不要按流派拆分？""看看前 5 名？"）。
- **处理规则**：数字必须来自结果集原文，禁止计算性外推（差值/占比可计算，但需标注"由结果计算"）；结果为空时输出"未查到数据"+ 可能原因提示（时间范围/过滤条件过严）。

#### 4.6.1 图表推荐规则【平安：智能推荐柱状图、折线图等】

| 结果形态 | 判定条件 | 推荐图表 |
|---|---|---|
| 单值 | 1 行 1 列聚合值 | 指标卡 |
| 时间趋势 | 维度含时间且 ≥ 3 个连续期 | 折线图 |
| 分类排名 | 分类维度 + 排序/TopN | 柱状图（横向，TopN ≤ 10） |
| 占比构成 | 问法含占比/份额，且类别 ≤ 6 | 饼图/环形图；>6 类 → 柱状图 |
| 两期对比 | 含同比/环比 | 分组柱状图 + 差值标注 |
| 明细列表 | 无聚合 | 表格（分页） |
| 双指标 | 2 个量纲不同的指标 | 双轴图 |

用户可手动切换图表类型（可干预原则）。

### 4.7 Analyze Agent（归因分析，P1）【Aloudata：时间对比+维度归因；数势：异动分析】

- **功能描述**：对"为什么涨/跌"类问题，执行两期对比 + 维度拆分归因。
- **触发条件**：问法命中归因模式（为什么/为何/下降/上涨的原因 + 可对比的两期）。
- **处理流程**：
  1. 解析目标期与对比期（"本月 vs 上月"；未明确 → 默认最近完整月 vs 上一月，并声明）；
  2. 分别查询两期指标总量，计算差值与变化率；
  3. **维度贡献拆分**：按候选维度（国家/流派/艺人，取语义层配置）分别拆分两期明细，计算各维度值对总差值的贡献额并排序；
  4. 归因结论：取贡献绝对值 Top3 生成结论（模板："下降 X 元，其中 YY 贡献了 Z%（主因）"）；
  5. 数据不足（如某一期无数据）→ 明确说明无法归因，仅输出对比结果。
- **输出**：归因结论 + 贡献表 + 归因用拆分 SQL（透明可追溯）。

## 5. 知识与语义层功能设计

### 5.1 指标语义模型功能【Aloudata：1 个原子指标派生大量场景】

- **指标分类与问法支持**：

| 指标类型 | chinook 示例 | 支持的派生问法 |
|---|---|---|
| 原子指标 | 销售额（invoice 总额求和）、订单量（invoice 计数）、客户数（customer 计数去重）、销量（invoice_items 数量求和） | 指定时间/维度/过滤组合查询 |
| 派生指标 | 客单价=销售额/订单量、环比/同比/累计值、TopN | "本月日均销售额""销售额月同比" |
| 复合指标 | 购买转化相关组合指标 | 组合条件查询 |

- **功能规则**：
  1. 指标定义包含：名称、同义词、计算口径、可用维度、默认时间粒度——所有问数**必须**经指标定义（零裸口径）；
  2. 同一指标在不同时间粒度下自动切换聚合方式（日/月/年）；
  3. 指标不可用维度组合（如"客户数按专辑"无意义）→ 提示不支持并给出近似建议。

### 5.2 术语库功能【去哪儿：行业黑话术语库】

- **功能**：黑话/缩写/口语 → 标准语义层表述的映射；Rewrite Agent 改写时应用。
- **chinook 场景示例**："爆款" → 销量 Top10 且高于均值；"老客户" → 首单时间早于 12 个月前的客户；"重购买家" → 订单数 ≥2 的客户。
- **规则**：术语映射结果在口径说明中展示，让用户知道黑话被如何理解。

### 5.3 Few-shot 示例库功能【去哪儿：知识库 V3 SQL 模板】

- **功能**：按问题类型（时间/聚合/多表/排序/歧义）组织"问题 ↔ MQL ↔ SQL"标准示例；Semantic/SQL Agent 检索 Top-k 相似示例注入上下文。
- **规则**：示例库可配置化维护；badcase 修正后可提炼为新示例（与 F5.3 联动）。

### 5.4 默认条件功能【去哪儿：表的默认补充条件】

- **功能**：配置化默认规则，降低澄清频率：
  1. 时间未指定 → 指标默认时间范围（如销售额默认最近 12 个月）；
  2. 时间粒度未指定 → 按跨度自动选择（≤60天按日、≤3年按月、更长按年）；
  3. 排序未指定 → 聚合类默认按指标降序。
- **规则**：凡使用默认值的回答，必须在口径说明中声明"未指定 X，已默认 Y"。

## 6. 对话交互功能设计

### 6.1 多轮对话管理【Aloudata：多轮连续分析】

| 功能 | 规则 |
|---|---|
| 上下文窗口 | 保留最近 3 轮有效问答（澄清轮不计入） |
| 槽位继承 | 下一轮未指定的时间/维度/过滤继承上一轮 |
| 指代消解 | 见 4.1；无法消解 → 反问 |
| 会话重置 | 用户说"重新开始/换个问题" → 清空槽位继承 |
| 中断澄清 | 澄清等待中用户提出全新问题 → 判断为新话题则丢弃旧澄清 |

### 6.2 回答呈现规范

见 §4.6 六段结构。附加规则：
- 思考链默认折叠，一键展开（改写结果/命中指标/生成轨标记/校验轮次）；
- `low-confidence`（兜底轨）回答顶部显示提示条："本回答由模型直接生成 SQL，请核对口径"；
- 权限拒绝不显示 SQL；错误信息面向用户友好化，技术细节进日志。

### 6.3 可干预操作（Human in the Loop）【Aloudata：查询结果可调】

| 操作 | 行为 |
|---|---|
| 修改时间 | 点击时间胶囊 → 选新区间 → 重跑 S4 起流程 |
| 增删维度 | 点击"加个拆分维度" → 候选维度列表（来自指标可用维度） |
| 修改过滤值 | 点击过滤条件 → 重新选择 |
| 切换图表 | 图表类型切换（不重新查数，仅换渲染） |
| 查看 SQL | 展开 SQL 面板，可复制 |

### 6.4 反馈功能【平安：点踩点赞；去哪儿：运营机制】

- 点赞/点踩/错误类型选择（数值错误/口径错误/图表不当/答非所问）+ 可选文字说明；
- 点踩记录自动进入 badcase 池（F5.3），标注问题类型与所在里程碑版本。

### 6.5 端到端示例对话

**示例 1：普通问数 + 排名**

> **用户**：上个月哪个国家的销售额最高？
> **系统**（S1 改写：时间"上个月" → 2026-09-01~09-30）→（S3 MQL：指标=销售额，维度=国家，排序 desc limit 1）→（S6 校验通过）
> **回答**：结论"2026 年 9 月销售额最高的国家是 **美国，$XX**"；柱状图 Top10；SQL 面板；口径说明；推荐追问"要不要看前 5 名？"。

**示例 2：歧义澄清**

> **用户**：帮我看看最近卖得好的音乐。
> **系统**（S2 检出：指标口径歧义 + 时间模糊）
> **反问**："您想按哪个口径衡量'卖得好'？" [按销量（张数）] [按销售额（金额）]；"时间范围是？" [最近7天] [最近30天] [最近90天]
> **用户**：选"按销量"+"最近30天"
> **回答**：Top5 流派销量柱状图 + 口径声明（含默认排序说明）。

**示例 3：归因分析（P1）**

> **用户**：为什么 9 月销售额比 8 月下降了？
> **系统**（Analyze Agent：9 月 $A vs 8 月 $B，差 -$C）→ 按国家拆分 → 按流派拆分
> **回答**："9 月较 8 月下降 $C（-x%）。主要原因是**加拿大销售额减少 $D（占总降幅 y%）**，其次是摇滚流派销量下滑（贡献 z%）。" + 贡献表 + 拆分 SQL。

**示例 4：多轮指代**

> **用户**：上个月各国家订单量？→ **系统**：表格+地图友好的柱状图
> **用户**：那客单价呢？
> **系统**（S1 继承：时间=上月、维度=国家；指标替换为客单价）→ 输出，口径说明注明继承关系。

## 10. 异常与降级设计

| 错误码 | 场景 | 系统行为 | 用户提示 |
|---|---|---|---|
| E01 | LLM 调用超时/异常（改写/澄清外环节） | 跳过该 Agent 以规则降级或终止 | "服务暂时不可用，请稍后重试" |
| E02 | SQL 校验 2 轮修正后仍失败 | 终止，不输出任何数据 | "未能生成可靠查询，请换个问法，或说明您要的指标和时间" |
| E03 | 权限拒绝 | 终止，不生成 SQL | 权限申请指引（§7） |
| E04 | 查询超时/行数超限 | 截断或终止 | "结果过大，已展示前 1000 行，建议增加过滤条件" |
| E05 | 空结果 | 正常输出空态 | "未查到数据"+ 原因建议（时间范围/过滤过严） |
| E06 | 反问 2 轮仍有歧义 | 采用兜底默认值 | "已按 XX 假设回答，可点击修改" |
| E07 | 归因数据不足 | 降级为对比输出 | "数据不足以完成归因，仅展示对比结果" |

**通用原则**：任何异常路径都**不得输出未校验的数据**（宁可不答，不可错答）。
