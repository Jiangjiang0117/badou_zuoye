## 1. 技术选型

| 层面 | 选型 | 理由 |
|---|---|---|
| 语言/运行时 | Python 3.12 | 与 homework1 一致；生态齐全 |
| LLM 接入 | OpenAI Agents SDK（`Agent/Runner/ModelSettings`）+ DashScope compatible-mode | homework1 已验证可用；SDK 自带 trace、handoff 扩展位 |
| 模型 | 主推理 `qwen3.8-flash`（可配置，见 §12.4） | 成本/速度平衡；兜底轨可切更强模型（行业经验：可行性验证用最好的模型） |
| 数据库 | SQLite（chinook.db），**只读连接** | 单文件零部署；`mode=ro` 从连接层杜绝写操作 |
| SQL 解析 | `sqlglot`（L1 语法校验/方言检查） | 纯 Python、支持方言；比正则可靠 |
| 结构化输出 | `pydantic` v2 | MQL/Agent 输出强校验 + 失败重试 |
| 语义层存储 | YAML 配置文件（metrics/dimensions/terms/fewshots/defaults/permissions） | 知识配置化，改知识不改代码（NF-可维护） |
| 交互层 | M1–M2 CLI；M3 起 Streamlit（可选） | 最小可用优先，Web 展示思考链/图表 |
| 图表 | Streamlit 内置 + Plotly（可选） | 六段式回答中的图表段 |
| 评估 | 自研脚本（JSONL 驱动） | EX 分层统计，版本留存 |

**不引入**：向量库（语义层为小规模结构化配置，规则检索足够；预留 embedding 扩展位）、OLAP 引擎（chinook 量级不需要）。

## 3. 语义层 Schema 设计

> 全部为 YAML 配置；`loader.py` 启动时加载并建立倒排索引（同义词 → 指标/维度）。**MQL 中出现的指标/维度/过滤值必须能在本 Schema 中解析，否则视为语义未命中**（功能 §4.3 规则 5，防幻觉的落地点）。

### 3.1 指标定义（config/metrics.yaml）

```yaml
metrics:
  - name: revenue                 # 内部名（MQL 引用名）
    display_name: 销售额
    synonyms: [收入, 营业额, 销售金额, sales, 业绩]   # 检索匹配用
    type: atomic                  # atomic | derived | composite
    expr: "SUM(invoices.Total)"   # 原子指标：物理口径（零裸口径的落地）
    time_field: invoices.InvoiceDate
    allowed_dimensions: [country, city, genre, artist, album, time]
    forbidden_dimensions: []      # 显式禁用组合优先于白名单
    default_time_range: last_12_months   # 时间未指定时注入
    unit: currency

  - name: orders
    display_name: 订单量
    synonyms: [订单数, 发票数, 订单量]
    type: atomic
    expr: "COUNT(DISTINCT invoices.InvoiceId)"
    time_field: invoices.InvoiceDate
    allowed_dimensions: [country, city, genre, artist, time]
    default_time_range: last_12_months

  - name: buyers
    display_name: 客户数
    synonyms: [客户数, 买家数, 购买人数]
    type: atomic
    expr: "COUNT(DISTINCT invoices.CustomerId)"
    allowed_dimensions: [country, city, time]   # 客户数按专辑无意义 → 不可用
    default_time_range: last_12_months

  - name: qty_sold
    display_name: 销量
    synonyms: [销量, 卖出数量, 张数]
    type: atomic
    expr: "SUM(invoice_items.Quantity)"
    time_field: invoices.InvoiceDate
    allowed_dimensions: [genre, artist, album, media_type, country, time]
    default_time_range: last_12_months

  - name: avg_order_value
    display_name: 客单价
    synonyms: [平均订单金额, 单均金额]
    type: derived                 # 派生指标：引用其他指标
    expr: "revenue / orders"      # 由 mql2sql 展开为 SUM/COUNT
    allowed_dimensions: [country, city, genre, time]
    default_time_range: last_12_months
```

### 3.2 维度与关联路径（config/dimensions.yaml）

```yaml
dimensions:

    synonyms: [歌手, 艺术家, 乐队]
    field: artists.Name
    join_path:
      - invoices.InvoiceId = invoice_items.InvoiceId
      - invoice_items.TrackId = tracks.TrackId
      - tracks.AlbumId = albums.AlbumId
      - albums.ArtistId = artists.ArtistId

  - name: time
    display_name: 时间
    field: invoices.InvoiceDate
    granularities: {day: "date(InvoiceDate)", month: "strftime('%Y-%m', InvoiceDate)", year: "strftime('%Y', InvoiceDate)"}
```

## 4. 数据契约：Agent 通信协议

> 功能 NF-可扩展要求"Agent 间以标准消息结构通信"。所有 Agent 输入输出均为 pydantic 模型，编排器只传协议对象，不传裸字符串。

### 4.1 统一消息与会话上下文（chatbi/context.py）

```python
class Status(str, Enum):
    OK = "ok"; CLARIFY = "clarify"; FALLBACK = "fallback"
    REJECT = "reject"; FAIL = "fail"

class ErrorInfo(BaseModel):
    code: Literal["E01","E02","E03","E04","E05","E06","E07"]   # 功能 §10 错误码
    message: str          # 用户可读
    detail: str = ""      # 技术细节，仅入日志

class AgentMessage(BaseModel):
    trace_id: str                     # 一次问答全程唯一
    stage: Literal["S1","S2","S3","S4","S5","S6","S7","S8","S8a","S9"]
    agent: str                        # rewrite / clarify / semantic / sql / validate / report / analyze
    status: Status
    data: dict                        # 各 Agent 负载（§4.2–4.4）
    error: ErrorInfo | None = None
    latency_ms: int

class SessionContext(BaseModel):
    session_id: str
    history: list[QAItem] = []        # 最近 3 轮有效问答（澄清轮不计入，功能 §6.1）
    pending_clarify: ClarifyPayload | None = None   # 澄清等待状态（恢复点）
    inherit_slots: dict = {}          # 槽位继承：{time, dimensions, filters, metric}
    low_confidence: bool = False      # 兜底轨标记 → 回答顶部提示条
```

### 4.2 MQL JSON Schema（Semantic Agent 输出 / SQL Agent 输入）

```json
{
  "metrics":   [{"name": "revenue", "alias": "销售额"}],
  "dimensions": ["country", "time"],
  "filters":   [{"dimension": "genre", "op": "in", "values": ["Rock"]}],
  "time":      {"start": "2026-09-01", "end": "2026-10-01",
                "granularity": "month", "resolved_from": "上个月", "is_default": false},
  "order_by":  {"metric": "revenue", "direction": "desc"},
  "limit":     1,
  "compare":   null,
  "confidence": 0.95
}
```

校验规则（pydantic + retriever 联查）：`metrics[].name / dimensions[] / filters[].dimension` 必须存在于语义层；`op ∈ {in, not_in, eq, like, gt, lt, between}`；`compare` 为 `{type: mom|yoy, base_start, base_end}`（归因/同比环比用）。

### 4.3 各 Agent 输出负载

| Agent | `data` 负载 schema |
|---|---|
| Rewrite | `{rewritten: str, inherited: [{slot, from}], term_hits: [str]}` |
| Clarify | `{question: str, options: [str] ≤4, fallback: str?, scope: 歧义类型}` |
| Semantic | `{mql: MQL, hit: bool, matched: {metric_synonym, dimension_synonyms}}` |
| SQL | `{sql: str, track: "semantic"\|"fallback", semantics_note: 口径说明文本}` |
| Validate | `{passed: bool, level: "L1"\|"L2"\|"L3", error: str?, fix_hint: str?}` |
| Report | `{conclusion: str, table: rows, chart: {type, x, y}, sql, caliber: str, followups: [str] ≤3}` |
| Analyze | `{target: {start,end,total}, base: {...}, delta, contributions: [{dim_value, delta, share}], sql_list, insufficient: bool}` |

### 4.4 传递与持久化

- AgentMessage 由编排器追加到 `logs/{trace_id}.json`（全链路留痕，功能 §7/S10）；
- 澄清交互：`status=CLARIFY` 时编排器挂起，将 `pending_clarify` 存入 SessionContext；用户答复 → 合并进上下文 → **从 S3 重新进入**（不重跑 S1）。

## 5. 编排器实现设计（chatbi/orchestrator.py）

```python
class Orchestrator:
    HANDLERS = {                       # 固定编排表：状态 → 处理函数（Workflow 式，腾讯 DFSDT 结论）
        "S1": rewrite_agent.run,  "S2": clarify_agent.run,
        "S3": semantic_agent.run, "S4": sql_agent.run,
        "S5": perm.check,         "S6": validate_agent.run,
        "S7": executor.run,       "S8": report_agent.run,
        "S8a": analyze_agent.run,
    }

    async def ask(self, question: str, ctx: SessionContext) -> Answer:
        ctx.assert_no_pending_or_conflict(question)          # §6.1 中断澄清规则
        msg = await self.step("S1", ctx, question)
        msg = await self.step("S2", ctx, msg)                # CLARIFY → 挂起返回
        if msg.status is Status.CLARIFY:
            ctx.pending_clarify = msg; return Answer.of(msg)
        msg = await self.step("S3", ctx, msg)
        if not msg.data["mql"]["hit"] and msg.data["mql"]["confidence"] < 0.6:
            return await self.ask_fallback_confirm(ctx, msg) # 低置信兜底 → 先反问（功能 §4.2 规则4）
        for attempt in range(3):                             # S4–S6：1 次生成 + 2 轮修正（硬上限）
            msg = await self.step("S4", ctx, msg)
            msg = await self.step("S5", ctx, msg)            # REJECT → 直接终止
            if msg.status is Status.REJECT: return Answer.of(msg)
            msg = await self.step("S6", ctx, msg)
            if msg.data["validate"]["passed"]: break
            msg.inject_fix_hint(msg.data["validate"]["fix_hint"])   # ReAct：观察→修正
        else:
            return Answer.error("E02")                       # 宁可不答，不可错答
        rows = await self.step("S7", ctx, msg)
        answer = await self.step("S8", ctx, rows)
        if is_attribution(question):                         # 归因模式命中（功能 §4.7）
            answer.merge(await self.step("S8a", ctx, msg))
        self.persist_trace(ctx); return answer
```

**实现要点**：
1. 状态机为**显式固定表**，LLM 不参与流程决策（对应项目文档关键取舍 3）；
2. 修正循环即 ReAct 最小闭环：`fix_hint` 由 Validate Agent 生成（含 sqlglot 报错位置/数据库报错原文），注入下一轮 SQL Agent Prompt；
3. 每个 `step()` 计时并产出 AgentMessage，异常捕获统一映射错误码 E01；
4. `persist_trace` 落 `logs/`，字段与 §4.1 协议一致，供评估与 badcase 回流。

## 6. 关键模块实现设计

### 6.1 时间解析器（semantic/time_parser.py）【数势难点4：规则抽取 + 模型抽取 + 校验】

```
输入时间文本 ──► 规则 Parser（正则模板表，优先）
                  │命中 → 产出 {start, end, granularity}，直接返回
                  ▼未命中
               LLM 解析（输出 JSON {start,end,granularity}）
                  ▼
               规则校验（格式合法、start<end、end≤今天、跨度≤10年）
                  │通过 → 返回    │失败 → 视为时间模糊 → Clarify Agent
```

规则模板表（内置，可配置扩展）：`上个月`、`最近N天/周/月`、`今年/去年/去年全年`、`YYYY年Q季度`、`YYYY-MM`、`今年以来`、`最近一个月`。所有区间为**左闭右开** `[start, end)`，与 SQL 生成约定一致（消除边界歧义）。

### 6.2 MQL → SQL 确定性生成器（sqlgen/mql2sql.py）

映射规则（纯代码，无 LLM——语义轨可靠性的核心）：

| MQL 要素 | SQL 片段 |
|---|---|
| metrics[].expr | SELECT 聚合列；derived 指标先展开（`revenue/orders` → `SUM(...)/COUNT(...)`） |
| dimensions[] | GROUP BY 列 + SELECT 别名（display_name）；`time` 按 granularity 取 `strftime` 模板 |
| filters | WHERE 条件（值来自语义层已校验的维度值） |
| time | WHERE `time_field >= 'start' AND time_field < 'end'`（左闭右开） |
| join_path | 按 dimensions 的路径**去重合并**生成 JOIN 链 |
| order_by / limit | ORDER BY / LIMIT |

生成示例（"上个月哪个国家的销售额最高？"）：

```sql
SELECT cu.Country AS 国家, SUM(i.Total) AS 销售额
FROM invoices i
JOIN customers cu ON cu.CustomerId = i.CustomerId
WHERE i.InvoiceDate >= '2026-09-01' AND i.InvoiceDate < '2026-10-01'
GROUP BY cu.Country
ORDER BY 销售额 DESC
LIMIT 1;
```

### 6.3 兜底 NL2SQL（sql_agent.py fallback 轨）

- **Schema 瘦身**【去哪儿知识库 V2"瘦身"】：按问题关键词对 11 张表打分，仅注入 Top-3 相关表的 DDL + 3 行样例（复用 homework1 `DBParser.get_table_sample`）；
- Few-shot：从 `fewshots.yaml` 按标签/关键词取 Top-3 完整"问题↔MQL↔SQL"示例注入；
- 约束注入：Prompt 明示"只允许 SELECT、必须含 LIMIT"；生成后经 `guard.py` 硬校验；
- 产物标记 `track=fallback`，SessionContext 置 `low_confidence=True`。

### 6.4 三级校验与守卫（agents_impl/validate_agent.py + sqlgen/guard.py）

| 级别 | 实现 |
|---|---|
| L1 语法 | `sqlglot.parse(sql, dialect="sqlite")`：解析失败 → 返回错误位置；多语句（`;` 分割 >1）→ 拒绝；AST 根节点非 `Select` → 拒绝 |
| L1 只读 | 禁用词正则 `\b(INSERT|UPDATE|DELETE|DROP|ALTER|CREATE|ATTACH|DETACH|PRAGMA|VACUUM|REINDEX)\b`（忽略大小写）+ 双保险：连接本身 `mode=ro` |
| L2 试运行 | `EXPLAIN QUERY PLAN` 无异常 → `LIMIT 1` 试执行真实跑通 → 捕获 SQLite 报错作为 `fix_hint` 原文 |
| L3 合理性 | 行数 ≤ `settings.max_rows`（默认 1000，超限注入 LIMIT 并声明）；时间区间非空；聚合指标全 NULL → 警告标记 |

### 6.5 权限拦截（perm.py）【平安：指标+用户权限；代码强制】

```yaml
# permissions.yaml
demo_user: {allowed_metrics: [revenue, orders, qty_sold, avg_order_value], denied_metrics: []}
```

- 拦截点 1：S5——MQL 中的指标逐一比对白名单；
- 拦截点 2：兜底轨执行前——对最终 SQL 做 `sqlglot` 列引用分析，引用了禁用指标对应物理列 → 拦截（功能 §7"兜底轨限制"）；
- 拒绝输出 E03 话术，不返回 SQL 与口径。

### 6.6 图表推荐规则引擎（charts.py）——功能 §4.6.1 规则表代码化

```python
def recommend_chart(mql: MQL, rows: list[Row]) -> ChartSpec:
    if len(rows) == 1 and len(rows[0]) == 1:        return ChartSpec("kpi")
    if has_time_dim(mql) and len(rows) >= 3:        return ChartSpec("line")
    if mql.is_ratio() and len(rows) <= 6:           return ChartSpec("pie")
    if mql.compare:                                 return ChartSpec("grouped_bar")
    if mql.order_by and len(rows) <= 10:            return ChartSpec("hbar")
    if len(mql.metrics) == 2:                       return ChartSpec("dual_axis")
    return ChartSpec("table")
```

### 6.7 归因实现（agents_impl/analyze_agent.py，P1）

1. `compare` 解析两期 → 复用 MQL 查询两次总量（target/base）；
2. 贡献拆分 = 对每个候选维度执行：

```sql
-- 以国家维度为例：各维度值对总差值的贡献
SELECT cu.Country AS 维度值,
       SUM(CASE WHEN i.InvoiceDate >= :t_start AND i.InvoiceDate < :t_end  THEN i.Total ELSE 0 END)
     - SUM(CASE WHEN i.InvoiceDate >= :b_start AND i.InvoiceDate < :b_end THEN i.Total ELSE 0 END) AS 贡献额
FROM invoices i JOIN customers cu ON cu.CustomerId = i.CustomerId
WHERE i.InvoiceDate >= :b_start AND i.InvoiceDate < :t_end
GROUP BY cu.Country ORDER BY ABS(贡献额) DESC LIMIT 10;
```

3. `share = 贡献额 / 总差值`，取绝对值 Top3 套用结论模板；`insufficient=True` 时输出 E07 降级。

## 7. Prompt 设计

### 7.1 统一规范

- 结构：`角色 → 上下文（语义层摘要/示例）→ 任务 → 硬约束 → 输出格式（JSON Schema 内联）`；
- 温度：生成类 0.1–0.3（沿用 homework1 实践）；解读类 0.3；
- **结构化输出**：要求 JSON 的 Agent 一律 pydantic 校验，失败将校验错误回填重试，**最多 2 次**，仍失败走降级（E01/E06）；
- 所有 Prompt 模板存放于各 `agents_impl/*.py` 模块常量（与 homework1 `instructions` 风格一致）。

### 7.2 关键模板

**Semantic Agent（语义编译，全系统最关键的 Prompt）**

```
你是 BI 语义编译器。只允许使用下方"语义层"中存在的指标与维度，禁止编造。
【语义层】指标：{metrics 摘要（名称/同义词/口径/可用维度）}
         维度：{dimensions 摘要（名称/同义词/关联路径）}
【任务】将用户问题编译为 MQL JSON：
{metrics:[{name,alias}], dimensions:[], filters:[{dimension,op,values}],
 time:{start,end,granularity,resolved_from,is_default}, order_by, limit, confidence}
【硬约束】
1. 指标/维度名必须逐字来自语义层；
2. 时间已由系统解析为 {resolved_time}，直接填入，不要改动；
3. 无法确定的要素置空并在 confidence 中反映（<0.6 视为未命中）；
4. 只输出 JSON。
【用户问题】{rewritten_question}
```

**Clarify Agent**

```
你是 BI 助手的澄清器。判断问题是否存在歧义，歧义类型限于：
metric_ambiguous / entity_ambiguous / time_fuzzy / rank_ambiguous / slot_missing。
存在歧义：输出 {"clarify": true, "question": "...", "options": ["..."] (≤4), "fallback": "..."|null}
无歧义：输出 {"clarify": false}
规则：必须给候选项，禁止开放式提问；只输出 JSON。
【候选素材】指标列表：{metrics}；维度值匹配结果：{entity_hits}；当前槽位：{slots}
【用户问题】{rewritten_question}
```

**SQL Agent（兜底轨）**

```
你是 SQL 专家。根据问题生成 SQLite 查询（只读）。
【相关表结构】{slim_schema: DDL + 样例行}
【参考示例】{fewshots}
【硬约束】仅 SELECT；多表用标准 JOIN；明细查询必须带 LIMIT；禁止任何写操作与 PRAGMA。
【历史修正提示】{fix_hint?}
【用户问题】{rewritten_question}
只输出 SQL。
```

**Report Agent**：输入 = 结果集 + MQL 口径 + `low_confidence` 标记；约束 = "结论中的数字必须逐字来自结果集，禁止外推；空结果输出原因建议"；输出 = 六段 JSON（§4.3）。

**Analyze Agent**：输入 = 两期总量 + 贡献表；约束 = "结论模板：『{期间}{指标}{变化}{金额}（{pct}%），主要原因是 {Top1 维度值}（贡献 {share}%）…』；insufficient=true 时只输出对比"；输出 = 归因 JSON。

## 8. 评估脚本设计（chatbi/evals/）

### 8.1 验证集格式（evals/validation_set.jsonl）

```json
{"id": "V-T-01", "difficulty": "时间推理", "question": "上个月哪个国家的销售额最高？",
 "gold_sql": "SELECT ...", "gold_rows": [["USA", 13.86]],
 "expect": {"clarify": false, "declare_default": false, "track": "semantic"},
 "order_matters": false}
```

- `difficulty ∈ {时间推理, 聚合口径, 多表关联, 歧义问题, 排序复合}`，每类 ≥10 题；
- `gold_rows` 由 gold_sql 离线预执行生成（评估时不重复执行标准 SQL，保证可比）；
- 歧义类题目 `expect.clarify=true`，不提供 gold_rows（以澄清行为为判定）。

### 8.2 EX 判定算法（evals/ex.py）

```python
def execution_accuracy(pred_rows, gold_rows, order_matters=False, tol=1e-4) -> bool:
    norm = lambda rows: sorted(
        [tuple(round(float(c), 4) if isinstance(c, (int, float)) else str(c).strip() for c in r)
         for r in rows]) if not order_matters else [
        tuple(round(float(c), 4) if isinstance(c, (int, float)) else str(c).strip() for c in r)
        for r in rows]
    return norm(pred_rows) == norm(gold_rows)
```

要点：浮点四舍五入容差；默认行序无关（sorted），`order_matters=true` 时保序；列数不一致直接判负。

### 8.3 运行与报告

```
python -m chatbi.evals.runner --set evals/validation_set.jsonl --tag m2-baseline
```

- 逐题走完整 Orchestrator（非单测 Agent），采集：EX（总体+分层）、澄清率（歧义子集 `clarify` 命中率）、`declare_default` 合规率、平均时延、track 分布（semantic/fallback 占比）；
- 报告输出 `evals/reports/{tag}.md`（分层表格）+ 原始 JSON（版本留存，支持两轮对比）；
- 失败用例自动写入 `badcases/eval_failures.jsonl`（联动 F5.3 回流）。
