## 1. 背景与问题

市场 / 产品同学经常需要针对一个主题做调研，典型场景包括：竞品分析、行业趋势、技术选型、政策解读。

当前人工调研的痛点：

- **耗时**：人工搜索几十个网页、整理资料、撰写报告，一个主题动辄 **2~3 小时**。
- **易遗漏**：人工检索覆盖面有限，关键信息容易漏掉。
- **不可追溯**：结论与来源脱节，报告中的信息无法回溯到原始出处，可信度存疑。

## 2. 产品目标与定位

**一句话定位**：输入一个研究主题，自动完成检索、阅读、迭代与综合，产出一份**带来源引用、可追溯**的深度研究报告。

**目标**：将单主题调研从 2~3 小时压缩到分钟级的自动流程，同时保证结论有据可查。

**与一次性问答的区别**：本产品不是"问一句答一句"，而是一个**多步迭代的 Agent 研究流程**：
规划（拆子问题）→ 多轮检索 → 阅读抽取 → 判断是否需要补检 → 综合生成报告。

## 3. 目标用户与核心场景

| 用户 | 场景 | 期望产出 |
| --- | --- | --- |
| 市场同学 | 竞品分析、行业趋势 | 分节正文 + 竞品/趋势结论，每条结论可回溯来源 |
| 产品同学 | 技术选型 | 方案对比、关键结论、待确认的遗留问题 |
| 通用 | 政策解读 | 摘要 + 正文 + 政策原文出处 |

**核心用户故事**：
> 作为一名市场/产品同学，我希望输入一个研究主题后，系统自动检索、阅读并迭代研究，最终得到一份结构化研究报告；每条结论都能点回原始网页，我能看到研究过程（搜了什么、读了什么、迭代了几轮），并知道每条结论的可靠程度。

## 4. 功能需求

### 4.1 输入

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| F1-1 | 用户输入一个**研究主题**（自然语言，如"XX 品类 2026 年竞争格局"） | P0 |
| F1-2 | 主题应支持中文；对模糊主题由 Agent 在规划阶段拆解为可检索的子问题 | P0 |

### 4.2 核心研究流程（Agent 主循环）

| 编号 | 阶段 | 需求描述 | 优先级 |
| --- | --- | --- | --- |
| F2-1 | 规划 | 将主题拆解为若干**子问题**，形成研究计划 | P0 |
| F2-2 | 检索 | 根据子问题生成检索关键词，调用**联网搜索工具**获取候选网页（多轮） | P0 |
| F2-3 | 阅读抽取 | 阅读检索到的网页内容，抽取与子问题相关的事实与观点 | P0 |
| F2-4 | 迭代判断 | Agent 自行判断：信息是否足够？是否需要换关键词**补检**？迭代直至信息充分或达到轮次上限 | P0 |
| F2-5 | 综合生成 | 汇总所有材料，生成最终研究报告 | P0 |

### 4.3 输出物（四大交付）

| 编号 | 交付物 | 需求描述 | 优先级 |
| --- | --- | --- | --- |
| F3-1 | **结构化研究报告** | 包含：摘要、分节正文、关键结论、遗留问题 | P0 |
| F3-2 | **来源列表** | 每条结论关联 URL / 标题 / 来源，全文可追溯 | P0 |
| F3-3 | **研究过程记录** | 记录检索了哪些关键词、读了哪些页面、迭代了几轮 | P1 |
| F3-4 | **置信度说明** | 说明结论可靠程度、信息截止时间；无来源支撑的结论须标注为"模型推断" | P1 |

### 4.4 外部依赖：搜索工具

- 采用**博查（Bocha）Web Search API**：`POST https://api.bocha.cn/v1/web-search`
- 文档：https://bocha-ai.feishu.cn/wiki/RXEOw02rFiwzGSkd9mUcqoeAnNK
- 请求参数（示例）：`query`（检索词）、`summary: true`（返回摘要）、`count: 10`（返回条数）
- 鉴权：`Authorization: Bearer <API_KEY>`，**密钥必须放在环境变量 / 配置中，不得硬编码进代码或文档**

## 5. 流程示意

```
用户输入主题
    │
    ▼
① 规划：拆解子问题（研究计划）
    │
    ▼
② 检索：生成关键词 → 博查 Web Search ──┐
    │                                  │
    ▼                                  │
③ 阅读抽取：阅读网页，抽取事实/观点      │
    │                                  │
    ▼                                  │
④ 判断：信息足够？──否（换关键词补检）──┘
    │ 是（或达轮次上限）
    ▼
⑤ 综合生成
    │
    ├── 结构化研究报告（摘要 / 正文 / 关键结论 / 遗留问题）
    ├── 来源列表（URL / 标题，结论↔来源关联）
    ├── 研究过程记录（关键词 / 页面 / 轮次）
    └── 置信度说明（可靠度 / 信息截止时间 / "模型推断"标注）
```

## 6. 非功能需求

| 类别 | 要求 |
| --- | --- |
| 可追溯性 | 报告中每条关键结论必须能定位到至少一条来源；无来源的必须显式标注"模型推断" |
| 透明性 | 研究过程（关键词、页面、迭代轮次）完整留痕，可回放审计 |
| 成本控制 | 设定最大检索轮次 / 最大页面阅读数上限，防止 Agent 无限迭代 |
| 安全性 | API Key 不入代码库；网页内容仅用于研究，不外传 |
| 时效声明 | 报告须注明"信息截止时间"，避免用户误信过期信息 |

## 7. 成功指标（验收标准）

1. 输入任意给定主题，端到端产出完整四件套（报告 / 来源 / 过程 / 置信度）。
2. 报告关键结论 ≥ 80% 带有可访问的来源链接；无来源结论均已标注"模型推断"。
3. 过程记录能还原：搜过的关键词、读过的页面、迭代轮次。
4. 单次研究总耗时显著低于人工基线（2~3 小时），目标进入分钟级。

## 8. 范围边界（本期不做）

- 不做报告在线编辑、多人协作、导出格式定制（如 Word/PPT）。
- 不做定时自动更新研究主题（如每日监控）。
- 不做付费数据源（Wind、数据库等）接入，仅用公开网页搜索。

## 9. 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 搜索结果质量差 / 命中率低 | 报告空洞、结论错误 | 多关键词多轮补检；结论强制挂来源 |
| 网页读取失败或内容不可用 | 材料不足 | 记录失败页面，置信度说明中如实披露 |
| Agent 过度迭代 | 耗时 / token 成本失控 | 设定轮次与页面数上限，到限即综合出报告 |
| 模型幻觉 | 无来源结论混入正文 | 强制标注"模型推断"；置信度说明分层 |
| API 配额 / 密钥泄露 | 服务不可用 / 安全事故 | 密钥走环境变量；监控调用量 |
