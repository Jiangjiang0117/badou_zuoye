## 一、项目介绍（开场必问）

### Q：请简单介绍一下这个项目？

**参考回答（STAR 法则）：**

> 我在这个项目中做的是**电商智能问答系统**。
>
> **背景（Situation）**：电商平台用户每天有大量关于商品、物流、售后的咨询问题，传统人工客服响应慢、成本高，且答案质量参差不齐。
>
> **任务（Task）**：我负责构建一套基于大模型的智能问答系统，核心是意图识别模块，能够准确理解用户的问题意图，并给出准确回答。
>
> **行动（Action）**：
> - 使用 BiLSTM+CRF 和 R-BERT 进行命名实体识别（NER），F1-score 达到 91.26%
> - 构建包含 31,680 个实体的 Neo4j 知识图谱
> - 采用 BM25 + 向量检索的混合检索策略
> - 结合 RAG 技术和 Deepseek 大模型生成最终回答
>
> **结果（Result）**：系统上线后，问答准确率达到 **93%**（测试集 1000 条），显著提升了用户问答体验。

## 二、技术深度问题

### Q：介绍一下 BiLSTM+CRF 在 NER 中的作用？

**要点：**
- **BiLSTM**：双向 LSTM，从前向和后向两个方向编码上下文信息，每个位置都能获取全局语义
- **CRF**：条件随机场，在 BiLSTM 输出的基础上，加入**标签转移约束**（如 B 后面只能接 I，不能直接接 I）
- **为什么要 CRF**：纯 LSTM 输出的每个位置标签是独立预测的，可能出现非法序列（如 I-PER 出现在 B-LOC 后）；CRF 对整个序列联合建模，保证标注的全局最优

```
BiLSTM 输出：[0.8(B-PROD), 0.1(I-PROD), 0.05(O), ...]
CRF：考虑相邻标签转移概率，输出全局最优序列
```

---

### Q：R-BERT 和 BiLSTM+CRF 相比有什么优势？

**要点：**
- R-BERT 基于预训练的 BERT 模型，拥有海量语料预训练的语言知识
- 在少量标注数据下，R-BERT 表现更优（迁移学习优势）
- 对长距离依赖和语义歧义处理能力更强
- 本项目中 R-BERT 的 F1-score（91.26%）比 BiLSTM+CRF 高约 3~5 个百分点
- **代价**：推理速度略慢，模型体积更大

---

### Q：RAG 是什么？为什么要用 RAG？

**要点：**
- **RAG = Retrieval-Augmented Generation（检索增强生成）**
- 流程：`用户问题 → 检索相关知识 → 将知识注入 Prompt → 大模型生成答案`
- **为什么用**：
  1. 大模型知识有截止日期，无法知道实时商品/活动信息
  2. 减少大模型"幻觉"（hallucination），用真实文档约束回答
  3. 降低大模型训练成本（不需要全量微调）
- **本项目中的作用**：将 Neo4j 图谱查询结果 + 向量检索结果作为上下文，输入 Deepseek 生成最终回答

---

### Q：你们的混合检索是怎么做的？

**要点：**
1. **BM25 关键词检索**：基于词频/逆文档频率，擅长精确匹配（如查询"Nike Air Max 2024"）
2. **向量语义检索**：基于句向量相似度，擅长语义匹配（如"最新款运动鞋"能匹配到"Nike Air Max 2024"）
3. **Neo4j 图谱查询**：基于识别的实体，精确查询关系型知识（如查询"Nike 的退换货政策"）
4. **融合策略**：使用 **RRF（Reciprocal Rank Fusion）** 算法，将三路结果统一排序合并

```python
# RRF 核心公式
score(d) = Σ 1 / (k + rank_i(d))  # k=60, i为各检索路径
```

---

### Q：知识图谱是怎么构建的？

**要点：**
1. **数据来源**：电商商品库、售后政策文档、历史 FAQ
2. **实体识别**：使用 NER 模型抽取商品名、品牌、属性、价格等实体
3. **关系抽取**：使用 R-BERT 识别实体间关系（品牌-商品、商品-政策等）
4. **三元组入库**：(实体A, 关系, 实体B) 写入 Neo4j
5. **规模**：共 31,680 个实体节点，覆盖主要商品及服务场景
6. **查询示例**：
```cypher
MATCH (p:Product {name: "Nike"})-[:HAS_POLICY]->(policy:Policy)
RETURN policy.content
```

### Q：项目中遇到了哪些技术难点？

**要点（选 2~3 个重点讲）：**

**难点一：实体歧义消解**
- 问题："苹果手机"中的"苹果"是品牌，"苹果汁"中的"苹果"是水果
- 解决：引入上下文向量 + 知识图谱实体链接，结合候选实体的先验概率消歧

**难点二：大模型幻觉控制**
- 问题：Deepseek 在知识图谱无结果时会自行编造答案
- 解决：在 Prompt 中明确指令"若参考知识为空，回复'暂无相关信息'"，并在后处理中校验

**难点三：多轮对话上下文管理**
- 问题：用户连续提问时，代词指代不清（"它多少钱？"—— "它"指什么？）
- 解决：基于 Redis 维护会话状态，将历史对话注入当前 Prompt 实现上下文感知

## 三、项目亮点问题

### Q：这个项目最大的亮点是什么？

**参考回答：**

> 本项目最大的亮点有两个：
>
> 第一是**混合检索策略**。我们没有单纯依赖大模型，而是结合了 BM25 精确检索、向量语义检索和 Neo4j 图谱查询三种方式，通过 RRF 算法融合，既保证了精确词汇的匹配，又覆盖了语义相似的长尾问题，最终问答准确率达到 93%。
>
> 第二是**知识图谱与 RAG 的结合**。电商领域的知识有强关联性，单纯的向量检索无法表达"商品-品牌-政策"这类结构化关系，引入知识图谱后，系统能够精确回答"XX 品牌的退换货政策是什么"这类需要多跳推理的问题。

---

### Q：为什么选择 Deepseek 而不是 GPT-4？

**参考回答：**

> 主要考虑了三个因素：
> 1. **成本**：Deepseek API 调用成本远低于 GPT-4，在高并发电商场景下更经济
> 2. **中文能力**：Deepseek 在中文理解和生成上表现优秀，适合中文电商客服场景
> 3. **数据安全**：国内服务商合规性更强，用户对话数据不出境，满足数据安全要求
