### 2.1 数据来源
- 电商平台商品信息（商品参数、品牌、价格区间）

- 活动运营文档（促销规则、优惠券使用说明）

### 2.2 数据处理流程

**Step 1：知识抽取**
- 使用 BiLSTM+CRF 进行命名实体识别（NER）
- 识别实体类型：商品名、品牌名、属性词、价格、日期等
- **实测效果：F1-score 达 91.26%**（基于 R-BERT 模型微调）

**Step 2：知识图谱构建**
```python
# 示例：构建 Neo4j 三元组
```

## 三、模型训练

### 3.1 实体识别模型（NER）

**方案一：BiLSTM + CRF**
```
输入文本 → 字符嵌入 → BiLSTM 编码 → CRF 解码 → 实体标注序列
```
- 适合中文序列标注，CRF 保证标注连贯性
- 训练数据：电商领域标注语料
- 标注格式：BIO / BIOES

**方案二：R-BERT（推荐）**
```
输入文本 → BERT 预训练编码 → 关系分类头 → 实体关系抽取
```
- 基于预训练模型，少量标注数据即可获得高质量结果
- **F1-score 91.26%**，优于 BiLSTM+CRF 约 3~5 个百分点

### 3.2 意图识别模型（NLU）

**模型结构：**
```
用户输入 → BERT/Deepseek 编码 → 意图分类层（Softmax）→ 意图类别
```

**意图类别示例（电商场景）：**

| 意图 ID | 意图名称 | 示例问题 |
|---|---|---|
| INT_001 | 物流查询 | "我的包裹到哪了？" |
| INT_002 | 退换货咨询 | "想申请退款怎么操作？" |
| INT_003 | 商品参数查询 | "这款手机支持5G吗？" |
| INT_004 | 优惠活动查询 | "双十一有什么折扣？" |
| INT_005 | 投诉建议 | "客服态度太差了" |

### 3.3 对话管理

- 引入 NLU 模块解析用户意图，结合上下文进行**多轮对话管理**
- 对话槽位填充（Slot Filling）：确保联系机器人时必要信息完整
- 支持话题切换识别与对话历史追踪

## 四、RAG 检索增强生成

### 4.1 检索策略（混合检索）

```python
# 混合检索流程
def hybrid_retrieval(query, intent, entities):
    # 1. BM25 关键词检索
    bm25_results = bm25_search(query, top_k=10)

    # 2. 向量语义检索
    vector_results = vector_search(query_embedding, top_k=10)

    # 3. Neo4j 图谱查询（基于识别实体）
    graph_results = neo4j_query(entities)

    # 4. 结果融合排序（RRF算法）
    final_results = reciprocal_rank_fusion(
        bm25_results, vector_results, graph_results
    )
    return final_results[:5]
```

## 六、技术难点与解决方案

### 难点1：实体歧义问题
- **问题**：同一词在不同语境代表不同实体（如"苹果"→水果 or 品牌）
- **解决**：引入上下文向量，结合知识图谱实体链接消歧

### 难点2：多轮对话状态管理
- **问题**：用户连续追问时，系统需维护对话历史
- **解决**：实现对话槽位（Slot）记忆机制，上文信息注入下文 Prompt

### 难点3：知识图谱与向量检索融合
- **问题**：两种检索结果排序标准不统一
- **解决**：使用 RRF（Reciprocal Rank Fusion）算法统一融合排序

### 难点4：大模型回答"幻觉"
- **问题**：Deepseek 在知识不足时可能生成错误信息
- **解决**：强制 RAG 约束，无检索结果时回复"暂无相关信息"兜底策略
