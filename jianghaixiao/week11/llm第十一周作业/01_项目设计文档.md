## 1. 背景与问题

传统 BI 工具功能强大，但使用门槛高：

- 业务人员需要学习 SQL、拖拽报表、配置公式；
- 临时取数要排期，等数据团队几天；
- 同一个指标在不同报表里口径不一致；
- 数据分散在 MySQL、ClickHouse、Excel、API 等多个来源；
- 分析结论依赖人工，异常发现滞后。

**ChatBI 要解决的，是让用户用自然语言直接问数据，系统自动完成"理解问题 → 找表 → 写 SQL → 校验 → 执行 → 汇总成结论"的全过程。**

---

## 2. 项目目标

### 2.1 业务目标

1. 业务人员无需写 SQL 即可完成日常取数；
2. 临时分析从"按天/按周"缩短到"秒级/分钟级"；
3. 指标口径统一到语义层，减少跨部门争议；
4. 所有查询可追溯（问题、SQL、数据源、执行时间、结果）。

### 2.2 成功指标

| 指标 | 定义 | MVP 目标 | V1 目标 |
|---|---|---|---|
| SQL 执行成功率 | 生成 SQL 能成功执行的比例 | ≥ 90% | ≥ 97% |
| 结果准确率 | 结果与标准答案一致的比例 | ≥ 75% | ≥ 85% |
| P95 响应时间 | 从提问到返回结论 | ≤ 20s | ≤ 10s |
| 追问澄清率 | 歧义问题触发反问的比例 | ≥ 60% | ≥ 80% |
| 用户采纳率 | 回答被点赞/直接使用的比例 | ≥ 50% | ≥ 65% |
| 单次查询成本 | 平均 token 成本 | ≤ 0.05 元 | ≤ 0.02 元 |

## 3. 用户与典型场景

### 3.1 目标用户

| 用户 | 关注点 | 典型问题 |
|---|---|---|
| 业务运营 | 快速看数、看趋势 | "上周新增用户多少？" |
| 产品经理 | 功能使用、转化 | "哪个功能使用率最高？" |
| 数据分析师 | 临时探索、验证假设 | "按渠道拆一下最近的转化率" |
| 管理层 | 经营概览 | "本月销售额和上月比怎么样？" |
| 数据管理员 | 口径、权限、质量 | "这个指标是怎么定义的？" |

### 3.2 典型场景

1. **日常取数**：自然语言查询 → 表格/图表 → 复制/导出；
2. **异常排查**：发现指标异常 → 多维下钻 → 定位原因；
3. **汇报支撑**：一句话生成图表和结论，直接用于周报；
4. **口径确认**：追问指标定义、数据来源、更新时间。

## 4. ChatBI / Data Agent 能力模型

> 本模型综合了与 ChatGPT、DeepSeek、Qwen、豆包等模型围绕"ChatBI/Data Agent 需要具备哪些能力"的讨论，归纳为 8 个维度。具体对话记录见《04_多模型调研记录.md》。

| # | 能力维度 | 具体能力 | 为什么重要 | 优先级 |
|---|---|---|---|---|
| 1 | 数据接入 | 多数据源连接、Schema 解析、样例采样、元数据管理 | 没有数据就没有分析 | P0 |
| 2 | 语义理解 | 意图识别、实体抽取、指标/维度识别、歧义澄清、多轮上下文 | 决定"问得对不对" | P0 |
| 3 | 语义层 | 表/字段中文别名、指标口径、同义词、业务规则 | 决定"答得准不准" | P0 |
| 4 | SQL 生成 | Text-to-SQL、多表 JOIN、聚合、窗口函数、方言适配 | 核心生产力 | P0 |
| 5 | SQL 校验 | 语法校验、表/字段存在性、只读安全、EXPLAIN、执行校验 | 决定"敢不敢跑" | P0 |
| 6 | 自修复 | 报错反思、SQL 改写、重试上限、失败兜底 | 决定"能不能用" | P1 |
| 7 | 结果呈现 | 表格、图表推荐、自然语言总结、导出、分享 | 决定"好不好用" | P1 |
| 8 | 治理运营 | 权限、脱敏、审计、成本控制、评测、Badcase 闭环 | 决定"能不能上线" | P0 |

### 4.1 能力成熟度分级

| 等级 | 特征 | 对应能力 |
|---|---|---|
| L1 可用 | 单表查询、简单聚合，人工兜底 | Text-to-SQL + 执行 |
| L2 好用 | 多表 JOIN、自动校验、失败重试、图表 | 语义层 + 校验 + 改写 |
| L3 可信 | 指标口径统一、权限隔离、结果可解释、评测闭环 | 治理 + 评测 |
| L4 智能 | 主动洞察、异常归因、多轮探索、自动生成报告 | Agent 自主规划 |

**本项目 MVP 目标：L2；V1 目标：L3。**

## 5. 产品范围

### 5.1 本期做（MVP）

- 单数据源（SQLite / MySQL）接入；
- 自然语言问答（中文）；
- 表选择 + SQL 生成 + 校验 + 执行 + 汇总；
- 表格展示 + 基础柱状图/折线图；
- 多轮对话（保留最近 10 轮）；
- 历史会话记录与回看；
- 基础权限（用户登录、数据源只读）。

### 5.2 本期不做（明确边界）

- 不做数据写入（INSERT/UPDATE/DELETE）；
- 不做跨库联邦查询；
- 不做复杂的 OLAP 预计算；
- 不做移动端 App；
- 不做自然语言建模（建表/改表）；
- 不做多租户计费。

> 明确"不做什么"，比列"做什么"更重要——它决定了排期和风险边界。

## 6. 总体架构

```
┌─────────────────────────────┐
│ 前端：Streamlit / Vue3       │  对话页、图表、历史列表
└──────────────┬──────────────┘
               │ HTTP / SSE
┌──────────────▼──────────────┐
│ 后端：FastAPI                │  鉴权、会话、路由、限流、审计
└──────────────┬──────────────┘
               │
┌──────────────▼──────────────┐
│ Agent Orchestrator           │  意图 → 选表 → SQL → 校验 → 改写 → 执行 → 汇总
└──────┬───────────────┬──────┘
       │               │
┌──────▼──────┐  ┌─────▼──────┐
│ MCP Tools   │  │ 语义层      │  表/字段别名、指标口径、同义词
└──────┬──────┘  └────────────┘
       │
┌──────▼──────────────────────┐
│ 数据源：SQLite / MySQL /    │
│ ClickHouse / Excel / API    │
└─────────────────────────────┘
```

**设计要点**：

1. **前端只负责展示**，不直接接触数据库；
2. **后端负责鉴权与会话**，Agent 不处理登录注册；
3. **Agent 与数据源之间通过 MCP 工具解耦**，新增数据源不改 Agent；
4. **语义层是"业务口径"的唯一来源**，避免模型自由发挥。

## 7. 核心业务流程

```
用户提问
   │
   ▼
① 鉴权 + 数据权限过滤（用户能看哪些表/字段）
   │
   ▼
② 意图识别：是取数、解释指标、还是闲聊？
   │
   ├── 闲聊/无关 → 直接回答，结束
   ├── 指标解释 → 查语义层，回答
   └── 取数 → 继续
   │
   ▼
③ 表选择：语义召回 Top-5 → LLM 确认 Top-2~4
   │
   ▼
④ SQL 生成：问题 + schema + 口径 → SELECT
   │
   ▼
⑤ SQL 校验：静态（只读/表字段）→ EXPLAIN → 执行限制
   │
   ├── 不通过 → ⑥ SQL 改写（最多 3 次）→ 回到 ⑤
   │
   ▼
⑦ SQL 执行：只读 + LIMIT + 超时
   │
   ▼
⑧ 结果汇总：自然语言 + 图表推荐
   │
   ▼
返回：回答 + SQL + 数据 + 图表 + 耗时
```

## 9. 风险与应对

| 风险 | 影响 | 概率 | 应对 |
|---|---|---|---|
| 模型幻觉字段/表 | SQL 报错 | 高 | Schema 注入 + 静态校验 + 改写 |
| 结果看似正确实则错误 | 决策失误 | 中 | 结果校验 + 展示 SQL + 用户反馈 |
| 指标口径不一致 | 跨部门争议 | 高 | 语义层统一口径 + 版本管理 |
| 大表查询拖垮数据库 | 服务不可用 | 中 | 只读账号 + 超时 + 限行 + 缓存 |
| 数据权限泄露 | 合规事故 | 低 | 行/列级权限 + 审计日志 |
| 调用成本过高 | 预算超支 | 中 | 小模型路由 + 缓存 + 限流 |
| 多轮上下文膨胀 | 延迟/成本上升 | 中 | 只带最近 10 轮 + 摘要压缩 |

## 10. 验收标准

### 10.1 功能验收

- [ ] 能用中文提问并得到结果；
- [ ] 支持单表、JOIN、聚合、时间过滤；
- [ ] 生成的 SQL 可在界面上查看；
- [ ] 执行失败的 SQL 能自动改写（≥1 次）；
- [ ] 结果能以表格 + 图表展示；
- [ ] 多轮对话能记住上文；
- [ ] 历史会话可回看。

### 10.2 质量验收

- [ ] 10 题评测集执行成功率 ≥ 90%；
- [ ] 结果准确率 ≥ 75%；
- [ ] P95 响应 ≤ 20 秒；
- [ ] 无越权查询；
- [ ] 无写操作（INSERT/UPDATE/DELETE）。
