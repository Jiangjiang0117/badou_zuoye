# ChatBI Demo 项目设计文档

**版本**：v0.1  
**文档类型**：项目设计文档（Project Design Document）  
**上游依据**：ChatBI Demo 产品定位文档（PRD）v0.1

## 1. 项目概述

### 1.1 项目背景
业务人员查数依赖分析师或固定报表，沟通成本高。ChatBI Demo 旨在验证“自然语言 → 口径确认 → SQL 查询 → 图表与结论”的核心链路，为后续产品化提供可行性依据。

### 1.2 项目目标
构建一个可本地运行、可演示的 Web ChatBI Demo：
- 用户自然语言提问电商销售数据问题；
- 系统先展示“我理解的问题/口径”，用户可编辑/纠正；
- 口径确认后生成并执行 SQL；
- 返回文字总结、SQL、结果表格、自动图表；
- 支持上下文继承、指代省略、下钻/换维三类多轮；
- 查询失败自动纠错最多 2 次，仍失败只提示用户。

### 1.3 项目定位
- **演示优先**：优先保证核心链路稳定、演示脚本可跑通。
- **范围克制**：不做生产级能力，接口与模块保留扩展点。
- **可替换**：LLM、数据库、前端均可替换；MCP 作为可选扩展。

## 2. 项目范围

### 2.1 In Scope
| 类别 | 内容                                                         |
| ---- | ------------------------------------------------------------ |
| 前端 | Streamlit Web 聊天页、口径卡片编辑、结果展示、会话重置       |
| 后端 | FastAPI 接口、意图解析、口径管理、SQL 生成/校验/执行/纠错、图表选型、文字总结 |
| 数据 | 本地 MySQL 内置电商样例库（5 张表，3000～5000 订单）         |
| LLM  | Qwen，通过 OpenAI Agents SDK 以 OpenAI 兼容协议接入，Key 放 `.env` |
| 多轮 | 上下文继承、指代省略、下钻/换维                              |
| 图表 | Streamlit 原生 `st.line_chart` / `st.bar_chart`，自动选图    |
| 安全 | 只读账号、仅 SELECT、表白名单、`LIMIT 1000`、超时 10 秒      |
| 验收 | 20 题 ≥15 过、3 组多轮、单次 10 秒内                         |

### 2.2 Out of Scope
权限控制、多租户、数据脱敏、复杂指标口径治理、高并发、审计日志、移动端适配、导出、手动切换图表、ECharts、饼图、生产级监控告警。

### 2.3 可选扩展（P1，不阻塞 Demo）
- 只读 MySQL MCP Server，封装 `list_tables`、`describe_table`、`run_readonly_query`；
- 会话持久化到 SQLite/Redis；
- 更丰富的图表类型与导出。

## 4. 项目模块划分（WBS）

```text
ChatBI Demo
├── M1 前端聊天与口径编辑（Streamlit）
├── M2 会话与上下文管理
├── M3 意图解析与口径卡片
├── M4 SQL 生成与安全校验
├── M5 SQL 执行与自动纠错
├── M6 结果处理与图表选型
├── M7 文字总结生成
├── M8 样例数据与元数据
├── M9 配置、日志与错误处理
└── M10（P1）MCP 工具封装
```

### 4.1 模块职责
| 模块 | 职责                                            | 关键产出       |
| ---- | ----------------------------------------------- | -------------- |
| M1   | 聊天交互、口径卡片渲染与编辑、结果展示、重置    | Streamlit 页面 |
| M2   | `session_id` 管理、对话历史、上一轮口径与结果列 | 会话状态       |
| M3   | 自然语言 → 结构化口径；歧义识别；复述           | 口径 JSON      |
| M4   | 口径 → SELECT SQL；只读/白名单/LIMIT 校验       | 安全 SQL       |
| M5   | 执行 SQL；失败回喂纠错（≤2 次）；失败提示       | 结果集/错误    |
| M6   | 根据结果列与口径选择折线/柱状；无合适维度不出图 | 图表配置       |
| M7   | 基于结果生成不编造的文字总结                    | 总结文本       |
| M8   | 建表、造数、schema 元数据、指标口径常量         | 样例库         |
| M9   | `.env` 配置、日志、错误脱敏、超时               | 配置与日志     |
| M10  | 可选 MCP 工具                                   | MCP Server     |

### 4.2 模块依赖
```text
M1 → M2 → M3 → M4 → M5 → M6 → M7
                ↑           ↑
               M8          M8
M9 横切所有模块；M10 可选替换 M8/M5 的工具层
```

## 6. 环境与依赖

### 6.1 运行环境
| 项       | 要求                        |
| -------- | --------------------------- |
| 操作系统 | macOS / Linux / Windows WSL |
| Python   | 3.10+                       |
| MySQL    | 本地 8.x，只读账号          |
| LLM      | Qwen，OpenAI 兼容端点       |
| 浏览器   | Chrome/Edge 现代浏览器      |

### 6.2 主要依赖
- 前端：`streamlit`
- 后端：`fastapi`、`uvicorn`、`pydantic`
- LLM：`openai-agents`（OpenAI Agents SDK，兼容 OpenAI 协议）
- 数据库：`pymysql` 或 `sqlalchemy`
- 配置：`python-dotenv`
- 测试：`pytest`

### 6.3 配置项（`.env.example`）
```env
QWEN_API_KEY=
QWEN_BASE_URL=
QWEN_MODEL=
MYSQL_HOST=127.0.0.1
MYSQL_PORT=3306
MYSQL_USER=chatbi_ro
MYSQL_PASSWORD=
MYSQL_DB=chatbi_demo
QUERY_TIMEOUT_SECONDS=10
MAX_ROWS=1000
MAX_SQL_RETRY=2
```

### 6.4 启动方式（目标）
```bash
# 1. 初始化样例库
python data/seed.py

# 2. 启动后端
uvicorn backend.main:app --reload --port 8000

# 3. 启动前端
streamlit run frontend/app.py
```

## 9. 验收与演示计划

### 9.1 验收标准
- 20 个典型问题 ≥15 个返回合理结果；
- 3 组多轮连续对话跑通；
- 单次响应 ≤10 秒（不含 LLM 排队）；
- 口径确认前不执行 SQL；
- 自动纠错 ≤2 次，仍失败仅提示用户；
- 输出包含文字总结、SQL、表格、自动图表（有合适维度时）。

### 9.2 验收方式
- 使用 `tests/acceptance_cases.md` 记录每题：问题、口径卡片、SQL、结果、图表、总结、耗时、结论。
- 多轮单独记录会话 ID 与每轮口径继承情况。
- 失败题标注原因：解析错误 / SQL 错误 / 纠错失败 / 结果不合理。

### 9.3 演示计划
- 10 个精选单轮 + 3 组多轮，覆盖聚合、分组、趋势、排名、多表关联、同比、退款、指代、下钻、纠错。
- 演示前重置会话，按脚本顺序执行，保留一题失败纠错演示。

## 10. 风险与应对

| 风险                            | 影响         | 应对                                                         |
| ------------------------------- | ------------ | ------------------------------------------------------------ |
| Qwen 结构化输出不稳定           | 口径解析失败 | JSON 校验 + 重试一次 + 失败提示；关键字段用枚举约束          |
| Qwen 工具调用/Agents SDK 兼容性 | 链路阻塞     | 先验证最小调用；必要时降级为直接 Chat Completions + JSON 输出 |
| Streamlit 状态与后端会话不同步  | 多轮错乱     | `st.session_state` 存 `session_id`；每次请求带 `session_id`；重置同步 |
| 多轮口径继承偏差                | 结果不符预期 | 口径卡片展示继承后完整口径；允许用户编辑纠正                 |
| SQL 安全                        | 误操作       | 只读账号 + SELECT 白名单 + LIMIT + 超时 + 多语句拦截         |
| 自动纠错循环                    | 延迟/成本    | 最多 2 次；失败即停并提示                                    |
| Streamlit 原生图表能力有限      | 图表不理想   | 仅折线/柱状；无合适维度时表格优先                            |
| MCP 增加调试成本                | 进度风险     | MCP 列为 P1，不进入核心链路                                  |
| 样例数据不具代表性              | 演示效果差   | 覆盖多地区/品类/时间/退款状态，预置典型问题                  |

## 11. 默认假设与变更管理

### 11.1 默认假设
- 口径编辑同时支持结构化编辑与自然语言重述；
- 口径确认后直接执行 SQL，不再二次确认 SQL；
- 会话存内存，重启丢失可接受；
- 图表仅 Streamlit 原生折线/柱状，自动选图；
- MCP 为可选 P1；
- 样例库为本地 MySQL，允许重建。

### 11.2 变更管理
- 范围变更需更新 PRD 与本文件；
- 新增功能优先判断是否影响验收标准；
- P1 项（MCP、持久化、导出）不阻塞 P6 验收。

## 12. 术语表

| 术语     | 含义                                                        |
| -------- | ----------------------------------------------------------- |
| 口径卡片 | 系统对用户问题的结构化理解，含指标/维度/过滤/排序/限制/歧义 |
| 口径确认 | 用户确认或编辑口径后才允许生成执行 SQL                      |
| 自动纠错 | SQL 失败后回喂错误由 LLM 修正，最多 2 次                    |
| 多轮三类 | 上下文继承、指代省略、下钻/换维                             |
| P0/P1    | P0 为 Demo 必须；P1 为可选扩展                              |
