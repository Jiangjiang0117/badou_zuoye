# 电商智能问答系统 · NLU 意图识别模块 — 产品文档

> 版本：v1.0
> 日期：2026-08-13
> 关联项目：项目三「电商智能问答系统」中的自然语言理解（NLU）子模块

---

## 1. 项目背景

电商平台每天面临海量用户咨询（商品参数、订单状态、退换货政策、物流进度等）。传统人工客服响应慢、成本高；通用大模型缺乏领域知识，容易产生"幻觉"或答非所问。

在「基于知识图谱的智能问答系统（RAG + BM25 + Deepseek）」的整体架构中，**NLU 意图识别模块**是对话流程的入口：它负责在进入检索/生成之前，先准确判断用户到底想问什么（意图）以及带有哪些关键信息（实体/槽位）。意图识别准确率直接决定后续"检索什么、生成什么"，是整个问答链路的第一道关卡。

本项目为「作业 2」—— 基于既有 `01-intent-classify` 项目的方法论（BERT 微调 + FastAPI 服务），独立实现一个**面向电商咨询场景的意图识别模块**。

## 2. 项目目标

1. 构建电商咨询场景下的**意图识别分类器**，将用户自然语言问句映射到预设意图类别。
2. 提供 **TF-IDF + 线性分类器（baseline）** 与 **BERT 微调（主模型）** 两条可对比的技术路线。
3. 以 **FastAPI** 对外提供 HTTP 推理接口，支持单条 / 批量输入。
4. 建立**可复用、解耦**的工程结构，具备完整测试用例与文档，便于后续接入知识图谱检索与 Deepseek 生成模块。

## 3. 范围说明

本次聚焦 **NLU 意图识别**，覆盖以下能力：

- 意图识别：文本 → 意图类别
- 推理服务：FastAPI 接口（单条 / 批量）
- 模型训练：TF-IDF baseline、BERT 微调

**不在本次范围**（属于项目三后续阶段）：

- 实体识别 / 槽位填充（BLSTM+CRF）
- 关系抽取（R-BERT）
- 知识图谱检索（BM25 / Neo4j）
- 答案生成（Deepseek）

## 4. 意图类别体系

针对电商咨询场景，设计 10 个意图类别：

| 类别ID | 英文标签 | 中文含义 | 典型问法示例 | 关键触发词 |
|--------|----------|----------|--------------|------------|
| 0 | Product-Query | 商品查询 | 这款手机电池多大？有蓝色的吗？ | 参数、规格、颜色、尺码、库存、材质 |
| 1 | Price-Query | 价格咨询 | 这个多少钱？有优惠吗？ | 多少钱、价格、贵、便宜、原价 |
| 2 | Order-Query | 订单查询 | 我的订单发货了吗？ | 订单、发货、下单、取消订单、修改地址 |
| 3 | Logistics-Query | 物流查询 | 快递到哪了？多久能到？ | 物流、快递、到哪、配送、签收、单号 |
| 4 | Return-Refund | 退换货 | 想退货，怎么退？能退款吗？ | 退货、换货、退款、七天无理由 |
| 5 | After-Sale | 售后保修 | 商品坏了能保修吗？ | 保修、维修、售后、质量问题、三包 |
| 6 | Payment | 支付问题 | 支付失败了怎么办？能开发票吗？ | 支付、付款、发票、微信、支付宝、扣款 |
| 7 | Promotion | 优惠活动 | 有什么优惠券？满减活动怎么算？ | 优惠券、满减、活动、折扣、秒杀、包邮 |
| 8 | Human-Service | 人工客服 | 帮我转人工。 | 人工、人工客服、转人工、真人 |
| 9 | Other | 其他 | 谢谢、再见、表情符号 | （兜底，无明确领域意图） |

> 说明：类别采用「1 + N」设计 —— `Other` 为兜底类，用于吸收闲聊、无效输入与无法归类的内容，降低误分类带来的下游风险。

## 5. 技术方案

### 5.1 模型选型

| 路线 | 模型 | 作用 | 特点 |
|------|------|------|------|
| baseline | TF-IDF + LinearSVC | 快速基线 | 轻量、无需 GPU、可解释 |
| 主模型 | BERT（`bert-base-chinese`）微调 | 意图识别 | 语义理解强、准确率高 |

- 分词：`jieba`（中文分词 + 停用词过滤）
- 框架：`transformers`（BERT）、`sklearn`（TF-IDF/SVC）、`torch`

### 5.2 为什么用 BERT 微调

- 电商问句短文本、口语化、同义表达多（"多少钱"="价格多少"="怎么卖"），规则与词袋模型难以覆盖。
- BERT 通过双向上下文建模能更好捕捉语义，符合项目三「使用微调后的 BERT 进行意图识别」的既定技术路线。

### 5.3 推理链路

```
用户文本
   │
   ├─> 预处理（jieba 分词 + 停用词过滤）──> TF-IDF 特征 ──> LinearSVC ──> 意图
   │
   └─> BERT Tokenizer ──> BERT(微调) ──> logits ──> argmax ──> 意图
```

## 6. 数据方案

### 6.1 数据来源

电商领域无现成公开意图数据集，采用「**种子样例 + 模板变体 + 人工复核**」策略构造：

- 每个意图类别手工编写**种子问法**（覆盖不同口语表达、句式）。
- 通过同义改写、主语替换、语气词、标点变化等方式生成**模板变体**，扩充样本量。
- 最终导出为 TSV 格式：`文本\t意图标签`（与 `01-intent-classify` 数据格式一致，便于迁移）。

### 6.2 数据规模（目标）

| 类别 | 目标样本数（约） |
|------|------------------|
| 9 个领域意图（各） | 40 ~ 60 |
| Other 兜底 | 40 ~ 60 |
| **合计** | **约 400 ~ 600 条** |

> 说明：BERT 微调在数百条规模即可获得可用效果；后续可接入真实客服日志持续扩充。

### 6.3 标注规范

- 一条样本只属于一个主意图（多意图场景按"用户主诉求"标注）。
- 出现退换货诉求时优先标 `Return-Refund`，其次 `After-Sale`（售后/保修）。
- 问价格但诉求是"有没有优惠"时标 `Promotion`；单纯问"多少钱"标 `Price-Query`。
- 无法归入 0~8 类的标 `Other`。

### 6.4 数据划分

- 训练集 / 验证集：`stratify` 分层划分，比例 8 : 2，保证类别分布一致。

## 8. 接口设计

### 8.1 请求体（`TextClassifyRequest`）

```json
{
  "request_id": "req-001",
  "request_text": "我的订单发货了吗"
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| request_id | string | 否 | 请求 ID，便于追踪 |
| request_text | string / string[] | 是 | 待识别文本，支持单条或批量 |

### 8.2 响应体（`TextClassifyResponse`）

```json
{
  "request_id": "req-001",
  "request_text": "我的订单发货了吗",
  "classify_result": ["Order-Query"],
  "classify_time": 0.023,
  "error_msg": "ok"
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| classify_result | string / string[] | 识别出的意图标签（与输入一一对应） |
| classify_time | float | 推理耗时（秒） |
| error_msg | string | `ok` 表示成功，否则为异常堆栈 |

### 8.3 路由

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/` | 健康检查 |
| POST | `/v1/intent/tfidf` | TF-IDF baseline 推理 |
| POST | `/v1/intent/bert` | BERT 主模型推理 |

## 9. 评估指标

| 指标 | 目标值 | 说明 |
|------|--------|------|
| Accuracy | ≥ 0.90 | 整体准确率（验证集） |
| Macro-F1 | ≥ 0.85 | 类别不均衡下的平均 F1 |
| P50 / P95 延迟 | < 100ms / < 300ms | 单条推理耗时（CPU） |
