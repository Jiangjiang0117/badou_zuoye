# ChatBI 功能设计文档

> Functional Design · v0.1 · 讨论稿

**版本：** v0.1（讨论稿）  
**日期：** 2026-10-22  
**项目：** ChatBI 对话式商业智能

## 文档说明

本文定义用户可见功能、系统行为、业务规则、异常处理和验收条件。具体技术栈、数据库结构和部署方式由技术设计文档定义。

范围假设：首期支持一个或少量只读数据源、经过配置的业务语义、自然语言查询、表格 / 图表展示、多轮追问和基础管理能力。

## 1. 功能地图与优先级

| 功能域 | 功能项 | 优先级 | 说明 |
| --- | --- | --- | --- |
| 工作台 | 自然语言提问、会话历史、结果查看 | P0 | 核心问答闭环 |
| 问答分析 | 意图识别、指标映射、歧义澄清 | P0 | 避免误解用户问题 |
| 查询安全 | 权限检查、SQL 校验、执行限制 | P0 | 上线阻断项 |
| 结果呈现 | 数据表、基础图表、查询摘要 | P0 | 让结果可理解 |
| 语义管理 | 指标、维度、同义词、字段映射 | P0 | 保证业务口径一致 |
| 反馈与审计 | 有帮助 / 无帮助、执行记录 | P1 | 支持质量改进 |
| 管理后台 | 用户角色、数据源、连接测试 | P1 | 按实际首期范围确认 |
| 高级分析 | 自动归因、预测、跨域探索 | P2 | 不纳入首期验收 |

## 2. 角色与权限行为

| 角色 | 可执行行为 | 限制 |
| --- | --- | --- |
| 普通分析用户 | 对授权数据域提问、查看结果、追问、反馈 | 不能管理数据源或修改语义定义 |
| 业务管理员 | 维护业务指标说明、同义词和经授权的语义配置 | 不能绕过底层数据权限 |
| 数据管理员 | 配置数据源、表列白名单、访问规则和查询限制 | 敏感操作需审计 |
| 系统管理员 | 管理用户、角色、系统级配置与运行状态 | 管理操作按最小权限授权 |

权限判定必须在服务端和查询执行前完成。前端隐藏按钮不能作为安全控制。用户无权访问的数据，不应通过错误信息、SQL 预览、图表摘要或模型上下文间接泄露。

## 3. 核心功能：自然语言提问

### 3.1 触发与输入

- 用户进入一个已授权的数据域，在输入框提交问题。
- 支持自然语言、常见时间表达、筛选条件、排序、分组和比较意图。
- 可附加当前会话上下文；用户可开启新会话，避免不相关上下文串入。
### 3.2 处理与输出

- 识别问题涉及的指标、维度、时间范围、筛选条件、比较基准和期望呈现方式。
- 如果关键语义明确，进入查询规划；如果存在会改变结果的歧义，先发起澄清。
- 结果区域展示答案状态、摘要、数据表 / 图表、数据来源说明和查询时间。
- 在有权限且可安全展示的情况下，允许用户查看生成的 SQL 或查询说明。
### 3.3 业务规则

- 不得仅因用户使用“增长、下降、最好”等词就推断未经定义的指标口径。
- 相对时间必须依据系统配置的业务时区解释；展示实际使用的起止时间。
- “销售额”若存在含税 / 不含税、支付 / 下单 / 退款后等多种定义，必须采用已配置口径或询问用户。
- 如果请求超出当前数据覆盖范围，应说明缺少的数据，而不是生成看似合理的答案。
### 3.4 验收标准

- 对标准问题，系统映射到预期指标、维度、过滤条件和时间范围。
- 对影响结果的歧义，系统先澄清，不静默猜测。
- 无权限问题在执行前被拒绝；不会返回敏感字段值。
## 4. 核心功能：多轮追问与上下文

用户可基于上一次结果继续追问，例如“只看日本市场”“按周拆分”“把前五名画成柱状图”。系统应继承仍然有效的上下文，并清晰反映新增或变更条件。

| 用户追问 | 预期行为 | 注意事项 |
| --- | --- | --- |
| “只看日本市场” | 保留原指标、时间范围和其他筛选，新增市场条件 | 若上文不存在可继承查询，要求补充问题 |
| “按周拆分” | 在原查询基础上调整时间分组 | 说明周的起始日和时区规则 |
| “那上个月呢？” | 只替换时间范围，保留其他条件 | 将实际日期范围展示给用户 |
| “换成订单数” | 替换指标，保留兼容的维度和筛选 | 如指标不兼容，提示原因 |
| 用户开始完全不同的问题 | 建议新建会话或识别为新主题 | 不能错误继承旧筛选 |

系统应提供“当前分析条件”或等效的可检查摘要，至少展示指标、时间范围、筛选、分组维度。用户可以修正条件。

## 5. 核心功能：歧义澄清

当不同解释会导致明显不同结果时，系统应优先提出简短、具体的澄清问题。澄清应尽量提供有意义的选项，同时允许用户自行补充。

| 问题情况 | 示例 | 系统行为 |
| --- | --- | --- |
| 指标口径不明 | “收入”可能指下单金额或支付金额 | 询问采用哪种已配置口径 |
| 时间范围不明 | “最近表现怎么样” | 询问时间范围，或按产品约定的默认范围并明确说明 |
| 维度指代不明 | “按区域看”但有销售区域和客户地区 | 询问要使用哪个维度 |
| 数据域不匹配 | 用户要求分析当前数据集没有的广告成本 | 说明数据缺失，提供可分析的替代项 |
| 无实质歧义 | “统计本月订单数”且口径已定义 | 直接执行，不增加不必要的追问 |

验收标准：澄清问题应针对一个或少数关键缺失项；用户回答后应继续原任务，不应要求重复已经提供的信息。

## 6. 核心功能：SQL / 查询安全

查询执行前必须经过确定性的安全策略校验。大模型自我声明“SQL 安全”不能替代校验器。

- 只允许配置的数据源、数据库、schema、表和列。
- 首期只允许只读查询；拒绝 INSERT、UPDATE、DELETE、DROP、ALTER、TRUNCATE、权限变更及多语句请求。
- 执行前应用用户权限、行列权限、最大返回行数、超时和成本限制。
- SQL 不通过校验时，不执行；返回安全且不泄露内部实现细节的提示，并记录原因码。
- 禁止通过模型生成的自由文本直接拼接权限条件；权限过滤应由受控代码或数据库策略施加。
| 异常 | 用户可见行为 | 系统记录 |
| --- | --- | --- |
| SQL 语法错误 | 说明查询未成功，可尝试改写问题 | 错误类型、脱敏 SQL、关联请求 ID |
| 检测到危险语句 | 拒绝执行，提示该操作不被支持 | 策略命中项、用户和请求 ID |
| 超时 / 资源超限 | 说明查询超出限制，建议缩小时间范围或筛选 | 耗时、限制类型 |
| 权限不足 | 说明无权查看所需数据或需申请权限 | 权限策略、资源标识 |
| 数据源不可用 | 提示暂时无法查询，可稍后重试 | 连接状态、错误码 |

## 7. 核心功能：结果呈现与解释

- 表格：支持列名、数据类型 / 单位、排序和合理的分页或截断提示。
- 图表：根据结果结构推荐合适的柱状图、折线图、饼图或表格；不适合图表时优先展示表格。
- 摘要：描述结果中可直接由数据支持的事实，例如最大值、最小值、变化幅度和排名。
- 比较：必须展示比较基准、计算方式和时间范围。
- 空结果：明确显示“当前条件下没有匹配数据”，不得把空结果解释成业务值为零。
- 小样本或缺失数据：在结论中标明限制，不得把相关性直接表述为因果关系。
- 可追溯性：展示查询时间、数据集名称、指标口径；SQL 仅对授权用户可见。
验收标准：摘要中的数值、单位和变化幅度与查询结果一致；图表与表格使用同一结果集；截断数据必须明确提示。

## 8. 核心功能：语义层管理

语义层用于把业务语言映射到可信的数据定义，是 ChatBI 正确性的关键配置，而不是可有可无的辅助功能。

| 配置对象 | 必需信息 | 规则 |
| --- | --- | --- |
| 指标 | 名称、定义、表达式 / 计算逻辑、单位、口径负责人 | 指标定义应版本化，避免同名异义 |
| 维度 | 名称、对应字段、数据类型、描述 | 明确日期、地区、渠道等含义 |
| 同义词 | 业务常用说法、缩写、别名 | 冲突词需配置优先级或触发澄清 |
| 关系 | 表之间的关联键、关系类型、基数约束 | 防止错误 Join 导致重复计数 |
| 数据范围 | 可查询表列、默认时间范围、数据新鲜度 | 明确数据覆盖边界 |
| 权限策略 | 角色、资源、行列限制 | 语义配置不能扩大底层权限 |

编辑语义配置应支持校验、预览和测试问题。高影响指标的修改应保留版本和变更记录。

## 9. 会话、反馈与错误状态

| 状态 | 说明 | 可执行操作 |
| --- | --- | --- |
| 处理中 | 正在解析、校验或执行查询 | 显示进度状态，防止重复提交 |
| 需要澄清 | 系统等待用户补充关键信息 | 回答澄清、取消或修改问题 |
| 成功 | 结果已生成并通过基本校验 | 追问、查看详情、反馈 |
| 无数据 | 查询成功但没有匹配记录 | 修改条件或时间范围 |
| 部分结果 | 因限制截断或部分数据源失败 | 查看限制说明、重试或缩小范围 |
| 失败 | 查询未能完成 | 重试、改写问题、查看可公开错误说明 |

用户反馈用于质量改进，不应直接作为真实业务数据。反馈应关联问题、语义解析、SQL 版本、执行状态和结果版本。

## 10. 管理与运维功能

- 数据源配置：连接信息安全存储、连通性测试、健康状态和权限检查。
- 用户与角色：用户分配、数据域授权、管理员操作审计。
- 语义管理：指标、维度、同义词、关联关系、版本与测试。
- 运行监控：请求成功率、延迟、模型 / 查询成本、SQL 拒绝率、错误类型。
- 评测管理：维护标准问题集，记录模型、Prompt、语义配置版本和测试结果。
## 11. 端到端验收用例

| ID | 场景 | 输入 / 前置条件 | 预期结果 |
| --- | --- | --- | --- |
| F-001 | 标准查询 | “统计本月订单数”，指标口径已配置 | 返回正确值、日期范围和来源 |
| F-002 | 歧义指标 | “查看收入”，存在多个收入口径 | 先询问用户选择口径 |
| F-003 | 多轮筛选 | 先查询销售额，再说“只看日本” | 保留原条件并新增市场筛选 |
| F-004 | 无数据 | 选择不存在记录的时间范围 | 展示空结果，不伪造零值 |
| F-005 | 越权访问 | 用户请求未授权客户明细 | 执行前拒绝，结果不泄露敏感信息 |
| F-006 | 危险 SQL | 模型输出含删除操作的 SQL | 安全校验拒绝执行 |
| F-007 | 超时 | 查询超过系统限制 | 停止或取消查询，展示安全提示 |
| F-008 | 数值摘要 | 结果含明确总量和变化值 | 摘要与结果一致，单位正确 |
| F-009 | 上下文切换 | 新问题与上一问题无关 | 不错误继承上一轮筛选 |
| F-010 | 数据源失败 | 数据库连接不可用 | 展示失败状态并记录可追踪错误 |

## 12. 待确认问题

- 首期支持哪些业务域、数据源和数据库类型？
- 是否允许用户查看 SQL？哪些角色可以查看？
- 默认时区、财务周期、周起始日和默认时间范围是什么？
- 是否需要导出 CSV / Excel、分享分析结果或保存为固定报表？
- 会话历史、查询日志和用户问题分别保留多久？
- 首期是否要求自动归因，还是仅提供描述性统计和对比？
