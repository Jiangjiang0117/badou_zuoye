这份论文主要介绍 **GraphRAG**：一种利用知识图谱增强检索增强生成（RAG）的方法，目标是让大语言模型能够理解和回答**整个文档集合层面的“全局问题”**，而不只是从少量相关文本中寻找局部事实。

### 核心问题

传统的向量 RAG 通常流程是：

1. 将文档切分并转换为向量；
2. 根据用户问题检索最相似的若干文本片段；
3. 让 LLM 基于这些片段生成答案。

这种方法适合回答“某个事实是什么”之类的局部问题，但不擅长回答：

- 数据集中有哪些主要主题？
- 整个语料库反映出哪些趋势？
- 不同人物、事件和观点之间有什么联系？
- 多篇文档综合起来能得出什么洞见？

因为这些问题要求模型理解整个语料库，而不是只看几个相似片段。

### GraphRAG 的主要方法

GraphRAG 在检索前先构建一个由 LLM 生成的图索引：

1. **文档切分**：将源文档分成文本块；
2. **信息抽取**：从文本块中提取实体、实体之间的关系以及重要事实陈述；
3. **构建知识图谱**：实体作为节点，关系作为边，并聚合重复出现的信息；
4. **社区发现**：使用 Leiden 等算法，把关系紧密的实体划分成多层级社区；
5. **生成社区摘要**：从底层社区开始逐层总结，形成不同粒度的主题报告；
6. **回答全局问题**：
   - 对多个社区摘要分别生成局部答案；
   - 根据相关性或帮助程度筛选、排序；
   - 再将这些答案汇总成最终的全局答案。

可以把它理解为：先把一大堆文档整理成“人物—事件—组织—主题”的知识网络，再为每个主题群生成摘要，最后让模型综合这些主题摘要回答问题。

### 实验结论

论文在播客文字稿和新闻文章两个约百万 token 规模的数据集上进行了测试，每个数据集生成 125 个全局理解问题，并将 GraphRAG 与传统向量 RAG、普通的 map-reduce 文本摘要进行比较。

主要结果是：

- **完整性更高**：GraphRAG 能覆盖更多相关方面；
- **多样性更好**：答案包含更多不同观点、证据和主题；
- **比向量 RAG 更适合全局问题**：在综合整个数据集的问题上，GraphRAG 明显优于向量检索；
- **直接性较弱**：向量 RAG 的答案通常更短、更直接；
- **节省上下文 token**：尤其是使用根层社区摘要时，相比直接对全部源文本做摘要，所需 token 大幅减少；论文报告根层摘要所需 token 可减少超过 97%；
- **不同社区层级适合不同需求**：低层级摘要信息更细，根层摘要范围更广但细节较少。

### 论文的局限

作者也指出：

- 实验只覆盖两个数据集和有限的全局理解任务；
- 尚未充分评估不同领域上的泛化能力；
- 对答案编造或事实错误率的评估还不够；
- GraphRAG 的索引构建需要多次 LLM 调用，因此会产生一定的预处理成本。

### 一句话总结

**GraphRAG 的核心思想是“先用知识图谱组织全局信息，再用分层社区摘要进行检索和汇总”，从而弥补传统向量 RAG 只擅长局部检索、却不擅长全局理解的不足。**
