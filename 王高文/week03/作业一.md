 **langchain 工具调用 和 llm function call 有什么区别？**

LLM Function Calling 是大模型厂商提供原生 API 协议，模型可以根据传入的工具描述，返回结构化的工具调用指令。使用原生 SDK 开发时，我们需要手动编写工具 Schema、解析返回结果、组装消息、维护函数映射，代码重复量大，但是自由度极高，没有额外框架依赖。

LangChain 工具调用是上层封装，底层优先复用这套 FunctionCall 协议；通过`@tool`自动生成工具描述，统一封装消息结构、结果解析逻辑，抹平不同大模型厂商 API 差异，节省开发样板代码。

**langchain 工具调用 的 速度是受到什么影响？**

LangChain 工具调用速度影响因素按优先级：

1. **LLM 相关（首要）**：模型推理速度、网络延迟；优先使用模型原生 Function Call，避免 ReAct 提示词模拟方案；
2. **Agent 轮次**：工具调用的循环次数，每一轮都会产生一次 LLM 网络请求；多个独立工具尽量并发执行，禁止串行；
3. **上下文 Token**：挂载工具数量、对话历史、工具返回内容持续膨胀，导致输入变长、推理变慢；
4. **自定义工具内部耗时**：工具中的数据库、HTTP 等 IO 阻塞；
5. **框架自身开销**：消息封装、回调日志、异常重试等，一般占比不高。
