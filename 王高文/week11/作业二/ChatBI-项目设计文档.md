# ChatBI 项目设计文档

整理日期：2026-10-22｜状态：讨论稿

## 项目定位

为企业业务人员提供自然语言数据分析能力：用户用对话查询指标、按维度拆分、比较趋势并追问；系统基于企业授权数据和统一业务口径返回可追溯结果。

ChatBI 结合大模型语言理解、业务语义定义、受控查询执行和结果展示。大模型不是指标口径或数据计算的唯一来源。

## 目标

- 让业务人员通过自然语言完成常见指标查询和维度分析。
- 统一指标口径，保证同一业务问题得到一致解释。
- 在查询前校验权限并限制资源。
- 展示指标口径、时间范围、筛选条件和数据更新时间。
- 对歧义、无权限、无数据和暂不支持的情况明确反馈。

## 首版范围与假设

暂按“公司内部使用、连接现有数仓、只读分析、先覆盖一个业务域”规划。可从销售域开始，覆盖销售额、订单数、退款额等指标，以及日期、地区、产品等维度。

先不支持任意数据源、复杂预测、自动建模或对话写回。优先复用现有身份系统、数仓和数据建模资产。

## 总体方案

1. 交互层：对话、澄清、追问、表格/图表、历史和反馈。
2. 对话分析层：识别指标、维度、时间范围和筛选意图。
3. 业务语义层：管理指标公式、字段映射、同义词、表关系和时间口径。
4. 查询执行层：构造查询，校验权限与资源限制后调用数仓。
5. 治理层：权限、语义版本、查询审计、反馈和运行监控。

## 数据流

用户提问 → 解析结构化分析意图 → 匹配业务定义 → 必要时先澄清 → 校验权限与查询限制 → 执行只读查询 → 返回结果及口径说明 → 记录执行信息并收集反馈。

数据库/数仓负责计算数字；语义层提供业务口径；模型负责理解问题和组织表达。

## 设计原则与阶段

语义优先、结构化查询、最小权限、结果可解释、执行可追溯、逐步扩展。

- 阶段一：一个业务域的 MVP，少量指标维度、自然语言问数、基础图表、权限和审计。
- 阶段二：多轮上下文、同比环比、排名下钻、反馈纠错。
- 阶段三：增加业务域和数据源，评估订阅、缓存、复杂统计及多租户能力。

## 待确认

目标用户是内部员工还是外部客户；首个业务域、数据源和高频问题；现有指标口径、建模与权限系统；部署和合规要求。
