# ChatBI 功能设计文档

整理日期：2026-10-22｜状态：讨论稿｜假设：内部只读分析 MVP

## 用户角色

- 业务用户：提问、追问、查看结果和历史、提交反馈。
- 业务/数据管理员：维护并审核指标、维度、同义词、字段映射、关系和示例问题。
- 系统管理员：配置数据源、用户角色、权限和运行策略，查看审计与异常。

## 功能模块

| 模块 | 首版功能 | 优先级 |
|---|---|---|
| 自然语言问数 | 识别指标、时间、筛选和分组；歧义时澄清；保留会话上下文 | P0 |
| 结果展示 | 数字、表格或基础图表；展示口径、条件、时间和更新时间 | P0 |
| 追问分析 | 修改筛选、换维度、排序、趋势；常见周期比较 | P0基础 / P1扩展 |
| 语义配置 | 指标公式、单位、时间口径、维度、别名、字段和表关系；预览和版本 | P0 |
| 数据源与权限 | 配置数据源；角色和数据范围授权；查询前校验 | P0 |
| 历史与反馈 | 会话记录；反馈正确/错误及原因；关联语义定义 | P0 |
| 审计与排错 | 记录用户、语义版本、查询状态、耗时和错误类型 | P0 |
| 扩展 | 导出、分享、订阅、缓存、复杂分析和写回 | P1/P2 |

## 核心交互

**成功查询：** 用户提问 → 解析并映射业务定义 → 权限及查询检查 → 执行 → 展示答案和口径 → 追问继承上下文。

**歧义处理：** 对“销售额”多种口径或日期字段不明确等情况，先列出简明选项让用户确认。

**无法回答：** 区分未配置指标、无权限、无数据、超时和暂不支持，并给出下一步建议。

## 交互要求

- “只看华东”应在当前分析上追加筛选。
- 答案说明指标口径、筛选、日期范围和更新时间。
- 可根据权限决定是否显示查询摘要或 SQL。
- 用户反馈应能帮助管理员定位语义定义问题。
- 普通日志避免保留不必要的敏感结果明细。

## 版本与验收

P0：问数、澄清、基础追问、语义配置、权限、结果解释、历史反馈、审计。  
P1：同比环比、排名下钻、导出分享、模板和质量看板。  
P2：订阅告警、预测/因果分析、多租户外部版本、对话写回。

验收用业务确认的问题集检查：指标映射和报表口径一致；歧义会澄清；越权数据不可见；结果有依据；失败分类清楚。
