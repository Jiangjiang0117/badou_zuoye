# 深度研究助手 · 阅读指南

> 想快速看懂这个「深度研究助手」项目，按本文顺序读。核心是**理解研究循环**，而不是每个文件。

---

## 0. 一句话理解

市场/产品同学输入一个**研究主题** → 系统自动完成「规划 → 多轮检索 → 阅读总结 → 判断是否补检 → 综合成报告」，产出**带来源引用的四类产物**（结构化报告 / 来源列表 / 过程记录 / 置信度说明）。

它是 **agentic loop**，不是一次性问答。这是理解全项目的钥匙。

## 2. 先看「数据长什么样」（10 分钟）

所有 pydantic 模型都集中在一个文件里，这是读代码前必须先建立的心智模型：

**`backend/models.py`** —— 只看这几个：

- `KeywordOutput` / `JudgeDecision` / `DraftBlock` / `ReportOutline` → agent 的中间输出（进/出 LLM 的结构）
- `Source` → 一条可追溯来源（url/title/snippet/site_name/date）
- `ConfidenceInfo` → 置信度（可靠程度 + 信息截止时间 + 模型推断标注）
- `ResearchProcess` → 过程记录（plan/search_queries/reviewed_urls/iterations/steps）
- `ReportContent` = 元信息 + sections（正文分节）
- `ResearchRecord` → **最终落盘的完整记录**（四类产物 + 状态机 status）

运行 `python -m backend.models` 看序列化 round-trip。

---

## 3. 读「研究引擎」——项目的灵魂（15 分钟）

**`backend/engine.py` 的 `DeepResearch.run()`** 是核心控制流，纯确定性编排，不含任何 LLM 调用。

按这个顺序逐行看 `run()`：

1. **规划** → `KeywordAgent.generate_keywords(topic)` 拆解出初始关键词
2. **多轮检索循环** `for rnd`：
   - 逐关键词 `web_search(kw)`（`tools.py` 直接函数调用）→ 去重进 `sources`
   - `SummaryAgent.summarize(...)` 总结成一段正文 → **累积进草稿 `draft`**
   - `JudgeAgent.judge(...)` **判断要不要补检** → 不足则用新关键词进下一轮
   - 每轮结束回调 `on_progress`（中间态逐步落盘，轮询可实时看到过程）
3. **收敛判据**：Judge 判 `sufficient` → 提前结束；到 `max_rounds`（默认 3）→ 强制结束
4. **置信度**：`_compute_confidence` 按来源数/轮数**确定性**计算（不花 LLM）
5. **报告**：`ReportAgent.generate` 产出元信息 + HTML

> 💡 读 `engine.py` 时脑子里挂一个回路图：
> `规划 →(关键词)→ 检索 →(结果)→ 总结 →(正文) 累积进 draft → 判断 → 补检? → 回到检索`

## 4. 读「角色 agent」——无工具的 LLM 调用（10 分钟）

`backend/agent/` 里只有**角色 agent**，都是**单次 LLM 调用、不带工具**。分工：

- `base.py` — `BaseAgent` 基类 + SDK 全局初始化 + `parse_json` 兜底。**先读这个**，其它 agent 都继承它。
- `keyword.py` — 拆解关键词（结构化 JSON）
- `summary.py` — **特例**：输出纯文字（不走 JSON），一篇报告正文
- `judge.py` — 判断补检（结构化 JSON）
- `report.py` — 两次调用：先元信息 JSON，再把报告渲染成自包含 HTML

重点理解 `base.py`：
- SDK 用 `agents` 包，走 `chat_completions`，指向 DeepSeek（`base_url`）
- `_run`：对「200 OK 却空输出」自动重试 `LLM_RETRIES` 次
- `parse_json`：Direct 解析 → ```json``` 代码块 → 首尾花括号，三层兜底

> 💡 **agent 与 engine 的分工**：agent 只会「调一次 LLM」，engine 才负责「编排流程」。看代码时不要在这两者间混淆。

---

## 5. 读「提示词模板」——提示词不在代码里（5 分钟）

`backend/templates/*.jinja2`，每个 agent 一个。读的时候对照 agent 代码看变量从哪来：
`keyword_agent` 用 `{{ user_input }}`，`summary/judge/report/report_html_agent` 各注入 `topic`/`draft`/`sources`/`confidence` 等系统变量。

这就是 CLAUDE.md 强调的「**提示词与代码分离**」——要改提示词就改模板，不动 Python。

---

## 6. 读「外围四件套」——怎么跑起来（5 分钟）

| 文件 | 职责 |
|---|---|
| `config.py` | 从根 `.env` 读所有配置（DeepSeek/Bocha key、轮数等），pydantic-settings |
| `tools.py` | `web_search`：封装 Bocha 搜索 API，返回统一 `list[dict]` |
| `storage.py` | `data/research/{id}.json` 原子读写（threading.Lock） |
| `research.py` | 研究编排：后台执行 + `on_progress` 中间结果逐步落盘 → 最终落盘 |
| `app.py` | FastAPI 出入口：POST 提交→202+id，GET 轮询→看状态/中间结果 |

**一次请求的生命周期**（串起来看）：
`POST /api/research` → `app.py` 建 id、`asyncio.create_task` 后台执行 `research.run_research` → engine 跑循环 → 每轮 `on_progress` 写 running 中间态 → 完成写 completed → 前端轮询 `GET /api/research/{id}`。

## 7. 建议的阅读命令

```bash
# 离线自检（不需要密钥，先跑通就有底）
python -m backend.config            # 配置自检
python -m backend.models            # 模型序列化自检
python -m backend.storage           # 落盘读写自检
python -m backend.agent.base        # parse_json + 模板渲染
python -m backend.agent             # agent 包导出自检

# 端到端（需要 .env 里的 DeepSeek + Bocha key）
python -m backend.engine            # 研究引擎完整流水线
python -m backend.research          # 完整研究 + 落盘
bash start.sh                       # 启动服务，再 curl 三个接口
```
