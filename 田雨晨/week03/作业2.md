# 意图识别系统 - 请求响应流程说明

## 概述

本文档描述从 FastAPI 接收用户请求到返回分类结果的完整流程。以一个具体示例贯穿说明：

> **示例请求**
> ```json
> {
>   "request_id": "123",
>   "request_text": "帮我播放周杰伦的歌"
> }
> ```

---

## 完整流程

### 第一步：用户发送请求

用户通过 HTTP POST 方法向服务发送请求。

请求地址为以下四种之一：
- `http://localhost:8000/v1/text-cls/regex` （正则模型）
- `http://localhost:8000/v1/text-cls/tfidf` （TF-IDF模型）
- `http://localhost:8000/v1/text-cls/bert` （BERT模型）
- `http://localhost:8000/v1/text-cls/gpt` （大语言模型）

请求体格式：
```json
{
  "request_id": "123",
  "request_text": "帮我播放周杰伦的歌"
}
```

---

### 第二步：FastAPI 网关接收

FastAPI 作为 web 服务入口，接收用户的 HTTP 请求。

主要工作：

1. **路由分发**
   - 根据 URL 路径选择调用哪个函数
   - 例如：`/v1/text-cls/tfidf` 会调用 `tfidf_classify()` 函数

2. **数据验证**
   - 使用 `data_schema.py` 中定义的 `TextClassifyRequest` 校验请求格式
   - 检查必填字段 `request_id` 和 `request_text` 是否存在

3. **日志记录**
   - 将请求信息记录到日志（控制台 + app.log 文件）

---

### 第三步：模型推理

根据选择的模型类型，执行不同的推理逻辑。

---

#### 3.1 正则表达式模型（/regex）

**适用场景**：简单规则、关键词匹配

**流程**：

```
1. 从 config.py 加载预定义的正则规则
   REGEX_RULE = {
       "FilmTele-Play": ["播放", "电视剧"],
       "HomeAppliance-Control": ["空调", "广播"]
   }

2. 遍历所有规则，检查文本是否包含关键词
   - "帮我播放周杰伦的歌" 包含 "播放"
   - 匹配到 "FilmTele-Play" 类别

3. 如果没有匹配任何规则，返回 "Other"

4. 返回结果："FilmTele-Play"
```

**优点**：速度快（毫秒级）
**缺点**：只能识别预先定义的规则，泛化能力差

---

#### 3.2 TF-IDF + SVM 模型（/tfidf）

**适用场景**：中等复杂度、需要一定泛化能力

**流程**：

```
第1步：中文分词
   使用 jieba 分词库
   输入："帮我播放周杰伦的歌"
   输出：["帮", "我", "播放", "周杰伦", "的", "歌"]

第2步：去除停用词
   加载 baidu_stopwords.txt 停用词表
   去除"的"、"我"等无意义词汇
   输出："帮 播放 周杰伦 歌"

第3步：TF-IDF 向量化
   使用训练好的 TF-IDF 模型（tfidf_ml.pkl）
   将文本转换为数字向量
   例如：[0.0, 0.3, 0.5, 0.1, ...]

第4步：SVM 分类预测
   使用训练好的 SVM 模型
   输入：TF-IDF 向量
   输出：预测的类别标签 "Music-Play"
```

**优点**：有一定泛化能力，速度较快
**缺点**：无法理解深层语义

---

#### 3.3 BERT 模型（/bert）

**适用场景**：需要高准确率、有 GPU 资源

**流程**：

```
第1步：加载模型
   - 加载预训练中文 BERT：bert-base-chinese
   - 加载微调后的分类模型：bert.pt
   - 模型加载到 GPU（如有）或 CPU

第2步：文本编码
   使用 BERT Tokenizer 分词
   输入："帮我播放周杰伦的歌"
   输出：token IDs、attention_mask 等

第3步：转换为张量
   转换为 PyTorch 张量
   移动到设备（GPU/CPU）

第4步：BERT 前向传播
   输入：张量数据
   输出：logits（分类得分）

第5步：Softmax 分类
   对 logits 进行 softmax 得到概率分布
   取概率最大的类别作为结果

第6步：映射回类别名称
   数字标签 1 → "Music-Play"
```

**优点**：理解语义深，准确率最高
**缺点**：需要 GPU，推理速度较慢

---

#### 3.4 大语言模型（/gpt）

**适用场景**：复杂句子、最求最高准确率、不介意调用成本

**流程**：

```
第1步：计算相似度
   使用 TF-IDF 计算待预测文本与训练数据的相似度
   找出最相似的 10 个训练样本

第2步：构造 Few-shot 提示词
   参考例子格式：
   "播放王菲的歌 -> Music-Play"
   "打开空调 -> HomeAppliance-Control"
   ...（共10个）

第3步：调用大模型 API
   连接到阿里云通义千问（qwen-plus）
   发送提示词：
   
   你是一个意图识别的专家，请结合待选类别和参考例子进行意图分类。
   待选类别：Travel-Query/Music-Play/...
   
   历史参考例子如下：
   播放王菲的歌 -> Music-Play
   打开空调 -> HomeAppliance-Control
   ...
   
   待识别的文本为：帮我播放周杰伦的歌
   只需要输出意图类别，不要其他输出。

第4步：解析返回结果
   大模型返回："Music-Play"
```

**优点**：最智能，能处理复杂句子
**缺点**：调用API需要付费，速度最慢

---

### 第四步：封装响应

无论使用哪种模型，最后都会将结果封装为统一的响应格式：

```python
TextClassifyResponse(
    request_id="123",           # 原样返回请求ID
    request_text="帮我播放周杰伦的歌",  # 原样返回请求文本
    classify_result="Music-Play",  # 识别出的意图类别
    classify_time=0.015,         # 处理耗时（秒）
    error_msg="ok"              # 错误信息，正常为"ok"
)
```

---

### 第五步：返回响应

FastAPI 将响应转换为 JSON 格式，返回给用户：

```json
{
  "request_id": "123",
  "request_text": "帮我播放周杰伦的歌",
  "classify_result": "Music-Play",
  "classify_time": 0.015,
  "error_msg": "ok"
}
```

## 各模型对比

| 模型 | 接口路径 | 速度 | 准确率 | 成本 | 适用场景 |
|------|----------|------|--------|------|----------|
| 正则 | /regex | 最快 ★★★★★ | 低 ★★☆☆☆ | 免费 | 简单规则匹配 |
| TF-IDF | /tfidf | 快 ★★★★☆ | 中 ★★★☆☆ | 免费 | 中等复杂度 |
| BERT | /bert | 慢 ★★★☆☆ | 高 ★★★★☆ | GPU成本 | 高准确率需求 |
| 大模型 | /gpt | 最慢 ★★☆☆☆ | 最高 ★★★★★ | API付费 | 复杂句子 |

## 错误处理

如果推理过程出现异常：

```python
try:
    # 正常推理
    response.classify_result = model_xxx(req.request_text)
    response.error_msg = "ok"
except Exception as err:
    # 异常处理
    response.classify_result = ""
    response.error_msg = traceback.format_exc()  # 记录错误详情
```
